# Game servers and online services checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Recommended (6–8)

- [ ] `GAMESERVER-8` (8) Let a backend service that authenticates players request matches and game servers for them, and take skill ratings and other matching attributes from server-side data, not from the client. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-10` (8) Roll out new server builds without ending running matches: start the new version next to the old one, send new matches to it, and let the old servers exit when their matches end. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-13` (8) Admit to a match only the players the matchmaker placed in it: the client presents its player session or ticket, and the server validates it before accepting the connection. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-14` (8) Keep player inventories, currencies, progression and scores in data that only server code can write. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-1` (7) Drive each game server through the hosting platform's lifecycle with its server SDK: report ready only when it can accept players, keep its health checks passing, mark it allocated when a match starts, and end the process when the match is over. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-2` (7) Ship the server as its own headless build without rendering, audio or client-only assets: Unity's Dedicated Server build target, an Unreal `Server` target, or a Godot export preset in *Export as dedicated server* mode. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-3` (7) Choose the lowest tick rate that gives an acceptable player experience, and keep each tick within its time budget, with no database or HTTP calls inside it. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-5` (7) Scale each fleet with a buffer of ready servers: start with a generous buffer and a maximum well above the expected peak, and lower the buffer later from real usage. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-6` (7) Handle the shutdowns you can't prevent: when the platform signals termination, stop accepting players, save the match state, disconnect players cleanly and exit before the deadline. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-7` (7) Run game servers in more than one region, and in more than one cluster or fleet per region, and allocate across them, so that one failed cluster doesn't stop matches from starting. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-9` (7) Place each match in the region with the lowest measured latency for its players: have clients time UDP round trips to each region, send the results with the matchmaking request, cap the latency you accept, and relax the limits step by step while players wait. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-11` (7) Version the network protocol, check the version when a client connects, and reject clients that don't match; send players only to servers running a build compatible with their client. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-15` (7) Rate-limit each player's actions and traffic, and protect game servers from DDoS attacks, for example with a relay that hides their IP addresses. ([specific/game-servers](../specific/game-servers/README.md))
- [ ] `GAMESERVER-16` (7) Record tick time and achieved tick rate for every game server, along with players, active sessions and crashed or abnormally terminated sessions, and alert on severe problems such as ticks that overrun their budget. ([specific/game-servers](../specific/game-servers/README.md))
