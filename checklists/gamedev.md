# Game development (engine-independent) checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Recommended (6–8)

- [ ] `GAMEDEV-1` (8) Advance the simulation in fixed time steps, decoupled from the render rate, and interpolate between the last two simulated states when rendering. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-5` (8) In competitive multiplayer games, make the server authoritative: clients send inputs, and the server runs the simulation and sends back the results. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-10` (8) Version the save-data schema from the first release, and migrate older saves to the current version when loading them. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-12` (8) Set a frame-time budget for each target platform (33.3 ms at 30 fps, 16.7 ms at 60 fps), and measure against it with a profiler on the target hardware, before and after each optimisation. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-15` (8) Pick version control that handles large binary assets before the project grows: Git with Git LFS, or a system built for binaries such as Perforce. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-2` (7) Build game entities by composing components, not through deep inheritance hierarchies. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-3` (7) Define entity types and tuning values as data that designers can change without recompiling, not as one subclass per type. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-6` (7) Hide latency with client-side prediction and server reconciliation. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-11` (7) Keep the last good save until the new one is completely written, and store an integrity check so that a corrupt or partial save falls back to the previous one. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-16` (7) Lock binary assets that can't be merged, such as levels, textures, models and audio, before editing them: mark their types `lockable` in `.gitattributes` with Git LFS, or check them out exclusively in Perforce. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-17` (7) Plan accessibility at the design stage: review the Game Accessibility Guidelines before work starts, choose the ones that apply, and schedule early the ones that are costly to add later. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-18` (7) Address the four most common complaints first: control remapping, text size, colour blindness and subtitle presentation. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-7` (6) Render other players slightly in the past, interpolating between buffered server updates, instead of snapping to each update as it arrives. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-19` (6) Don't convey essential information by colour alone or by sound alone, and give effects, speech and music separate volume controls. ([specific/gamedev](../specific/gamedev/README.md))

## Conditional (1–5)

- [ ] `GAMEDEV-8` (5) For hit detection in fast-paced shooters, use lag compensation: the server rewinds the world to the moment the shooter saw it and checks the hit there. ([specific/gamedev](../specific/gamedev/README.md))
- [ ] `GAMEDEV-9` (5) Choose deterministic lockstep, which sends only inputs, only if the simulation is bit-for-bit deterministic on every platform you ship to. Otherwise, synchronise state. ([specific/gamedev](../specific/gamedev/README.md))
