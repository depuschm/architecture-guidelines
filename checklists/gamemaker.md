# GameMaker checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Strongly recommended (9–10)

- [ ] `GAMEMAKER-STRUCT-1` (9) Keep every project in source control from the first day, and keep the `.gitignore` and `.gitattributes` files that GameMaker adds to new and imported projects. ([specific/gamemaker/project-structure](../specific/gamemaker/project-structure.md))

## Recommended (6–8)

- [ ] `GAMEMAKER-CODE-1` (8) Don't rely on the order in which instances run the same event, or on the order in which a room creates its instances. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-STRUCT-4` (8) Develop on the LTS release, use one IDE and runtime version across the team and the build machines, and upgrade everyone together, after committing, when you choose to. ([specific/gamemaker/project-structure](../specific/gamemaker/project-structure.md))
- [ ] `GAMEMAKER-CODE-2` (7) Declare every instance variable in the Create event, or as an Object Variable, and use `var` for values that only one event needs. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md)) *Automatable: Feather messages.*
- [ ] `GAMEMAKER-CODE-5` (7) Keep game-wide state in a few known places: declare every global variable in one script function or one controller object at the start of the game, always with the `global.` prefix, and define all macros in a dedicated script asset. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-CODE-7` (7) Define global functions in script assets with `function name() {}`, and functions inside objects and constructors as method variables, `name = function() {}`, so that children can override them. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-CODE-8` (7) Use constructors and structs, not object instances, for data and logic that need no events, drawing or collisions, such as stats, inventories or states, and declare their methods `static` so that all structs from a constructor share one copy. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-CODE-11` (7) Use the asynchronous versions of slow operations, such as HTTP requests, file loading and adding sprites, and in the Async event check that `async_load[? "id"]` matches the request ID you stored. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-PERF-1` (7) Profile the game on every target device, during development and before and after each optimisation, with the Debugger's Profiler and the Debug Overlay. ([specific/gamemaker/content-and-performance](../specific/gamemaker/content-and-performance.md))
- [ ] `GAMEMAKER-PERF-3` (7) Destroy everything you create at run time that has a destroy function, such as data structures, surfaces and buffers, usually in the Clean Up event, and use arrays and structs rather than DS lists and maps. ([specific/gamemaker/content-and-performance](../specific/gamemaker/content-and-performance.md))
- [ ] `GAMEMAKER-PERF-4` (7) Assign sprites, tile sets and fonts to texture groups by where they're used, such as one group per level and one for the menus, and keep groups that only some rooms need out of memory: make them dynamic, load them with `texturegroup_load()` before they're needed, and unload them afterwards. ([specific/gamemaker/content-and-performance](../specific/gamemaker/content-and-performance.md)) *Automatable: Dynamic texture groups, explicit mode.*
- [ ] `GAMEMAKER-PERF-8` (7) Follow the manual's advice against losing saves: write each save to a new file, check it, then replace the old one, validate a save, for example with a checksum, before loading it, and keep files open only briefly. ([specific/gamemaker/content-and-performance](../specific/gamemaker/content-and-performance.md))
- [ ] `GAMEMAKER-STRUCT-2` (7) Save and close the project in GameMaker before you pull, merge, switch branches or revert with an external Git client, and if GameMaker reports changed files while the project is open, choose Reload, not Save. ([specific/gamemaker/project-structure](../specific/gamemaker/project-structure.md))
- [ ] `GAMEMAKER-STRUCT-5` (7) Compile every pull request in CI, with `gm-cli compile` or with Igor on your own build machine, and pin both the `gm-cli` version and the runtime version, which `gm-options.json` records in its `toolchain` field. ([specific/gamemaker/project-structure](../specific/gamemaker/project-structure.md)) *Automatable: gm-cli compile workflow.*
- [ ] `GAMEMAKER-GFX-1` (7) Keep texture swaps and vertex batches low: draw instances that need the same blend mode or shader together, from one controller object or through layer begin and end scripts, instead of letting each instance set and reset the state. ([specific/gamemaker/rendering](../specific/gamemaker/rendering.md))
- [ ] `GAMEMAKER-GFX-2` (7) Undo every GPU state change on every code path before the code that made it ends: `shader_reset()` after `shader_set()`, `surface_reset_target()` after `surface_set_target()`, and the blend mode and other `gpu_set_*` settings back to their defaults. ([specific/gamemaker/rendering](../specific/gamemaker/rendering.md)) *Automatable: Feather messages.*
- [ ] `GAMEMAKER-GFX-3` (7) Treat every surface except the application surface as volatile: check `surface_exists()` before each use and re-create the surface if it's gone, create and draw to surfaces in Draw events, keep them no larger than the view, and free them with `surface_free()`. ([specific/gamemaker/rendering](../specific/gamemaker/rendering.md))
- [ ] `GAMEMAKER-CODE-3` (6) Refer to a particular instance through its instance ID, and use the object name only in code meant for all its instances. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-CODE-4` (6) Put behaviour that a family of objects shares in a parent object that is never placed in a room itself, and call `event_inherited()` in a child's event when the parent's code for that event should also run. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md)) *Automatable: Feather messages.*
- [ ] `GAMEMAKER-CODE-6` (6) Make an object persistent only if its instance must outlive the room, such as a game manager or the player, and create that instance exactly once. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-CODE-9` (6) Don't depend on the order in which function arguments or parts of an expression are evaluated: call functions with side effects, such as `buffer_read`, in separate statements, and use brackets in expressions. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md)) *Automatable: Feather messages.*
- [ ] `GAMEMAKER-CODE-10` (6) Document script functions and constructors with JSDoc comments that give the types of `@param` and `@return`, and let Feather check types. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md)) *Automatable: Feather type checking.*
- [ ] `GAMEMAKER-PERF-2` (6) Test and debug on the VM, but build the release of a CPU-heavy game with YYC on the platforms that offer it, measure its performance in that build, and clear the compiler cache before every final build. ([specific/gamemaker/content-and-performance](../specific/gamemaker/content-and-performance.md))
- [ ] `GAMEMAKER-PERF-5` (6) Choose each sound's compression by its length and use, and put sounds that only some rooms need in audio groups that you load with `audio_group_load()`. ([specific/gamemaker/content-and-performance](../specific/gamemaker/content-and-performance.md))
- [ ] `GAMEMAKER-PERF-6` (6) Build static scenery from tile layers rather than instances with sprites, and check collisions against the tile map where the level fits a grid. ([specific/gamemaker/content-and-performance](../specific/gamemaker/content-and-performance.md))
- [ ] `GAMEMAKER-STRUCT-3` (6) Name every asset with a prefix for its type, such as `spr_`, `obj_`, `snd_` and `ts_`, agree on one way to group the Asset Browser, by asset type or by level, and set matching Feather naming rules. ([specific/gamemaker/project-structure](../specific/gamemaker/project-structure.md)) *Automatable: Feather naming rules.*
- [ ] `GAMEMAKER-GFX-4` (6) Fit the game to each display with a camera and viewport, and resize the application surface to match, instead of relying on the Full Scale option, which stretches the image and ignores the aspect ratio. For pixel art, also turn off *Interpolate colours between pixels*, which is on by default, in each platform's Game Options. ([specific/gamemaker/rendering](../specific/gamemaker/rendering.md))
- [ ] `GAMEMAKER-GFX-5` (6) Make every image fit on the smallest texture page of any platform you ship to, check the pages with the Preview button in each platform's Game Options, and turn on mipmaps for texture groups that the camera zooms in and out on or that a 3D game uses. ([specific/gamemaker/rendering](../specific/gamemaker/rendering.md))
- [ ] `GAMEMAKER-GFX-6` (6) Write shaders in GLSL ES, the only shader language that works on every target, follow its specification strictly, and check `shader_is_compiled()` at start-up before you use any shader that isn't simple GLSL ES. ([specific/gamemaker/rendering](../specific/gamemaker/rendering.md))
- [ ] `GAMEMAKER-TEST-1` (6) Test the logic in script functions and constructors, and the behaviour of objects over several frames, with a GML testing library such as GMTL, and run the tests every time you run the game in development. ([specific/gamemaker/testing](../specific/gamemaker/testing.md))
- [ ] `GAMEMAKER-TEST-2` (6) Smoke-test every target build automatically with Igor's test command. ([specific/gamemaker/testing](../specific/gamemaker/testing.md)) *Automatable: Igor test command.*

## Conditional (1–5)

- [ ] `GAMEMAKER-CODE-12` (5) Model objects with distinct modes, such as enemies, the player or menu buttons, as finite state machines: one state variable, states named by an enum, and the state code that a family shares in its parent object. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-CODE-13` (5) Build menus and the HUD in UI layers, with Flex Panels so that the layout adapts to the display, and place the objects that handle their input in those layers. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-CODE-14` (5) Choose the multiplayer approach before building gameplay: Rollback Multiplayer plays online only on the GX.games target and shares only input, so every client must run the same logic, and for other platforms use the Photon extension or your own server with the networking functions. ([specific/gamemaker/code-architecture](../specific/gamemaker/code-architecture.md))
- [ ] `GAMEMAKER-PERF-7` (5) If you deactivate instances outside the view, do it every few steps or when the camera moves, never every step or in a Draw event, and reactivate persistent instances at least one step before the room changes. ([specific/gamemaker/content-and-performance](../specific/gamemaker/content-and-performance.md))
- [ ] `GAMEMAKER-STRUCT-6` (5) Use configurations for what differs between builds of the same game, such as platforms, stores or a demo, and select the configuration in every build. ([specific/gamemaker/project-structure](../specific/gamemaker/project-structure.md))
- [ ] `GAMEMAKER-TEST-3` (5) If you use Rollback Multiplayer, test every change in Sync Test, on Windows, macOS or GX.games, before you test online. ([specific/gamemaker/testing](../specific/gamemaker/testing.md))
- [ ] `GAMEMAKER-STRUCT-7` (4) Share scripts and assets that several projects use as a Local Asset Package (`.yymps`) with a Package ID and version number, and update a project by importing the new version. ([specific/gamemaker/project-structure](../specific/gamemaker/project-structure.md))
