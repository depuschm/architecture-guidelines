# Google Cloud checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

## Recommended (6–8)

- [ ] `GCP-1` (8) Use one organization resource, with folders for environments or other policy boundaries, and a separate project for each workload in each environment. ([specific/gcp](../specific/gcp/README.md))
- [ ] `GCP-4` (8) Don't use service account keys: attach service accounts to workloads that run on Google Cloud, use Workload Identity Federation for CI pipelines and workloads elsewhere, and block key creation with an organization policy. ([specific/gcp](../specific/gcp/README.md)) *Automatable: Checkov Terraform policies, Organization Policy constraints, Security Command Center, Compliance Manager cloud controls.*
- [ ] `GCP-5` (8) Give each application its own single-purpose service account instead of a default service account, and grant users the Service Account User and Token Creator roles on individual service accounts, not on projects or folders. ([specific/gcp](../specific/gcp/README.md)) *Automatable: Checkov Terraform policies, Security Command Center, Compliance Manager cloud controls.*
- [ ] `GCP-6` (8) Enforce the Google Cloud security baseline constraints in every organization, including organizations created before 3 May 2024, which may not have them. ([specific/gcp](../specific/gcp/README.md)) *Automatable: Organization Policy constraints, Security Command Center, Compliance Manager cloud controls.*
- [ ] `GCP-10` (8) Deploy production workloads across multiple zones, and across regions where your availability or recovery targets require it. ([specific/gcp](../specific/gcp/README.md))
- [ ] `GCP-11` (8) Manage the organization's foundation and all workloads as code with Terraform, applied from a pipeline that validates changes against your policies, as the enterprise foundations blueprint does. ([specific/gcp](../specific/gcp/README.md))
- [ ] `GCP-8` (7) Keep secrets in Secret Manager, grant access per secret when one project holds secrets for many services, and reference secret versions by number instead of `latest`. ([specific/gcp](../specific/gcp/README.md))
- [ ] `GCP-12` (7) Route audit logs from the whole organization to a central project with an aggregated sink, and turn on Data Access audit logs for services that handle sensitive data. ([specific/gcp](../specific/gcp/README.md)) *Automatable: Checkov Terraform policies, Security Command Center, Compliance Manager cloud controls.*
- [ ] `GCP-13` (7) Create Cloud Billing budgets with alert thresholds for each billing account or project, and send the alerts to the owners or to Pub/Sub for automated responses. ([specific/gcp](../specific/gcp/README.md))
- [ ] `GCP-2` (6) Label projects and resources consistently, for example with application, environment, cost center and owner, and set the labels from infrastructure as code. ([specific/gcp](../specific/gcp/README.md))
- [ ] `GCP-7` (6) Add further Organization Policy constraints at the organization or folder level, starting from the enterprise foundations blueprint's set, and test each new policy in dry-run mode before you enforce it. ([specific/gcp](../specific/gcp/README.md))
