# Godot checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Strongly recommended (9–10)

- [ ] `GODOT-1` (9) Commit the `.import` files next to your assets and the `.uid` files next to your scripts and shaders, and ignore the `.godot/` folder. ([specific/godot/project-structure](../specific/godot/project-structure.md))

## Recommended (6–8)

- [ ] `GODOT-3` (8) Design scenes to work on their own: keep what a scene needs inside it, and let the parent supply any outside dependency. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-4` (7) Let parents call methods on and set properties of their children, and let children report what happened through signals. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-5` (7) Use autoloads only for broad-scoped systems that manage their own data, such as a quest or dialogue system. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-21` (7) Choose the scripting languages early: GDScript suits most game code, C# suits teams that already know it, as long as you don't ship to the web, and C++ through GDExtension suits performance-critical algorithms. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-9` (7) Use static typing throughout, and set the `untyped_declaration` warning to Error so that untyped declarations stop a script from compiling. ([specific/godot/code-architecture](../specific/godot/code-architecture.md)) *Automatable: GDScript warning system.*
- [ ] `GODOT-11` (7) Move objects and run game logic in `_physics_process`, and turn on physics interpolation so that motion stays smooth at any frame rate. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-22` (7) Read player input through actions defined in the Input Map, not specific keys or buttons, and handle gameplay input events in `_unhandled_input()` rather than `_input()`, so that UI controls receive them first. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-24` (7) In multiplayer games, replicate spawned scenes with `MultiplayerSpawner` and properties with `MultiplayerSynchronizer`, keep the server the multiplayer authority over gameplay state, and give each player authority only over a child node that sends their input. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-26` (7) Profile on every target platform during development, not only in the editor: run a debug export with *Deploy with Remote Debug*, and use the debugger's Profiler for script time, the Visual Profiler for CPU and GPU rendering time, and the Monitors for memory and object counts. ([specific/godot/content-and-performance](../specific/godot/content-and-performance.md))
- [ ] `GODOT-27` (7) Preload only what a script always needs, and load levels and other large or optional content in the background with `ResourceLoader.load_threaded_request()`, behind a loading screen, because `load()` blocks the thread until the resource has loaded. ([specific/godot/content-and-performance](../specific/godot/content-and-performance.md))
- [ ] `GODOT-28` (7) Free nodes you no longer need with `queue_free()`: unlike `RefCounted` objects such as Resources, nodes aren't freed automatically, and `remove_child()` only takes a node out of the tree. ([specific/godot/content-and-performance](../specific/godot/content-and-performance.md)) *Automatable: gdUnit4, Orphan nodes, GUT, Memory Management.*
- [ ] `GODOT-12` (7) Model designer-edited game data as custom Resource classes saved as `.tres` files. ([specific/godot/content-and-performance](../specific/godot/content-and-performance.md))
- [ ] `GODOT-13` (7) Write saves and settings to `user://`, and don't decode objects (`allow_objects`) from files that players can edit or share. ([specific/godot/content-and-performance](../specific/godot/content-and-performance.md))
- [ ] `GODOT-15` (7) Localize with Godot's translation system: add CSV or gettext PO translations under *Project Settings > Localization*, look up text with `tr()` and `tr_n()` or a Control's automatic translation, fill named placeholders with `String.format()`, and switch languages with `TranslationServer.set_locale()`. ([specific/godot/content-and-performance](../specific/godot/content-and-performance.md))
- [ ] `GODOT-31` (7) Save scenes and resources in the text formats, `.tscn` and `.tres`, rather than the binary `.scn` and `.res`, so that they stay readable and easy to manage in version control. ([specific/godot/project-structure](../specific/godot/project-structure.md))
- [ ] `GODOT-35` (7) Commit `export_presets.cfg`, keep signing keys, passwords and encryption keys out of the repository, and automate release builds with `--export-release`. ([specific/godot/project-structure](../specific/godot/project-structure.md))
- [ ] `GODOT-16` (7) Choose the renderer for the platforms and oldest hardware you ship to: Forward+ for desktop games that need advanced rendering features, Mobile for mobile devices and standalone XR, and Compatibility for the web, older devices or the widest hardware support. ([specific/godot/rendering](../specific/godot/rendering.md))
- [ ] `GODOT-17` (7) In Forward+ and Mobile, let pipeline precompilation see everything during loading: show a simple scene that uses every rendering feature the game needs, such as MSAA, reflection probes or VoxelGI, before loading most assets, and instance effects that scripts add during play once as hidden nodes. ([specific/godot/rendering](../specific/godot/rendering.md))
- [ ] `GODOT-18` (7) Reuse materials, and where you can't, reuse shaders: share one material across objects and give each object its own values through per-instance uniforms (`instance uniform`), not a unique material. ([specific/godot/rendering](../specific/godot/rendering.md))
- [ ] `GODOT-14` (7) Write automated tests with GUT or gdUnit4, and run them headless in CI on every change. ([specific/godot/testing](../specific/godot/testing.md)) *Automatable: gdUnit4 command line tool, GUT command line.*
- [ ] `GODOT-37` (7) Unit-test game logic in isolation, in `RefCounted` classes and other scripts that you can create with `new()`, and test whole scenes in integration tests with gdUnit4's Scene Runner or GUT's `simulate()` and input sender, for behaviour that spans frames or depends on input. ([specific/godot/testing](../specific/godot/testing.md))
- [ ] `GODOT-6` (6) Reference other nodes through `@export` properties or scene-unique names (`%Name`), not long hard-coded node paths. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-10` (6) Follow the GDScript style guide, including its code order. ([specific/godot/code-architecture](../specific/godot/code-architecture.md)) *Automatable: gdlint.*
- [ ] `GODOT-23` (6) Set the base window size, stretch mode and stretch aspect at the start, following the docs' recommended settings for your kind of game, and lay out UI with anchors and Container nodes so that it adapts to every resolution and aspect ratio. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-25` (6) Don't change the active scene tree from another thread: build or load nodes outside the tree in the worker thread and add them on the main thread with `call_deferred()`, don't load the same resource from several threads at once, and protect data that threads share with a `Mutex`. ([specific/godot/code-architecture](../specific/godot/code-architecture.md))
- [ ] `GODOT-29` (6) Import 3D textures as VRAM Compressed with mipmaps, which *Detect 3D* sets automatically, and 2D textures, especially pixel art, as Lossless; if the project needs other settings, change the defaults project-wide in *Project Settings > Import Defaults*. ([specific/godot/content-and-performance](../specific/godot/content-and-performance.md))
- [ ] `GODOT-30` (6) Change imported 3D models in the modelling tool where you can, then in the import settings, and make any other change in an inherited scene, because Godot re-imports the whole scene whenever the source file changes. ([specific/godot/content-and-performance](../specific/godot/content-and-performance.md))
- [ ] `GODOT-32` (6) If you store large assets in Git LFS (`GAMEDEV-15`), set it up before the first commit, starting from the example `.gitattributes` in Godot's version control documentation, which also tracks Godot's binary formats such as `.scn`, `.res`, `.mesh` and `.lmbake`. ([specific/godot/project-structure](../specific/godot/project-structure.md))
- [ ] `GODOT-2` (6) Use snake_case for file and folder names (C# scripts excepted), and keep third-party code in `addons/`. ([specific/godot/project-structure](../specific/godot/project-structure.md))
- [ ] `GODOT-33` (6) Keep scripts and assets close to the scenes that use them, and move, rename or delete files only in Godot's FileSystem dock, so that references to them don't break. ([specific/godot/project-structure](../specific/godot/project-structure.md))
- [ ] `GODOT-19` (6) Draw thousands of identical objects, such as grass, flocks or particles, with a MultiMesh, and split it into several MultiMeshes by area, because Godot culls a MultiMesh only as a whole. ([specific/godot/rendering](../specific/godot/rendering.md))
- [ ] `GODOT-20` (6) Keep the mesh LODs that Godot generates on import, and add visibility ranges (HLOD) where a group of objects should turn into one simpler mesh or an impostor in the distance, or where distant effects should disappear. ([specific/godot/rendering](../specific/godot/rendering.md))
- [ ] `GODOT-38` (6) Let the code under test receive its dependencies, as `GODOT-3` describes for scenes, so that tests can replace them with GUT doubles and stubs or gdUnit4 mocks and spies. ([specific/godot/testing](../specific/godot/testing.md))
- [ ] `GODOT-39` (6) Keep tests and the test framework out of release exports: put tests in their own folder, such as `res://test/`, and add it and the framework's addon folder (`addons/gut/*` or `addons/gdunit4/*`) to the exclude filter of every export preset. ([specific/godot/testing](../specific/godot/testing.md))
