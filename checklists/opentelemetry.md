# OpenTelemetry checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Recommended (6–8)

- [ ] `OTEL-1` (8) Set `service.name` explicitly in every service, with the same value for all instances of the service, and add `service.version` and `deployment.environment.name` as resource attributes. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-3` (8) Propagate trace context across every process boundary, including queues: keep the default W3C Trace Context propagator for HTTP and gRPC, and have producers attach the context to each message. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-9` (8) Make `memory_limiter` the first processor in every Collector pipeline, set `GOMEMLIMIT` to about 80% of the Collector's hard memory limit, and batch data after sampling and filtering, preferably with the exporter's `sending_queue` batching. ([specific/opentelemetry](../specific/opentelemetry/README.md)) *Automatable: Collector `validate` command.*
- [ ] `OTEL-10` (8) Secure every Collector: bind receivers to `localhost` or a specific interface instead of `0.0.0.0`, require TLS and authentication on receivers that other hosts send to, keep credentials in a secret store or environment variables, and include only the components you use. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-12` (8) Keep secrets and personal data out of telemetry: don't record what you don't need, and remove, hash or truncate what instrumentation captures anyway, for example with the Collector's `redaction`, `attributes`, `transform` or `filter` processors. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-4` (7) Start with zero-code instrumentation or instrumentation libraries for your frameworks and clients, then add code-based spans, attributes and metrics for the business operations that matter. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-5` (7) Correlate logs with traces: keep your logging library, connect it to OpenTelemetry with a log appender (bridge) so that each record carries the active trace and span IDs, and prefer structured logs. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-6` (7) Keep span names and metric attributes low-cardinality: use route templates such as `/users/{id}` instead of raw paths, and keep user IDs, request IDs and other unbounded values off metric attributes. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-11` (7) Send telemetry over OTLP to an OpenTelemetry Collector, running as an agent next to the service or as a gateway, rather than from each service straight to a vendor. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-2` (6) Before you name a custom attribute or metric, look for it in the semantic conventions; when none fits, prefix the new name with your company's reverse domain name, such as `com.acme.`, or with your application's name. ([specific/opentelemetry](../specific/opentelemetry/README.md)) *Automatable: Weaver live check.*
- [ ] `OTEL-7` (6) Treat trace context from outside as untrusted: ignore or sanitize incoming trace headers from callers you don't trust, don't send internal context to external services, and never put credentials or personal data in baggage. ([specific/opentelemetry](../specific/opentelemetry/README.md))
- [ ] `OTEL-8` (6) Choose sampling deliberately: don't sample when you produce little data, use consistent probability (head) sampling to cut volume cheaply, and add tail sampling in a Collector tier when you must keep every error or slow trace. ([specific/opentelemetry](../specific/opentelemetry/README.md))
