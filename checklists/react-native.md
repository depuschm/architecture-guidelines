# React Native and Expo checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Strongly recommended (9–10)

- [ ] `RN-4` (9) Treat the JavaScript bundle and the app config as public: never put secrets in `EXPO_PUBLIC_` variables, the app config or the code, and call services that need a secret through your own server. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-5` (9) Store tokens and other secrets with `expo-secure-store`, which uses the iOS Keychain and the Android Keystore, not in AsyncStorage, which is unencrypted, or in a persisted state store, and keep them out of crash reports and analytics. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-6` (9) Sign users in through the system browser with `expo-auth-session` or `react-native-app-auth`, using the authorization code flow with PKCE (`AUTH-2`), never in a WebView, and exchange the code on your server when the provider requires a client secret. ([specific/react-native](../specific/react-native/README.md))

## Recommended (6–8)

- [ ] `RN-7` (8) Treat every incoming link as untrusted input: validate its route and query parameters before using them (`SEC-10`), never put tokens or personal data in a link, and use universal links and Android App Links for links that must open only your app. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-15` (8) Stay on a React Native release that still gets fixes, one of the latest three minor versions, by upgrading one Expo SDK at a time: run `npx expo install --fix` and `npx expo-doctor`, and apply native changes with the Upgrade Helper if you don't use Prebuild. ([specific/react-native](../specific/react-native/README.md)) *Automatable: Expo Doctor.*
- [ ] `RN-1` (7) Start new apps with Expo and Expo Router, and develop in development builds rather than in Expo Go. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-2` (7) Generate the `ios` and `android` directories with Prebuild (Continuous Native Generation): keep native configuration in the app config and config plugins, keep the generated directories out of Git, and don't edit them by hand. ([specific/react-native](../specific/react-native/README.md)) *Automatable: Expo Doctor.*
- [ ] `RN-8` (7) Declare the required reason APIs that the app and its libraries use in `ios.privacyManifests` in the app config, copying the reasons from each library's `PrivacyInfo.xcprivacy`. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-11` (7) Build and submit releases with EAS Build and EAS Submit from CI, and let EAS manage the signing credentials. If you use local credentials, add `credentials.json` and the keystore and certificate files to `.gitignore` (`SEC-2`). ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-13` (7) Render long or growing lists with a virtualized list, `FlatList`, `SectionList` or FlashList, not with `.map()` inside a `ScrollView`, and measure performance in release builds. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-16` (7) Test components with Jest, the `jest-expo` preset and React Native Testing Library, finding elements as users do (`WEB-14`), and cover the few critical journeys with Maestro end-to-end flows that run in CI, for example on EAS Workflows. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-3` (6) Write the app in TypeScript with `strict` on (`TS-1`), and turn on Expo Router's typed routes, so that the type checker reports links to routes that don't exist. ([specific/react-native](../specific/react-native/README.md)) *Automatable: TypeScript type checking.*
- [ ] `RN-9` (6) Give every build a runtime version that changes whenever its native code changes, preferably with the `fingerprint` policy, test each update on a preview build of the same runtime version through its own channel, and release it to production as a rollout to a small share of users first. Cancel the rollout, or roll back, if the error rate rises. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-10` (6) Use over-the-air updates for bug fixes and other changes that the stores allow without review, and ship new features and changes to the app's purpose in a store build. ([specific/react-native](../specific/react-native/README.md))
- [ ] `RN-14` (6) Turn on the React Compiler after checking the project with `react-compiler-healthcheck`, and in new code rely on it for memoization, with `useMemo` and `useCallback` only where you need precise control. ([specific/react-native](../specific/react-native/README.md)) *Automatable: eslint-config-expo.*
