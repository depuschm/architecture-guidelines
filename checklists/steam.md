# Steam and PC games checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Strongly recommended (9–10)

- [ ] `STEAM-4` (9) Keep the publisher Web API key and the Encrypted App Ticket key on your servers only, never in the game or its repository, and limit each publisher key to the permissions and calling IP addresses it needs. ([specific/steam](../specific/steam/README.md))

## Recommended (6–8)

- [ ] `STEAM-1` (7) Upload builds from CI with `steamcmd` under a dedicated Steam build account that has only the *Edit App Metadata* and *Publish App Changes To Steam* permissions, and keep its login token in the CI secret store. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-2` (7) Let CI set builds live only on a beta branch with a password, test each build there, and set it live on the default branch by hand in Steamworks. To roll back, set the previous build live again. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-3` (7) Ship updates and extra content through SteamPipe depots or DLC, not as downloads inside the game, and lay out pack files so that patches stay small: no more than about one or two GB each, grouped by level or feature, with new content in new pack files, no reordered assets or build timestamps, and compression only per asset. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-5` (7) Identify players on your game servers and backends by verifying a Steam session ticket, not by a Steam ID that the client reports: a game server or peer passes the ticket to `BeginAuthSession`, and a backend sends a ticket from `GetAuthTicketForWebApi` to the `ISteamUserAuth/AuthenticateUserTicket` Web API. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-6` (7) Run in-game purchases from your server: start each one with `ISteamMicroTxn/InitTxn`, grant the items only after your server's `FinalizeTxn` call succeeds, and call `GetReport` at least once a day to take back the items of refunded and charged-back orders. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-7` (7) Grant Steamworks permissions through groups that contain only the apps each person works on, give each person only the permissions they need, keep *Administrator*, *Manage Users*, *Manage Signing* and *Actual Authority* to a few people, and review who has them regularly. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-8` (7) Let only servers you host set the stats, achievements and leaderboard scores that competition or rewards depend on: set the stat's *Set By* to *Official GS* and register your servers' IP ranges, and set competitive leaderboards' *Writes* to *Trusted*, so that only your server can submit scores, with the `SetLeaderboardScore` Web API. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-9` (7) Write Steam Cloud saves to a folder for each Steam user, such as `{64BitSteamID}` in an Auto-Cloud path, keep Auto-Cloud root paths *Cross-Platform*, split saves into small files by how often they change, and never sync machine-specific settings such as resolution or graphics quality. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-11` (7) Make the whole game playable with a controller in its default configuration: read input as actions grouped into action sets, through the Steam Input API or your engine's action-based input (`UNREAL-29`, `GODOT-22`), show glyphs for the device in use, accept mouse and controller input at the same time, and open the on-screen keyboard with `ShowGamepadTextInput` or `ShowFloatingGamepadTextInput` when the game needs text. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-12` (7) Save graphics settings for each device and keep them out of Steam Cloud, choose defaults for the detected hardware without hiding any setting, support aspect ratios other than 16:9 and 16:10, and match the display's resolution on first launch. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-13` (7) Make all single-player content playable without an Internet connection, and test it offline, including the first launch on a new Steam account. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-15` (7) Collect crash reports from players' release builds through your engine's crash reporter or a crash-reporting service, and archive the debug symbols of every build you upload, outside the depots. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-10` (6) Let Steam keep stats and achievements: call `SetStat` whenever a stat changes and `StoreStats` at checkpoints and right after unlocking achievements, and don't keep a copy of them in your own files. ([specific/steam](../specific/steam/README.md))
- [ ] `STEAM-14` (6) Build everything the player needs into the game instead of a separate launcher, choose middleware that runs under Proton, and test the Windows build under Proton, on Linux or a Steam Deck. ([specific/steam](../specific/steam/README.md))

## Conditional (1–5)

- [ ] `STEAM-16` (5) Sign the Windows executables, libraries and installers you ship, in the release pipeline, with one consistent signing identity, such as Azure Artifact Signing or an OV certificate, and sign after every step that changes the files, such as the Steam DRM wrapper. ([specific/steam](../specific/steam/README.md)) *Automatable: SignTool `verify`.*
