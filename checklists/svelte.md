# Svelte and SvelteKit checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Strongly recommended (9–10)

- [ ] `SVELTE-5` (9) Never keep user or request data in module-level variables or other shared state on the server: return it from `load`, pass it down as props or through context, and persist it in a database. Keep `load` functions free of side effects for the same reason. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-11` (9) Treat every form action, `+server.js` handler and remote function as a public HTTP endpoint: make sure an authorization check covers it, and validate its input on the server. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-12` (9) Declare environment variables in `src/env.ts`, mark one `public: true` only if its value may be public, and import secrets only from `$app/env/private`. ([specific/svelte](../specific/svelte/README.md)) *Automatable: Server-only module check.*

## Recommended (6–8)

- [ ] `SVELTE-13` (8) Check authentication in the `handle` hook or in each `+page.server.js` `load` function, not only in a `+layout.server.js` `load` function. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-1` (7) Write new components in runes mode, and don't use legacy features that have modern replacements, such as `$:` statements, `export let`, `on:` directives, slots, and stores for shared state. ([specific/svelte](../specific/svelte/README.md)) *Automatable: Svelte compiler `runes` option.*
- [ ] `SVELTE-2` (7) Compute values from state and props with `$derived`, not by assigning state in an `$effect`, and keep `$effect` as an escape hatch for things such as analytics and direct DOM manipulation. ([specific/svelte](../specific/svelte/README.md)) *Automatable: eslint-plugin-svelte.*
- [ ] `SVELTE-3` (7) Type-check `.svelte` files in CI with `sv check` (svelte-check). ([specific/svelte](../specific/svelte/README.md)) *Automatable: sv check.*
- [ ] `SVELTE-6` (7) Load data that needs the database, the filesystem or private credentials in server `load` functions (`+page.server.js`), and use universal `load` functions (`+page.js`) only for public APIs or for values that can't be serialized. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-9` (7) Choose rendering per route with page options: prerender pages that every user sees the same, server-render dynamic pages, and turn off `ssr` only for pages that can't run on the server. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-14` (7) Put code that uses secrets, the database or other server-only APIs in server-only modules: files with a `server` segment in their name, such as `db.server.ts`, or files in a `server` directory. ([specific/svelte](../specific/svelte/README.md)) *Automatable: Server-only module check.*
- [ ] `SVELTE-4` (6) Share reactive state between components with `$state` objects or classes with `$state` fields, defined in `.svelte.js` or `.svelte.ts` modules, and keep stores for complex asynchronous streams or for when you need manual control over updates. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-7` (6) Avoid request waterfalls: make dependent backend calls in server `load` functions, use the `fetch` that `load` receives, and call `await parent()` only after the requests that don't depend on it. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-8` (6) Implement mutations as form actions that work without JavaScript, return validation errors with `fail()`, and progressively enhance the form with `use:enhance`. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-15` (6) Give every page a unique, descriptive `<title>` in `<svelte:head>`, and set the `lang` attribute in `src/app.html`. ([specific/svelte](../specific/svelte/README.md))
- [ ] `SVELTE-16` (6) Fix the compiler's accessibility warnings, and silence one with `<!-- svelte-ignore -->` only for a false positive, with a note saying why. ([specific/svelte](../specific/svelte/README.md)) *Automatable: eslint-plugin-svelte, sv check.*
