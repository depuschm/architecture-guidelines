# Unity checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Strongly recommended (9–10)

- [ ] `UNITY-STRUCT-7` (10) Keep `.meta` files visible and committed, and keep asset serialization on Force Text, so that assets diff and merge. ([specific/unity/project-structure](../specific/unity/project-structure.md))
- [ ] `UNITY-STRUCT-8` (9) Start from the community Unity `.gitignore` so that generated folders such as `Library/` and `Temp/` are never committed. ([specific/unity/project-structure](../specific/unity/project-structure.md))
- [ ] `UNITY-GFX-1` (9) Start new projects on the Universal Render Pipeline (URP), and choose HDRP only for a PC or console project that needs its high-end features. Don't start a new title on the Built-in Render Pipeline. ([specific/unity/rendering](../specific/unity/rendering.md))
