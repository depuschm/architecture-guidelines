# Unreal Engine checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Strongly recommended (9–10)

- [ ] `UNREAL-1` (9) Hold UObject references that must keep their target alive in `UPROPERTY` members, preferably `TObjectPtr`, and use `TWeakObjectPtr` for references that must not. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md)) *Automatable: PVS-Studio V1100.*

## Recommended (6–8)

- [ ] `UNREAL-2` (8) Put match rules in the game mode, which exists only on the server, state that all players need in the game state, per-player state in the player state, and anything that must survive a level change in the game instance or its subsystems. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-8` (8) Keep the server authoritative: clients request actions through Server RPCs, and the server validates them before it changes any state. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-10` (8) Reference assets that aren't always needed with soft references (`TSoftObjectPtr`, `TSoftClassPtr`), and load them asynchronously. ([specific/unreal/content-and-performance](../specific/unreal/content-and-performance.md))
- [ ] `UNREAL-11` (8) Profile early and often on the target hardware, with Unreal Insights. ([specific/unreal/content-and-performance](../specific/unreal/content-and-performance.md))
- [ ] `UNREAL-37` (8) Keep generated folders out of version control: start from the community `UnrealEngine.gitignore`, which ignores `Binaries/`, `Intermediate/`, `Saved/` and `DerivedDataCache/`, or, with Perforce, from Epic's example `.p4ignore`. ([specific/unreal/project-structure](../specific/unreal/project-structure.md))
- [ ] `UNREAL-17` (8) Keep PSO precaching on, hold the first loading screen until `FShaderPipelineCache::NumPrecompilesRemaining()` reaches zero, and test first-run smoothness with `-clearPSODriverCache`. ([specific/unreal/rendering](../specific/unreal/rendering.md)) *Automatable: PSO precache validation.*
- [ ] `UNREAL-18` (8) Give the team a shared Derived Data Cache, so that each shader and other derived asset is built once for everyone: a Zen Storage Server or a network drive for people in one office, and Unreal Cloud DDC for a distributed team. ([specific/unreal/rendering](../specific/unreal/rendering.md))
- [ ] `UNREAL-3` (7) Write core systems, high-frequency logic and data-heavy work in C++ base classes, and expose a small API that designers extend in Blueprint subclasses. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-4` (7) Put game-wide services in subsystems (`UGameInstanceSubsystem`, `ULocalPlayerSubsystem`, `UEngineSubsystem` or `UEditorSubsystem`) instead of adding them to a custom game instance or overriding engine classes. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-23` (7) Don't poll for changes on Tick: run occasional logic from events, delegates or timers, give logic that must repeat but not every frame a tick interval, and turn ticking off on Actors and components that don't need it. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-26` (7) Put designer-tunable data in Data Tables, whose rows are C++ structs and which designers can import from CSV or JSON files, or in Data Assets, and make content that the Asset Manager loads on demand a Primary Data Asset. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-27` (7) Save games through your own `USaveGame` subclasses, with separate classes for globally unlocked features and for each playthrough's data, and save with `AsyncSaveGameToSlot` during play. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-9` (7) Prefer replicated properties with RepNotify to RPCs, use multicast RPCs sparingly, and make frequently called RPCs unreliable. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-16` (7) Keep all user-facing text in `FText`, created from text properties in assets, `LOCTEXT` macros in C++ or String Tables, and build messages with `FText::Format` and its `plural`, `ordinal` and `gender` argument modifiers. ([specific/unreal/content-and-performance](../specific/unreal/content-and-performance.md))
- [ ] `UNREAL-5` (7) Split code into modules with explicit dependencies in their `Build.cs` files: keep editor-only code in `Editor` modules, and prefer private dependencies to public ones. ([specific/unreal/project-structure](../specific/unreal/project-structure.md)) *Automatable: Unreal Build Tool, module dependencies.*
- [ ] `UNREAL-38` (7) Connect the editor to revision control, and turn on its automatic checkout or checkout prompt on modification, so that assets are checked out, and with that locked, before anyone changes them. ([specific/unreal/project-structure](../specific/unreal/project-structure.md))
- [ ] `UNREAL-15` (7) Keep One File Per Actor on (the default with World Partition), so that several people can change actors in the same level at once. ([specific/unreal/project-structure](../specific/unreal/project-structure.md))
- [ ] `UNREAL-19` (7) Build materials as a few parameterized parent materials, create the variations as Material Instances, and use Material Instance Dynamic only for values that change at run time. ([specific/unreal/rendering](../specific/unreal/rendering.md))
- [ ] `UNREAL-20` (7) Keep material permutations down: use few static switch parameters and few combinations of them across instances, and keep usage flags to the kinds of mesh a material is really used on, because each combination and each flag compiles more shaders. ([specific/unreal/rendering](../specific/unreal/rendering.md))
- [ ] `UNREAL-21` (7) Decide for each target platform, before content production starts, whether to use Nanite and Lumen. ([specific/unreal/rendering](../specific/unreal/rendering.md))
- [ ] `UNREAL-22` (7) Set rendering quality for each platform and device in `Config/DefaultDeviceProfiles.ini`, through the scalability groups (`sg.*`) and console variables, and test every quality level on low-, mid- and high-spec hardware. ([specific/unreal/rendering](../specific/unreal/rendering.md))
- [ ] `UNREAL-14` (7) Write automated tests with the Automation Test Framework, use Low-Level Tests for pure unit tests, and run both from the command line in CI. ([specific/unreal/testing](../specific/unreal/testing.md)) *Automatable: Gauntlet `RunUnreal`.*
- [ ] `UNREAL-41` (7) Write tests for code that needs engine systems as Automation Spec or CQTest tests rather than with the plain automation test macros, and test gameplay that spans frames or needs a level with Functional Tests, Actors placed in a test level. ([specific/unreal/testing](../specific/unreal/testing.md))
- [ ] `UNREAL-28` (6) Choose how Blueprints communicate by the relationship between them: a direct reference for one Actor talking to one specific other, an event dispatcher to tell any number of listeners that something happened, and a Blueprint Interface to call the same function on unrelated classes that each respond in their own way. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-29` (6) Handle player input with Enhanced Input: an Input Action for each thing the player can do, Input Mapping Contexts that you add, remove and prioritize as the player's situation changes, and Player Mappable Input Configs for control presets. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-12` (6) Register the content you load on demand, such as levels and data assets, as primary assets with the Asset Manager, and use asset bundles to control which secondary assets load with them. ([specific/unreal/content-and-performance](../specific/unreal/content-and-performance.md))
- [ ] `UNREAL-32` (6) Keep garbage-collection hitches out of gameplay: pool Actors that are spawned and destroyed often when the CPU budget is tight, and collect garbage manually where a spike is tolerable, such as behind a loading screen. ([specific/unreal/content-and-performance](../specific/unreal/content-and-performance.md))
- [ ] `UNREAL-33` (6) Find out what an asset pulls into memory with the Reference Viewer and its Size Map, and track memory at run time on each target platform with the Low-Level Memory Tracker and Memory Insights. ([specific/unreal/content-and-performance](../specific/unreal/content-and-performance.md))
- [ ] `UNREAL-13` (6) Turn content rules, such as naming conventions and size or performance budgets, into Data Validation rules, and run the `DataValidation` commandlet in CI. ([specific/unreal/content-and-performance](../specific/unreal/content-and-performance.md)) *Automatable: Data Validation commandlet.*
- [ ] `UNREAL-35` (6) Agree on an asset naming convention early in development, starting from Epic's `[AssetTypePrefix]_[AssetName]_[Descriptor]_[OptionalVariantLetterOrNumber]` scheme, and keep each person's experiments in their own Developers folder, which no asset outside it may reference. ([specific/unreal/project-structure](../specific/unreal/project-structure.md))
- [ ] `UNREAL-42` (6) Follow Epic's test design guidelines: don't assume the state of the game or the editor, because tests can run in any order or in parallel on several machines, leave files on disk as you found them, and mark a test as a Smoke test only if it finishes within a second. ([specific/unreal/testing](../specific/unreal/testing.md))
- [ ] `UNREAL-43` (6) Run boot tests and automation tests on packaged builds for each target platform with Gauntlet, not only in the editor. ([specific/unreal/testing](../specific/unreal/testing.md)) *Automatable: Gauntlet `RunUnreal`.*

## Conditional (1–5)

- [ ] `UNREAL-24` (5) Represent statuses, object types and gameplay events as hierarchical Gameplay Tags of the form `Movement.Mode.Swimming`, registered in `.ini` tag lists or as native tags in C++. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-6` (5) Use the Gameplay Ability System for games built around many abilities, attributes and status effects, especially multiplayer ones. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-25` (5) Model AI and other state-driven logic, such as game flow, in StateTree, Epic's general-purpose hierarchical state machine, or, for AI, in Behavior Trees with a Blackboard. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-30` (5) Keep game logic out of UMG widgets: give widgets their data through viewmodels and View Bindings (the UMG Viewmodel plugin, in Beta), which update a widget only when a value changes, and set the *Property Binding Rule* to *Prevent* so that nobody adds legacy property bindings. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md)) *Automatable: UMG Viewmodel, *Property Binding Rule*.*
- [ ] `UNREAL-34` (5) Build large open worlds with World Partition, which stores the world in one level divided into grid cells and streams the cells by distance, instead of dividing the map into sublevels and streaming them by hand. ([specific/unreal/content-and-performance](../specific/unreal/content-and-performance.md))
- [ ] `UNREAL-7` (5) Build optional or frequently changing features as Game Feature plugins, so that unrelated features can't depend on each other by accident. ([specific/unreal/project-structure](../specific/unreal/project-structure.md))
- [ ] `UNREAL-36` (5) After moving or renaming assets, fix up the redirectors they leave behind, in the Content Browser or with the `ResavePackages` commandlet and `-fixupredirects`, and submit the resaved packages. ([specific/unreal/project-structure](../specific/unreal/project-structure.md))
- [ ] `UNREAL-39` (5) Script CI builds, cooks and tests with BuildGraph, and give artists and designers the editor binaries that CI builds, for example through Unreal Game Sync with Perforce, so that they don't have to compile. ([specific/unreal/project-structure](../specific/unreal/project-structure.md))
- [ ] `UNREAL-40` (5) Iterate on C++ with Live Coding, which is on by default and is significantly faster and more flexible than Hot Reload, and keep Object Reinstancing on so that structural changes reach existing objects. ([specific/unreal/project-structure](../specific/unreal/project-structure.md))
- [ ] `UNREAL-31` (4) In games with many players and many replicated Actors, decide what each client receives with the Replication Graph, and evaluate Iris, which is still Experimental, before relying on it. ([specific/unreal/code-architecture](../specific/unreal/code-architecture.md))
- [ ] `UNREAL-44` (4) Catch rendering regressions with screenshot comparison tests: place Functional Screenshot Test Actors in test levels, turn off noisy rendering features, set a tolerance, and review differences in the Screenshot Comparison browser. ([specific/unreal/testing](../specific/unreal/testing.md))
