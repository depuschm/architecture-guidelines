# Unreal Engine checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Strongly recommended (9–10)

- [ ] `UNREAL-1` (9) Hold UObject references that must keep their target alive in `UPROPERTY` members, preferably `TObjectPtr`, and use `TWeakObjectPtr` for references that must not. ([specific/unreal](../specific/unreal/README.md)) *Automatable: PVS-Studio V1100.*

## Recommended (6–8)

- [ ] `UNREAL-2` (8) Put match rules in the game mode, which exists only on the server, state that all players need in the game state, per-player state in the player state, and anything that must survive a level change in the game instance or its subsystems. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-8` (8) Keep the server authoritative: clients request actions through Server RPCs, and the server validates them before it changes any state. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-10` (8) Reference assets that aren't always needed with soft references (`TSoftObjectPtr`, `TSoftClassPtr`), and load them asynchronously. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-11` (8) Profile early and often on the target hardware, with Unreal Insights. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-3` (7) Write core systems, high-frequency logic and data-heavy work in C++ base classes, and expose a small API that designers extend in Blueprint subclasses. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-4` (7) Put game-wide services in subsystems (`UGameInstanceSubsystem`, `ULocalPlayerSubsystem`, `UEngineSubsystem` or `UEditorSubsystem`) instead of adding them to a custom game instance or overriding engine classes. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-5` (7) Split code into modules with explicit dependencies in their `Build.cs` files: keep editor-only code in `Editor` modules, and prefer private dependencies to public ones. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-9` (7) Prefer replicated properties with RepNotify to RPCs, use multicast RPCs sparingly, and make frequently called RPCs unreliable. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-16` (7) Keep all user-facing text in `FText`, created from text properties in assets, `LOCTEXT` macros in C++ or String Tables, and build messages with `FText::Format` and its `plural`, `ordinal` and `gender` argument modifiers. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-15` (7) Keep One File Per Actor on (the default with World Partition), so that several people can change actors in the same level at once. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-14` (7) Write automated tests with the Automation Test Framework, use Low-Level Tests for pure unit tests, and run both from the command line in CI. ([specific/unreal](../specific/unreal/README.md)) *Automatable: Gauntlet `RunUnreal`.*
- [ ] `UNREAL-12` (6) Register the content you load on demand, such as levels and data assets, as primary assets with the Asset Manager, and use asset bundles to control which secondary assets load with them. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-13` (6) Turn content rules, such as naming conventions and size or performance budgets, into Data Validation rules, and run the `DataValidation` commandlet in CI. ([specific/unreal](../specific/unreal/README.md)) *Automatable: Data Validation commandlet.*

## Conditional (1–5)

- [ ] `UNREAL-6` (5) Use the Gameplay Ability System for games built around many abilities, attributes and status effects, especially multiplayer ones. ([specific/unreal](../specific/unreal/README.md))
- [ ] `UNREAL-7` (5) Build optional or frequently changing features as Game Feature plugins, so that unrelated features can't depend on each other by accident. ([specific/unreal](../specific/unreal/README.md))
