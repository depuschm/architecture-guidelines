# Web games checklist

Copy this list into a pull request, design review or project kickoff and tick what applies.
Rules are grouped by level and sorted by score ([criteria](../RANKING.md)). Each links to the file that explains it and cites its sources.
*Automatable* names tools that can check the rule in CI (see the file's "How to enforce" section).

Also apply the [general checklist](general.md).

This file is generated by `python3 scripts/rank.py fix` from the guidelines. Don't edit it by hand.

## Recommended (6–8)

- [ ] `WEBGAME-1` (8) Before you choose a scripting language, renderer or plugins, check what the engine's web export supports. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-5` (8) Set a download budget for the first load and for the whole game, from the portals and devices you target, and check every build against it. ([specific/web-games](../specific/web-games/README.md)) *Automatable: Lighthouse CI.*
- [ ] `WEBGAME-9` (8) Start audio from the player's first click, tap or key press, for example on a "tap to play" screen, and resume the `AudioContext` from a later tap whenever it is suspended or interrupted. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-13` (8) Store saves in IndexedDB rather than `localStorage`, request persistent storage when the player first saves, and keep a copy of progress that matters on a server, such as a portal's cloud save or your own backend. ([specific/web-games](../specific/web-games/README.md)) *Automatable: ESLint `no-restricted-globals`.*
- [ ] `WEBGAME-2` (7) Serve the engine's precompressed build files over HTTPS with the matching `Content-Encoding` header, `gzip` for `.gz` and `br` for `.br` files, and serve `.wasm` files as `application/wasm`. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-3` (7) Export without threads unless you control the headers of every page that hosts the game. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-6` (7) Download only what the first scene needs before play starts, load the rest per scene in the background, and let the engine cache downloaded files on the player's device. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-7` (7) When the page becomes hidden, pause the game, suspend the `AudioContext` and save progress. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-10` (7) Handle mouse, touch and pen with Pointer Events on the game canvas, set `touch-action: none` on the canvas only, and if the game runs in mobile browsers, give it touch controls and a layout for each orientation it supports. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-15` (7) Free GPU resources explicitly when a level or scene ends: in three.js, call `dispose()` on geometries, materials, textures and render targets, and in Phaser, remove assets that only the finished scene used. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-4` (6) Ship GPU texture formats for both desktop and mobile browsers: in Unity, make two builds, one with DXT for desktop and one with ASTC for mobile browsers, and in Godot, turn on VRAM texture compression for both desktop and mobile in the web export preset. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-8` (6) If you write your own game loop, drive it with `requestAnimationFrame`, request the next frame before doing the frame's work, and advance the fixed time step of `GAMEDEV-1` from the callback's timestamp. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-11` (6) Read gamepads by polling `navigator.getGamepads()` once per frame, ask the player to press a button before expecting a controller to appear, and let players remap buttons when a gamepad's `mapping` isn't `"standard"`. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-12` (6) Request fullscreen and pointer lock only from a click or key-press handler, handle a refusal, and check that the page embedding the game allows them. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-14` (6) If you publish on web game portals, integrate each portal's SDK and meet its technical requirements from the start: report loading and gameplay events, show ads only through the portal's SDK, and bundle every asset into the build. ([specific/web-games](../specific/web-games/README.md))
- [ ] `WEBGAME-16` (6) Profile web builds in the browser on the slowest device you support, and move heavy work that doesn't draw, such as pathfinding or procedural generation, to Web Workers. ([specific/web-games](../specific/web-games/README.md))
