# Angular

Scope: web apps built with Angular 22, the current major version (released on 3 June 2026), with standalone components, signals, the Angular CLI and, where used, Angular's server-side rendering. Angular 21 and 20 still get critical and security fixes in long-term support, until June 2027 and 28 November 2026, and older versions are no longer supported. From version 22 on, a new major version ships every 12 months instead of every 6 ([Angular, Versioning and releases](https://angular.dev/reference/releases)). Framework-independent rules for accessibility, performance, security and testing (`WEB-*`) are in [Web front end](../web/README.md), and the compiler settings (`TS-*`) in [TypeScript](../typescript/README.md). The Node.js server that renders pages for server-side rendering is backend code, so the [Node.js](../nodejs/README.md) and [Security](../../general/security.md) guidelines also apply to it.

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

- `10` [Angular documentation](https://angular.dev/overview): **the baseline.** The essentials and in-depth guides to components, templates, signals, dependency injection, routing, forms, the HTTP client, server-side and hybrid rendering, testing and internationalization, and the best-practice pages on security, accessibility and performance.
- `9` [Angular coding style guide](https://angular.dev/style-guide): the official Angular-specific conventions: file names that match the class inside, such as `user-profile.ts` for `UserProfile`, one concept per file, folders by feature instead of by type, `inject()` instead of constructor injection, and components that focus on presentation.
- `8` [Angular, Security](https://angular.dev/best-practices/security): Angular's XSS model and sanitization, Content Security Policy and Trusted Types, XSRF protection in `HttpClient`, and, for server-side rendering, allowed host names and trusted proxy headers against server-side request forgery.
- `8` [Angular, Signals](https://angular.dev/guide/signals): writable and computed signals, reactive contexts and read-only signals, with guides to `linkedSignal`, resources and effects.
- `8` [Angular, Server-side and hybrid rendering](https://angular.dev/guide/ssr): choosing a rendering mode, server routes with a render mode per route, prerendering, the HTTP transfer cache, and writing components that also run on the server.
- `7` [Angular, Performance](https://angular.dev/best-practices/performance): when to use each loading technique (lazy-loaded routes, `@defer`, lazy-loaded services, image optimization and server-side rendering) and each runtime technique (zoneless change detection, slow computations, skipping component subtrees and profiling).
- `7` [Angular, Versioning and releases](https://angular.dev/reference/releases): the release schedule, the support window of 12 months active and 12 months long-term support, the supported versions, the deprecation policy and the supported update paths.
- `7` [Angular Update Guide](https://angular.dev/update-guide): step-by-step instructions for an update between two versions, filtered by the app's complexity and dependencies such as Angular Material.
- `7` [Angular, Accessibility](https://angular.dev/best-practices/a11y): ARIA bindings, building on native elements, focus management and active links after routing, and the accessible components in Angular Material, the CDK and Angular Aria.
- `7` [Angular, Testing](https://angular.dev/guide/testing): unit tests with Vitest, the default runner for new projects, tests in a real browser, code coverage, CI, and guides to testing components, services, routing and HTTP and to component harnesses.
- `6` [Angular CLI](https://angular.dev/tools/cli): creating, building, serving, testing and updating apps with `ng`, plus builders and schematics. The esbuild-based application builder is the default, and the webpack-based `browser` builder is [deprecated](https://angular.dev/tools/cli/build-system-migration).

## Key rules

### Components and reactivity

- `7` `ANGULAR-1` **Keep the current defaults in new code: standalone components, `OnPush` change detection and zoneless change detection. Don't set `standalone: false`, `ChangeDetectionStrategy.Eager` or `provideZoneChangeDetection()`.** The Angular team recommends standalone components instead of NgModules for all new code, components are `OnPush` by default since version 22, and apps are zoneless by default since version 21. ([Angular, NgModules](https://angular.dev/guide/ngmodules/overview), [Skipping component subtrees: using OnPush](https://angular.dev/best-practices/skipping-subtrees#using-onpush), [Zoneless: enabling zoneless](https://angular.dev/guide/zoneless#enabling-zoneless-in-an-application))
- `7` `ANGULAR-2` **Derive state with `computed()`, or with `linkedSignal()` when the user can also set it, and use `effect()` only to sync signals with APIs that aren't reactive, such as storage, logging, or a canvas or third-party UI library.** Copying one signal into another with an effect can cause `ExpressionChangedAfterItHasBeenChecked` errors, circular updates and extra change detection. ([Angular, Use cases for effects](https://angular.dev/guide/signals/effect#use-cases-for-effects), [Dependent state with linkedSignal](https://angular.dev/guide/signals/linked-signal))
- `6` `ANGULAR-3` **Declare inputs, outputs and queries with the signal-based functions, such as `input()`, `output()`, `model()` and `viewChild()`, and name outputs in camelCase, without an `on` prefix and without the name of a DOM event such as `click`.** The decorator-based APIs remain supported, but the Angular team recommends the functions for new projects. ([Angular, Accepting data with input properties](https://angular.dev/guide/components/inputs), [Outputs: choosing event names](https://angular.dev/guide/components/outputs#choosing-event-names), [Queries](https://angular.dev/guide/components/queries))
- `6` `ANGULAR-4` **Use the built-in control flow (`@if`, `@for` and `@switch`) instead of the deprecated `*ngIf`, `*ngFor` and `*ngSwitch`, and give every `@for` a `track` expression with a property that uniquely identifies the item, such as its ID.** Track by `$index` only for collections that never change, and avoid tracking the item itself, which can make updates much slower. ([Angular, Why is track in @for blocks important?](https://angular.dev/guide/templates/control-flow#why-is-track-in-for-blocks-important), [NgIf](https://angular.dev/api/common/NgIf))

### Services and state

- `7` `ANGULAR-5` **Keep components focused on presentation, and move business logic, data access and state that several components share into services. Keep that state in private writable signals, and expose it as read-only signals, with `asReadonly()` or `computed()`, plus methods that change it.** ([Angular style guide, Keep components and directives focused on presentation](https://angular.dev/style-guide#keep-components-and-directives-focused-on-presentation), [Creating and using services](https://angular.dev/guide/di/creating-and-using-services), [Signals: converting writable signals to readonly](https://angular.dev/guide/signals#converting-writable-signals-to-readonly))
- `6` `ANGULAR-6` **Declare app-wide services with `@Service()`, or with `@Injectable({providedIn: 'root'})` before Angular 22, inject dependencies with `inject()`, and provide a service in a route's `providers` instead when only one feature uses it.** Root services are tree-shakable singletons. Route providers load with the feature's lazy-loaded routes, and its components, guards and resolvers share them. ([Angular, When to use @Service vs @Injectable](https://angular.dev/guide/di/creating-and-using-services#when-to-use-service-vs-injectable), [Style guide: prefer the inject function](https://angular.dev/style-guide#prefer-the-inject-function-over-constructor-parameter-injection), [Route providers](https://angular.dev/guide/di/defining-dependency-providers#route-providers))
- `6` `ANGULAR-7` **Read data that depends on signals with `httpResource()`, convert Observables that templates read with `toSignal()`, and send changes, such as `POST` and `PUT` requests, with `HttpClient` directly.** Give `httpResource()` a `parse` function, such as a Zod schema, to check responses at run time (`TS-8`), and put cross-cutting concerns, such as retries, caching and logging, in functional interceptors, which behave more predictably than DI-based ones. ([Angular, Using httpResource](https://angular.dev/guide/http/http-resource#using-httpresource), [Response parsing and validation](https://angular.dev/guide/http/http-resource#response-parsing-and-validation), [toSignal](https://angular.dev/ecosystem/rxjs-interop#create-a-signal-from-an-rxjs-observable-with-tosignal), [Interceptors](https://angular.dev/guide/http/interceptors))

### Routing and rendering

- `7` `ANGULAR-8` **Lazy-load every route except the main landing pages with `loadComponent` or `loadChildren`, and wrap heavy components that aren't visible on the first render in `@defer` blocks.** Don't defer content in the initial viewport, which causes layout shifts, and give nested `@defer` blocks different triggers. This is how an Angular app applies `WEB-5`. ([Angular, Should I use an eager or a lazy route?](https://angular.dev/guide/routing/loading-strategies#should-i-use-an-eager-or-a-lazy-route), [Lazily loaded components and routes](https://angular.dev/guide/routing/loading-strategies#lazily-loaded-components-and-routes), [Best practices for deferring views](https://angular.dev/guide/templates/defer#best-practices-for-deferring-views))
- `7` `ANGULAR-9` **In server-rendered apps, set a render mode for each route in the server routes: `RenderMode.Prerender` for pages that are the same for every user, `RenderMode.Server` for pages with user-specific data, and `RenderMode.Client` only where load performance and SEO matter less.** For hydration, render the same DOM on the server and in the browser: run browser-only code in `afterNextRender()`, and don't access `document` or change the DOM with native APIs. ([Angular, Server routing](https://angular.dev/guide/ssr#server-routing), [Choosing a rendering mode](https://angular.dev/guide/ssr#choosing-a-rendering-mode), [Authoring server-compatible components](https://angular.dev/guide/ssr#authoring-server-compatible-components), [Hydration: constraints](https://angular.dev/guide/hydration#constraints))
- `6` `ANGULAR-10` **Give every route a `title`, and move focus to the main content after each navigation.** Angular sets the page title when the route activates. For focus, listen for the router's `NavigationEnd` event, so that focus doesn't fall back to the `body` element. ([Angular, Page titles](https://angular.dev/guide/routing/define-routes#page-titles), [Accessibility: focus management after navigation](https://angular.dev/best-practices/a11y#focus-management-after-navigation))

### Security

- `9` `ANGULAR-11` **Never use route guards as access control: check authorization on the server for every request.** Guards only decide what the browser shows, and users can change any JavaScript that runs in their browser. This applies `SEC-1` in [Security](../../general/security.md), and [Authentication](../../general/authentication.md) covers sessions and tokens. ([Angular, Control route access with guards](https://angular.dev/guide/routing/route-guards))
- `9` `ANGULAR-12` **Never build Angular templates from user input: ship only templates that the CLI compiles ahead of time, and don't generate Angular templates with a server-side templating language.** Angular treats templates as trusted, executable code, so injected template syntax gives an attacker full control of the app. ([Angular, Security: XSS security model](https://angular.dev/best-practices/security#angulars-cross-site-scripting-security-model), [Use the AOT template compiler](https://angular.dev/best-practices/security#use-the-aot-template-compiler), [Server-side XSS protection](https://angular.dev/best-practices/security#server-side-xss-protection))
- `9` `ANGULAR-13` **Insert untrusted values through template bindings, so that Angular sanitizes them, never pass them to the `DomSanitizer.bypassSecurityTrust*()` methods, and don't write to the DOM through `ElementRef.nativeElement` or `document`.** Where direct DOM access can't be avoided, sanitize values with `DomSanitizer.sanitize()` and the matching `SecurityContext`. This is how an Angular app applies `WEB-8`. ([Angular, Sanitization and security contexts](https://angular.dev/best-practices/security#sanitization-and-security-contexts), [Trusting safe values](https://angular.dev/best-practices/security#trusting-safe-values), [Direct use of the DOM APIs](https://angular.dev/best-practices/security#direct-use-of-the-dom-apis-and-explicit-sanitization-calls))
- `9` `ANGULAR-14` **Never put secrets, such as API keys, in the files in `src/environments/`: the build bundles them into the client, where anyone who loads the page can read them.** Keep secrets on a server, for example behind a proxy. This applies `SEC-11`. ([Angular, Build environments](https://angular.dev/tools/cli/environments#configure-environment-specific-defaults))
- `7` `ANGULAR-15` **Send a Content Security Policy with a unique, unpredictable nonce for each response, and pass the nonce to Angular with the `ngCspNonce` attribute or the `CSP_NONCE` token. On static hosting that can't add a nonce, turn on `autoCsp` or avoid inline scripts, instead of hard-coding a nonce.** Also enforce Trusted Types with Angular's `angular` policy. This is how an Angular app applies `WEB-10`. ([Angular, Content security policy](https://angular.dev/best-practices/security#content-security-policy), [Hash inline scripts with autoCsp](https://angular.dev/best-practices/security#hash-inline-scripts-with-autocsp), [Enforcing Trusted Types](https://angular.dev/best-practices/security#enforcing-trusted-types))

### Build, tooling and upgrades

- `8` `ANGULAR-16` **Run a major version that is still supported, update with `ng update` one major version at a time, and plan each yearly major update before your version's long-term support ends.** `ng update` also runs the code migrations for the new version. This applies `SEC-17`. ([Angular, Actively supported versions](https://angular.dev/reference/releases#actively-supported-versions), [Breaking change policy and update paths](https://angular.dev/reference/releases#breaking-change-policy-and-update-paths), [ng update](https://angular.dev/cli/update))
- `7` `ANGULAR-17` **Keep strict template type checking on (`strictTemplates`, the default) together with TypeScript's `strict` (`TS-1`), and make the extended diagnostics fail the build by setting their `defaultCategory` to `error`.** Extended diagnostics find mistakes such as signals that aren't called in interpolations and `track` functions that aren't called, but by default they are only warnings. ([Angular, Template type checking: strict mode](https://angular.dev/tools/cli/template-typecheck#strict-mode), [Extended diagnostics: configuration](https://angular.dev/extended-diagnostics#configuration))

### Testing

- `6` `ANGULAR-18` **Test components the way users use them, and let Angular schedule change detection: drive shared UI components through component harnesses, await `fixture.whenStable()` instead of calling `fixture.detectChanges()`, and answer HTTP requests with `HttpTestingController`, then call `verify()`.** These are Angular's tools for `WEB-14` and `WEB-20`. ([Angular, Component harnesses overview](https://angular.dev/guide/testing/component-harnesses-overview), [Zoneless: using zoneless in TestBed](https://angular.dev/guide/zoneless#using-zoneless-in-testbed), [Testing HttpClient](https://angular.dev/guide/http/testing))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [Angular extended diagnostics](https://angular.dev/extended-diagnostics): compiler checks that run with strict template type checking, such as [NG8109](https://angular.dev/extended-diagnostics/NG8109) for signals that aren't called in interpolations and [NG8115](https://angular.dev/extended-diagnostics/NG8115) for `track` functions that aren't called. With `defaultCategory` set to `error`, `ng build` fails on them. The [`strictStandalone`](https://angular.dev/reference/configs/angular-compiler-options#strictstandalone) compiler option also reports every component, directive or pipe that isn't standalone. Checks `ANGULAR-17`, and partly `ANGULAR-1`.
- `6` [angular-eslint](https://github.com/angular-eslint/angular-eslint/blob/main/README.md): ESLint rules for Angular code and templates, set up with `ng add angular-eslint`. The [recommended configs](https://github.com/angular-eslint/angular-eslint/blob/main/packages/angular-eslint/src/configs/README.md) include [`prefer-standalone`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin/docs/rules/prefer-standalone.md), [`prefer-on-push-component-change-detection`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin/docs/rules/prefer-on-push-component-change-detection.md), which flags components that opt out of the default `OnPush`, [`prefer-inject`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin/docs/rules/prefer-inject.md), [`no-output-native`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin/docs/rules/no-output-native.md), [`no-output-on-prefix`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin/docs/rules/no-output-on-prefix.md) and [`template/prefer-control-flow`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin-template/docs/rules/prefer-control-flow.md). Turn on [`prefer-signals`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin/docs/rules/prefer-signals.md) and [`prefer-output-emitter-ref`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin/docs/rules/prefer-output-emitter-ref.md) for signal-based inputs, queries and outputs, and [`prefer-service-decorator`](https://github.com/angular-eslint/angular-eslint/blob/main/packages/eslint-plugin/docs/rules/prefer-service-decorator.md) on Angular 22. Partly checks `ANGULAR-1`, `ANGULAR-3`, `ANGULAR-4` and `ANGULAR-6`.
- `6` [Angular CLI size budgets](https://angular.dev/tools/cli/build#configuring-size-budgets): `ng build` fails when the initial bundle, a named lazy-loaded bundle or another budget type grows past its `maximumError`. Partly checks `ANGULAR-8`.
- `5` [Semgrep `angular-bypasssecuritytrust`](https://github.com/semgrep/semgrep-rules/blob/develop/typescript/angular/security/audit/angular-domsanitizer.yaml): flags calls to the `bypassSecurityTrust*()` methods whose argument comes from a string parameter of the surrounding function and wasn't sanitized, for example with DOMPurify. Partly checks `ANGULAR-13`.
