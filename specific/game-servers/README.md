# Game servers and online services

Scope: running dedicated game servers and the online services around them, whatever the engine: headless server builds, orchestration with Agones on Kubernetes or managed hosting on Amazon GameLift Servers, matchmaking and placement, game backends such as Nakama for player data, economy and leaderboards, releases, security, observability and cost. The guidelines cover Agones 1.61, Amazon GameLift Servers with server SDK 5.x, Nakama 3.41, Unity 6 with the Dedicated Server package 3.0, Unreal Engine 5.9 and Godot 4.7. Unity's Multiplay Game Server Hosting was [deprecated on 1 April 2026](https://status.unity.com/info_notices/362941), and Hathora shut down in May 2026. Client-server authority and netcode are in [Game development](../gamedev/README.md) (`GAMEDEV-5` to `GAMEDEV-9`), and each engine's multiplayer rules are in [Unreal Engine](../unreal/code-architecture.md) (`UNREAL-8`, `UNREAL-9`), [Godot](../godot/code-architecture.md) (`GODOT-24`), [Unity](../unity/code-architecture.md) (`UNITY-CODE-12`) and [GameMaker](../gamemaker/code-architecture.md) (`GAMEMAKER-CODE-14`). Agones runs on [Kubernetes](../kubernetes/README.md), so the `K8S` rules apply to its clusters, store purchases follow [Mobile games](../mobile-games/README.md) (`MOBGAME-1`), and Steam session tickets and server-set stats are in [Steam and PC games](../steam/README.md) (`STEAM-5`, `STEAM-8`). The general rules in [Operations and reliability](../../general/operations-reliability.md), [Security](../../general/security.md), [Authentication](../../general/authentication.md) and [OpenTelemetry](../opentelemetry/README.md) apply to every game server and backend service.

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

No single guide covers game server hosting across providers. Use the documentation of the platform you host on as its baseline.

- `9` [Agones documentation](https://agones.dev/site/docs/): **the baseline for hosting on Kubernetes**: GameServers and their lifecycle, the game server SDKs, Fleets, allocation, FleetAutoscalers, fleet updates, health checking, metrics and integration patterns.
- `9` [Amazon GameLift Servers Hosting Guide](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift-intro.html): **the baseline for managed hosting on AWS**: managed EC2 and container fleets, Anywhere fleets for your own hardware, game session placement, scaling, monitoring and security. Use the [decision guide](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/fleets-decision-guide.html) to choose a fleet type.
- `8` [Prepare for launch with Amazon GameLift Servers hosting](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift_quickstart_customservers_checklist.html): the launch checklists for testing, launch day and after launch, with the items that are critical for production.
- `8` [Nakama concepts](https://heroiclabs.com/docs/nakama/concepts/) (Heroic Labs): **the baseline for an open-source game backend**: accounts and authentication, the storage engine and its access controls, authoritative multiplayer, the matchmaker, leaderboards, wallets and purchase validation.
- `7` [Agones best practices](https://agones.dev/site/docs/guides/best-practices/): separating the Agones system from game server nodes, Pod Security Standards for GameServers, and spreading game servers across clusters and fault domains, with a [page for GKE](https://agones.dev/site/docs/guides/best-practices/gke/).
- `7` [Nakama server framework best practices](https://heroiclabs.com/docs/nakama/server-framework/introduction/best-practices/) (Heroic Labs): performance and scalability patterns for server runtime code, match handlers and hooks, with a launch checklist.
- `7` [Amazon GameLift Servers FlexMatch](https://docs.aws.amazon.com/gameliftservers/latest/flexmatchguide/match-intro.html): rule-based matchmaking on skill, roles and latency, either with GameLift hosting or on its own.
- `7` [Cost optimization strategies](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift-pricing-cost-optimization.html) (Amazon GameLift Servers): instance types, Graviton and Linux servers, Spot capacity, processes per instance, scaling to zero and data transfer.
- `7` [Unity, Introduction to Dedicated Server](https://docs.unity3d.com/Manual/dedicated-server-introduction.html), [Unreal Engine, Setting up dedicated servers](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-dedicated-servers-in-unreal-engine) and [Godot, Exporting for dedicated servers](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_dedicated_servers.html): how each engine builds a headless server.
- `6` [Amazon GameLift Servers FleetIQ best practices](https://docs.aws.amazon.com/gameliftservers/latest/fleetiqguide/gsg-best-practices.html): FleetIQ on its own, for hosting on Spot Instances in your own Amazon EC2 game server groups; it works best for session-based games with sessions under two hours.
- `6` [Edgegap documentation](https://docs.edgegap.com/learn/orchestration): an alternative managed host that starts a deployment for each match at the edge, with its own matchmaker, server browser, ping beacons and DDoS protection.
- `4` [Open Match 2](https://github.com/googleforgames/open-match2/blob/main/README.md) (Google for Games): an open-source framework for building your own matchmaker. It is a public preview, and Open Match 1 hasn't had a release since 2023, so weigh it against FlexMatch or Nakama's matchmaker.

## Key rules

### Server builds and lifecycle

- `7` `GAMESERVER-1` **Drive each game server through the hosting platform's lifecycle with its server SDK: report ready only when it can accept players, keep its health checks passing, mark it allocated when a match starts, and end the process when the match is over.** In Agones, call `Ready()`, `Health()` and `Shutdown()`, and let the matchmaker allocate with a `GameServerAllocation` rather than `Allocate()`; in GameLift, call `ProcessReady()`, answer `onHealthCheck()` within 60 seconds, call `ActivateGameSession()`, and call `ProcessEnding()` and exit when the session is over, so that the hosting resources are recycled. ([Agones, Client SDKs: lifecycle management](https://agones.dev/site/docs/guides/client-sdks/#lifecycle-management), [Agones, Health checking](https://agones.dev/site/docs/guides/health-checking/), [Amazon GameLift Servers, Add Amazon GameLift Servers to your game server](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift-sdk-server-api.html))
- `7` `GAMESERVER-2` **Ship the server as its own headless build without rendering, audio or client-only assets: Unity's Dedicated Server build target, an Unreal `Server` target, or a Godot export preset in *Export as dedicated server* mode.** Unity's target turns off the audio subsystem and removes GPU-only assets, and Multiplayer Roles strip client-only GameObjects; Godot's mode replaces textures and materials with placeholders; Unreal needs a source build of the engine to build a server target. ([Unity, Dedicated Server optimizations](https://docs.unity3d.com/Manual/dedicated-server-optimizations.html), [Unity, Multiplayer roles](https://docs.unity3d.com/Packages/com.unity.dedicated-server@3.0/manual/multiplayer-roles.html), [Unreal Engine, Setting up dedicated servers](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-dedicated-servers-in-unreal-engine), [Godot, Exporting for dedicated servers](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_dedicated_servers.html#exporting-a-project-for-a-dedicated-server))
- `7` `GAMESERVER-3` **Choose the lowest tick rate that gives an acceptable player experience, and keep each tick within its time budget, with no database or HTTP calls inside it.** Load player data when players join, keep the match state in memory, and save results when the match ends or on a coarse interval; Nakama ends a match whose loops keep falling behind. ([Nakama, Authoritative multiplayer: tick rate](https://heroiclabs.com/docs/nakama/concepts/multiplayer/authoritative/#tick-rate), [Nakama, Server framework best practices: match handlers](https://heroiclabs.com/docs/nakama/server-framework/introduction/best-practices/#match-handlers))

### Scaling and disruption

- `9` `GAMESERVER-4` **Don't let a scale-down or node maintenance end a running match.** On GameLift, set the fleet's game session protection policy to `FullProtection`, because the default, `NoProtection`, lets a scale-down end active sessions; on Agones, set `eviction.safe` from your session length and `SIGTERM` handling, and for sessions longer than an hour control node upgrades yourself, for example with blue/green clusters. ([Amazon GameLift Servers, Prepare for launch](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift_quickstart_customservers_checklist.html#gamelift_quickstart_customservers_launch_checklist), [CreateFleet: NewGameSessionProtectionPolicy](https://docs.aws.amazon.com/gameliftservers/latest/apireference/API_CreateFleet.html#API_CreateFleet_RequestParameters), [Agones, Controlling disruption](https://agones.dev/site/docs/advanced/controlling-disruption/#eviction-api), [Agones, GKE best practices](https://agones.dev/site/docs/guides/best-practices/gke/))
- `7` `GAMESERVER-5` **Scale each fleet with a buffer of ready servers: start with a generous buffer and a maximum well above the expected peak, and lower the buffer later from real usage.** Use an Agones FleetAutoscaler with a `Buffer` policy and the default `Packed` scheduling, which lets the cluster autoscaler remove empty nodes, or GameLift target-based auto scaling on `PercentAvailableGameSessions`; for launch, GameLift suggests 20% idle capacity and a maximum of twice the expected peak. ([Agones, Fleet Autoscaler: ready buffer autoscaling](https://agones.dev/site/docs/reference/fleetautoscaler/#ready-buffer-autoscaling), [Agones, Scheduling and autoscaling: Packed](https://agones.dev/site/docs/advanced/scheduling-and-autoscaling/#packed), [Amazon GameLift Servers, Target-based auto scaling](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/fleets-autoscaling-target.html), [Prepare for launch](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift_quickstart_customservers_checklist.html))
- `7` `GAMESERVER-6` **Handle the shutdowns you can't prevent: when the platform signals termination, stop accepting players, save the match state, disconnect players cleanly and exit before the deadline.** GameLift calls `onProcessTerminate()` for unhealthy processes, scale-downs and Spot interruptions, and `GetTerminationTime()` returns the deadline; on Agones, handle `SIGTERM` within `terminationGracePeriodSeconds`. This applies `OPS-15` and `K8S-3`. ([Amazon GameLift Servers, Respond to a server process shutdown notification](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift-sdk-server-api.html#gamelift-sdk-server-terminate), [Agones, Client SDKs: Shutdown](https://agones.dev/site/docs/guides/client-sdks/#shutdown), [Agones, Controlling disruption: considerations](https://agones.dev/site/docs/advanced/controlling-disruption/#considerations))
- `7` `GAMESERVER-7` **Run game servers in more than one region, and in more than one cluster or fleet per region, and allocate across them, so that one failed cluster doesn't stop matches from starting.** Agones suggests spreading game servers across fault domains and across several clusters within each, allocating across clusters through a service mesh, and upgrading Agones and Kubernetes by moving a growing share of matches to a new cluster; GameLift recommends multi-location queues. This applies `OPS-13`. ([Agones, Best practices: redundant clusters](https://agones.dev/site/docs/guides/best-practices/#redundant-clusters), [Agones, Upgrading Agones: multiple clusters](https://agones.dev/site/docs/installation/upgrading/#upgrading-agones-multiple-clusters), [Amazon GameLift Servers, Build a multi-location queue](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/queues-design-multiregion.html))

### Matchmaking and placement

- `8` `GAMESERVER-8` **Let a backend service that authenticates players request matches and game servers for them, and take skill ratings and other matching attributes from server-side data, not from the client.** Game clients shouldn't call the GameLift API directly; in Nakama, which is such a backend, set matchmaker properties authoritatively in a before hook on `MatchmakerAdd`. This applies `SEC-1` and `GAMEDEV-5`. ([Amazon GameLift Servers, Build a backend service](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift_quickstart_customservers_designbackend.html), [Nakama, Matchmaker: properties](https://heroiclabs.com/docs/nakama/concepts/multiplayer/matchmaker/#properties))
- `7` `GAMESERVER-9` **Place each match in the region with the lowest measured latency for its players: have clients time UDP round trips to each region, send the results with the matchmaking request, cap the latency you accept, and relax the limits step by step while players wait.** UDP pings reflect game traffic better than ICMP pings. ([Amazon GameLift Servers, UDP ping beacons](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/reference-udp-ping-beacons.html), [Create a player latency policy](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/queues-design-latency.html), [FlexMatch, Allow requirements to relax over time](https://docs.aws.amazon.com/gameliftservers/latest/flexmatchguide/match-rulesets-components-expansion.html), [Agones, Latency testing services](https://agones.dev/site/docs/guides/ping-service/), [Nakama, Matchmaker: expanding criteria](https://heroiclabs.com/docs/nakama/concepts/multiplayer/matchmaker/#expanding-criteria))

### Releases and versions

- `8` `GAMESERVER-10` **Roll out new server builds without ending running matches: start the new version next to the old one, send new matches to it, and let the old servers exit when their matches end.** Agones rolling updates never delete `Allocated` game servers, and a second Fleet that `GameServerAllocation` prefers allows canary tests and rollback; on GameLift, create a new fleet and move traffic with an alias or queue, and replace fleets at least every 30 days, because only a new fleet gets a newer AMI. This applies `OPS-15`. ([Agones, Fleet updates](https://agones.dev/site/docs/guides/fleet-updates/), [Agones, Canary testing a new Fleet](https://agones.dev/site/docs/integration-patterns/canary-testing/), [Amazon GameLift Servers, Managing game server updates](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift-prod-hosting.html#gamelift-prod-hosting-updates), [Security best practices: keep fleet runtime environments up to date](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/security-best-practices.html#security-best-practices-fleetupdates))
- `7` `GAMESERVER-11` **Version the network protocol, check the version when a client connects, and reject clients that don't match; send players only to servers running a build compatible with their client.** Unreal compares `FNetworkVersion` values, by default a checksum of the engine version, project name and project version, and Netcode for GameObjects checks that the client's `NetworkConfig`, including `ProtocolVersion`, matches the server's; Agones allocation selects servers by label, such as a version label. ([Unreal Engine 5.7 API, FNetworkVersion::GetLocalNetworkVersion](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/FNetworkVersion/GetLocalNetworkVersion?application_version=5.7), [Game Mode and Game State: PreLogin](https://dev.epicgames.com/documentation/en-us/unreal-engine/game-mode-and-game-state-in-unreal-engine), [Netcode for GameObjects, Connection approval](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@3.1/manual/basics/connection-approval.html), [NetworkConfig.ProtocolVersion](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@3.1/api/Unity.Netcode.NetworkConfig.html), [Agones, GameServerAllocation across Fleets](https://agones.dev/site/docs/guides/fleet-updates/#gameserverallocation-across-fleets))

### Security

- `9` `GAMESERVER-12` **Before launch, replace every default credential and close every administration port: change Nakama's `socket.server_key`, `session.encryption_key`, `runtime.http_key` and console password, and close RDP (3389) and SSH (22) on live fleets.** Give game servers short-lived credentials for other services through the fleet's role, such as GameLift's `GetFleetRoleCredentials()`, as `SEC-14` asks, and keep the Kubernetes API token out of the game server container, which Agones does by default. This applies `SEC-2`. ([Nakama, Configuration: common properties](https://heroiclabs.com/docs/nakama/getting-started/configuration/#common-properties), [Amazon GameLift Servers, Prepare for launch: testing](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift_quickstart_customservers_checklist.html#gamelift_quickstart_customservers_test_checklist), [Security best practices: ports](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/security-best-practices.html#security-best-practices-ports), [Access AWS resources with an IAM role](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift-sdk-server-resources.html#gamelift-sdk-server-resources-roles), [Agones, GameServer Pod service accounts](https://agones.dev/site/docs/advanced/service-accounts/))
- `8` `GAMESERVER-13` **Admit to a match only the players the matchmaker placed in it: the client presents its player session or ticket, and the server validates it before accepting the connection.** Use GameLift's `AcceptPlayerSession()`, Unreal's `PreLogin`, Netcode for GameObjects' connection approval or Godot's `SceneMultiplayer` authentication callback; Netcode for GameObjects doesn't encrypt connection approval data, so don't send tokens in it without an encrypted transport. This applies `SEC-1` and `SEC-7`; on Steam, also verify the player's session ticket (`STEAM-5`). ([Amazon GameLift Servers, Validate a new player](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift-sdk-server-api.html#gamelift-sdk-server-validateplayer), [Unreal Engine, Game Mode and Game State](https://dev.epicgames.com/documentation/en-us/unreal-engine/game-mode-and-game-state-in-unreal-engine), [Netcode for GameObjects, Connection approval](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@3.1/manual/basics/connection-approval.html), [Godot, High-level multiplayer: authentication](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html#authentication))
- `8` `GAMESERVER-14` **Keep player inventories, currencies, progression and scores in data that only server code can write.** In Nakama, write such storage objects from the server runtime with *No Write* permission for clients, keep currencies in wallets, which only runtime code can change, and create leaderboards as authoritative, because by default clients can submit scores; verify store purchases on the server, as `MOBGAME-1` asks. This applies `SEC-1` and `GAMEDEV-5`, and `STEAM-8` does the same for Steam stats and leaderboards. ([Nakama, Access controls: object permissions](https://heroiclabs.com/docs/nakama/concepts/storage/permissions/#object-permissions), [User accounts: virtual wallet](https://heroiclabs.com/docs/nakama/concepts/user-accounts/#virtual-wallet), [Leaderboards: authoritative leaderboards](https://heroiclabs.com/docs/nakama/concepts/leaderboards/#authoritative-leaderboards), [In-app purchase validation](https://heroiclabs.com/docs/nakama/concepts/iap-validation/))
- `7` `GAMESERVER-15` **Rate-limit each player's actions and traffic, and protect game servers from DDoS attacks, for example with a relay that hides their IP addresses.** Limit frequent actions in server code and backend APIs, and the number of game sessions one player can create, such as with GameLift's `ResourceCreationLimitPolicy`; GameLift's player gateway relays player traffic, rate-limits each player and admits only traffic with a valid player token. This applies `API-11`. ([Godot, High-level multiplayer: secure multiplayer design](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html#secure-multiplayer-design), [OWASP API Security Top 10, API4:2023 Unrestricted Resource Consumption](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/), [Amazon GameLift Servers, CreateFleet: ResourceCreationLimitPolicy](https://docs.aws.amazon.com/gameliftservers/latest/apireference/API_CreateFleet.html#API_CreateFleet_RequestParameters), [DDoS protection with Amazon GameLift Servers](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/ddos-protection-intro.html), [Player gateway](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/ddos-protection-player-gateway.html), [Edgegap, DDoS protection](https://docs.edgegap.com/docs/ddos-protection))

### Observability

- `7` `GAMESERVER-16` **Record tick time and achieved tick rate for every game server, along with players, active sessions and crashed or abnormally terminated sessions, and alert on severe problems such as ticks that overrun their budget.** Export them like other metrics (`OPS-11`), and keep match and player IDs off metric attributes (`OTEL-6`). ([Amazon GameLift Servers, Telemetry metrics: available metrics](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift-servers-metrics-types.html), [Monitor with Amazon CloudWatch](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/monitoring-cloudwatch.html), [Agones, Metrics](https://agones.dev/site/docs/guides/metrics/), [Prepare for launch](https://docs.aws.amazon.com/gameliftservers/latest/developerguide/gamelift_quickstart_customservers_checklist.html))
