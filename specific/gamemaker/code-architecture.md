# GameMaker: code architecture

How to structure objects, events and GML code so that the game stays easy to change: instances and event order, global state, functions, structs and types, async events, state machines, UI and multiplayer. Engine-independent patterns, such as components, fixed time steps and authoritative servers, are in [Game development](../gamedev/README.md).

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

- `8` [Game Programming Patterns](https://gameprogrammingpatterns.com/contents.html) (Robert Nystrom): engine-independent, free online, and the background to the state machine and component rules.
- `7` [GML Code Overview](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/GML_Overview.htm) (GameMaker Manual): variables and scope, script functions and methods, structs and constructors, and evaluation order.
- `7` [Object Events](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Object_Properties/Object_Events.htm) and [Event Order](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Object_Properties/Event_Order.htm) (GameMaker Manual): what each event is for, and which orders GameMaker guarantees.

## Key rules

### Objects, events and instances

- `8` `GAMEMAKER-CODE-1` **Don't rely on the order in which instances run the same event, or on the order in which a room creates its instances.** GameMaker guarantees only the order of the events, such as Begin Step, then Step, then End Step, so move code that must follow another instance's Step event into End Step. A room creates its instances one at a time in its instance creation order, so a `with` in a Create event runs for none of the instances that don't exist yet. ([GameMaker Manual, Event Order](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Object_Properties/Event_Order.htm), [with](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Language_Features/with.htm), [Room Properties: instance creation order](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Room_Properties/Room_Properties.htm#creation_order))
- `7` `GAMEMAKER-CODE-2` **Declare every instance variable in the Create event, or as an Object Variable, and use `var` for values that only one event needs.** Otherwise an event that runs before the one that first sets the variable, such as Begin Step before Step, fails when it reads it. Feather reports this as `GM2016`. ([GameMaker Manual, Feather Messages: GM2016](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Code_Editor_Properties/Feather_Messages.htm#gm2016))
- `7` `GAMEMAKER-CODE-5` **Keep game-wide state in a few known places: declare every global variable in one script function or one controller object at the start of the game, always with the `global.` prefix, and define all macros in a dedicated script asset.** Global variables last until the game ends and are easy to confuse with instance variables of the same name, and `globalvar` is deprecated. Macros can't change at run time, but can take a different value in each configuration. ([GameMaker Manual, Global Variables](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Variables/Global_Variables.htm), [Constants](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Variables/Constants.htm))
- `6` `GAMEMAKER-CODE-3` **Refer to a particular instance through its instance ID, and use the object name only in code meant for all its instances.** When several instances exist, `obj_enemy.hp` reads the first one created, which may change, while `with (obj_enemy)` and functions such as `instance_destroy(obj_enemy)` act on every instance of the object and of its children. ([GameMaker Manual, Objects vs. Instances](https://manual.gamemaker.io/lts/en/Additional_Information/Objects_vs_Instances.htm), [with](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Language_Features/with.htm))
- `6` `GAMEMAKER-CODE-4` **Put behaviour that a family of objects shares in a parent object that is never placed in a room itself, and call `event_inherited()` in a child's event when the parent's code for that event should also run.** A child event without that call replaces the parent's. Keep hierarchies shallow and compose the rest (`GAMEDEV-2`). ([GameMaker Manual, Parent Objects](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Object_Properties/Parent_Objects.htm), [Game development: components](../gamedev/README.md))
- `6` `GAMEMAKER-CODE-6` **Make an object persistent only if its instance must outlive the room, such as a game manager or the player, and create that instance exactly once.** A persistent instance runs its Create event only once and goes on into every following room until you destroy it, and one that is still deactivated when the room changes is lost. ([GameMaker Manual, The Object Editor: persistent](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Objects.htm))

### Functions, structs and types

- `7` `GAMEMAKER-CODE-7` **Define global functions in script assets with `function name() {}`, and functions inside objects and constructors as method variables, `name = function() {}`, so that children can override them.** The compiler optimises calls to script functions, so a script function that a child object defines doesn't override its parent's. To call a script function through a variable every step, convert it once with `method(undefined, fn)`, because each indirect call otherwise creates a new method. ([GameMaker Manual, Script Functions vs. Methods](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Script_Functions_vs_Methods.htm), [Script Functions And Variables](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Script_Functions.htm))
- `7` `GAMEMAKER-CODE-8` **Use constructors and structs, not object instances, for data and logic that need no events, drawing or collisions, such as stats, inventories or states, and declare their methods `static` so that all structs from a constructor share one copy.** Structs have no processing overhead after they're created and are garbage-collected, but their methods run only when your code calls them. ([GameMaker Manual, Structs & Constructors compared with objects](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Structs.htm#constructors_structs_vs_objects_instances), [Static Variables](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Functions/Static_Variables.htm), [Garbage Collection](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Reference/Garbage_Collection/Garbage_Collection.htm))
- `6` `GAMEMAKER-CODE-9` **Don't depend on the order in which function arguments or parts of an expression are evaluated: call functions with side effects, such as `buffer_read`, in separate statements, and use brackets in expressions.** The order differs between targets, for example between Windows and HTML5. Feather reports several function calls in one argument list as `GM2023`. ([GameMaker Manual, Evaluation Order](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Evaluation_Order.htm), [Feather Messages: GM2023](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Code_Editor_Properties/Feather_Messages.htm#gm2023))
- `6` `GAMEMAKER-CODE-10` **Document script functions and constructors with JSDoc comments that give the types of `@param` and `@return`, and let Feather check types.** Feather uses the comments for code completion and to check calls, and Strict Type mode makes the checks stricter. ([GameMaker Manual, JSDoc Comments](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Code_Editor_Properties/JSDoc_Script_Comments.htm), [Feather Data Types](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Code_Editor_Properties/Feather_Data_Types.htm), [Feather Preferences](https://manual.gamemaker.io/lts/en/Setting_Up_And_Version_Information/IDE_Preferences/Feather_Settings.htm))

### Async, state, UI and multiplayer

- `7` `GAMEMAKER-CODE-11` **Use the asynchronous versions of slow operations, such as HTTP requests, file loading and adding sprites, and in the Async event check that `async_load[? "id"]` matches the request ID you stored.** Async events run in every instance that has them, and `async_load` is valid only inside the event. ([GameMaker Manual, Async Events](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Object_Properties/Async_Events.htm), [http_get](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Reference/Asynchronous_Functions/HTTP/http_get.htm))
- `5` `GAMEMAKER-CODE-12` **Model objects with distinct modes, such as enemies, the player or menu buttons, as finite state machines: one state variable, states named by an enum, and the state code that a family shares in its parent object.** When states grow complex, make each state a struct with its own methods (the State pattern). This applies `GAMEDEV-21`. ([GameMaker, Finite State Machines (GML)](https://gamemaker.io/en/tutorials/coffee-break-tutorials-finite-state-machines-gml), [Nystrom, State](https://gameprogrammingpatterns.com/state.html))
- `5` `GAMEMAKER-CODE-13` **Build menus and the HUD in UI layers, with Flex Panels so that the layout adapts to the display, and place the objects that handle their input in those layers.** UI layers are shared by every room and draw on the GUI layer or a viewport, where cameras don't move them, and Mouse events and `mouse_x` and `mouse_y` of objects on them use UI coordinates. ([GameMaker Manual, UI Layers](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Room_Properties/UI_Layers.htm), [UI Layers At Runtime](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Room_Properties/UI_Layers_At_Runtime.htm))
- `5` `GAMEMAKER-CODE-14` **Choose the multiplayer approach before building gameplay: Rollback Multiplayer plays online only on the GX.games target and shares only input, so every client must run the same logic, and for other platforms use the Photon extension or your own server with the networking functions.** This applies `GAMEDEV-5` and `GAMEDEV-9`. ([GameMaker Manual, Rollback Multiplayer](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Reference/Rollback/Rollback_Multiplayer.htm), [Rollback System](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Reference/Rollback/Rollback_System.htm), [Networking](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Reference/Networking/Networking.htm), [YoYo Games, GMEXT-Photon](https://github.com/YoYoGames/GMEXT-Photon/blob/main/README.md))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [Feather messages](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Code_Editor_Properties/Feather_Messages.htm): the code editor reports `GM2016` for instance variables declared outside the Create event, `GM2023` for several function calls in one argument list, and `GM2040` for `event_inherited()` in an object whose parent has no such event. Set each message's severity in the Feather Preferences. [Feather directives with a path](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Code_Editor_Properties/Feather_Directives.htm#path), kept in a script such as `FeatherConfig`, set the profile and turn messages off or back on for the whole project, and are committed with it. Checks `GAMEMAKER-CODE-2`, and partly `GAMEMAKER-CODE-4` and `GAMEMAKER-CODE-9`.
- `7` [Feather type checking](https://manual.gamemaker.io/lts/en/Setting_Up_And_Version_Information/IDE_Preferences/Feather_Settings.htm): the TypeErrors profile and Strict Type mode check calls and assignments against the types in JSDoc comments, and a directive with a path, such as `// Feather use type-errors in /*`, sets the profile for the whole project. Partly checks `GAMEMAKER-CODE-10`.
