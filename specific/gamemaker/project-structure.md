# GameMaker: project structure

Version control, asset naming and the Asset Browser, release channels and versions, configurations, command-line builds, and sharing code between projects. Version control for large binary assets in any engine is in [Game development](../gamedev/README.md), and keeping secrets out of repositories is in [Security](../../general/security.md).

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Key rules

### Version control

- `9` `GAMEMAKER-STRUCT-1` **Keep every project in source control from the first day, and keep the `.gitignore` and `.gitattributes` files that GameMaker adds to new and imported projects.** YoYo Games strongly recommends source control for every project. The default files ignore the user-specific `.resource_order` file and force LF line endings for project metadata, so that merges work across Windows, macOS and Linux. This is how GameMaker projects apply `GAMEDEV-22`; choosing Git LFS or Perforce for large assets is `GAMEDEV-15`. ([GameMaker, Setting Up And Using Source Control](https://gamemaker.io/en/help/articles/setting-up-and-using-source-control), [GameMaker Manual, Project Format](https://manual.gamemaker.io/lts/en/Additional_Information/Project_Format.htm), [Plugin Preferences](https://manual.gamemaker.io/lts/en/Setting_Up_And_Version_Information/IDE_Preferences/Plugin_Preferences.htm))
- `7` `GAMEMAKER-STRUCT-2` **Save and close the project in GameMaker before you pull, merge, switch branches or revert with an external Git client, and if GameMaker reports changed files while the project is open, choose Reload, not Save.** External Git operations can change the main `.yyp` file under the open IDE, and Save writes the IDE's copy over them. Change `.yy` and `.yyp` files through the IDE or `gm-cli resourcetool`, not by hand: YoYo Games' own guidance for AI agents calls them very hard to edit correctly. ([GameMaker, Setting Up And Using Source Control](https://gamemaker.io/en/help/articles/setting-up-and-using-source-control), [GameMaker Manual, The File Watcher](https://manual.gamemaker.io/lts/en/IDE_Tools/The_File_Watcher.htm), [Conflicts](https://manual.gamemaker.io/lts/en/IDE_Tools/Source_Control/Conflicts.htm), [YoYo Games, gm-cli agent guidance](https://github.com/YoYoGames/gm-cli/blob/main/src/commands/init/claude-contents.txt))

### Assets and naming

- `6` `GAMEMAKER-STRUCT-3` **Name every asset with a prefix for its type, such as `spr_`, `obj_`, `snd_` and `ts_`, agree on one way to group the Asset Browser, by asset type or by level, and set matching Feather naming rules.** An asset's name is the identifier your code uses for it, and may contain only letters, digits and underscores. Feather checks names against the naming rules once you turn on its `GM2017` message, which is off by default. ([GameMaker Manual, Creating Sprites](https://manual.gamemaker.io/lts/en/Quick_Start_Guide/Creating_Sprites.htm), [Objects And Instances](https://manual.gamemaker.io/lts/en/Quick_Start_Guide/Objects_And_Instances.htm), [The Asset Browser](https://manual.gamemaker.io/lts/en/Introduction/The_Asset_Browser.htm), [Feather Preferences: naming rules](https://manual.gamemaker.io/lts/en/Setting_Up_And_Version_Information/IDE_Preferences/Feather_Settings.htm#s4), [YoYo Games, gm-cli agent guidance](https://github.com/YoYoGames/gm-cli/blob/main/src/commands/init/claude-contents.txt))

### Versions and builds

- `7` `GAMEMAKER-STRUCT-4` **Develop on the LTS release, use one IDE and runtime version across the team and the build machines, and upgrade everyone together, after committing, when you choose to.** Opening a project in a newer release can raise its project format, after which older versions open it only read-only, and the change can't be reverted. Beta releases can corrupt or lock project files, and YoYo Games asks you to back up or commit before bringing a project into a new LTS release. ([GameMaker, What To Do If GameMaker Says Your Project Is Read-Only](https://gamemaker.io/en/help/articles/what-to-do-if-gamemaker-says-your-project-is-read-only), [Download GameMaker](https://gamemaker.io/en/download), [GameMaker LTS 2026.0](https://gamemaker.io/en/blog/lts-2026-release), [GameMaker Manual, Installation Guide](https://manual.gamemaker.io/lts/en/Setting_Up_And_Version_Information/Installation_Guide.htm), [Runtime Feeds Preferences](https://manual.gamemaker.io/lts/en/Setting_Up_And_Version_Information/IDE_Preferences/Runtime_Feed_Preferences.htm))
- `6` `GAMEMAKER-STRUCT-5` **Compile every pull request in CI, with `gm-cli compile` or with Igor on your own build machine, and pin both the `gm-cli` version and the runtime version, which `gm-options.json` records in its `toolchain` field.** `gm-cli init` can generate the GitHub Actions workflow; keep the GameMaker access key it uses in a CI secret (`SEC-2`). Without a pinned runtime, `gm-cli` downloads the newest one: its 2.0 release moved every unpinned project to LTS 2026. ([YoYo Games, gm-cli README](https://github.com/YoYoGames/gm-cli/blob/main/README.md), [gm-cli compile workflow template](https://github.com/YoYoGames/gm-cli/blob/main/src/commands/init/compile.yml), [gm-cli changelog](https://github.com/YoYoGames/gm-cli/blob/main/CHANGELOG.md), [GameMaker Manual, Building & Testing via Command Line](https://manual.gamemaker.io/lts/en/Settings/Building_via_Command_Line.htm))
- `5` `GAMEMAKER-STRUCT-6` **Use configurations for what differs between builds of the same game, such as platforms, stores or a demo, and select the configuration in every build.** Each configuration can have its own game options, texture and audio group exports, included files and macro values; Igor takes it as `/config` and `gm-cli` as `--config`. ([GameMaker Manual, Configurations](https://manual.gamemaker.io/lts/en/Settings/Configurations.htm), [Constants: configuration override](https://manual.gamemaker.io/lts/en/GameMaker_Language/GML_Overview/Variables/Constants.htm), [Building & Testing via Command Line](https://manual.gamemaker.io/lts/en/Settings/Building_via_Command_Line.htm), [gm-cli changelog](https://github.com/YoYoGames/gm-cli/blob/main/CHANGELOG.md))

### Sharing code

- `4` `GAMEMAKER-STRUCT-7` **Share scripts and assets that several projects use as a Local Asset Package (`.yymps`) with a Package ID and version number, and update a project by importing the new version.** Importing copies the assets into the project. The Prefab Library, which references assets from a collection instead, currently offers only YoYo Games' asset bundles; a Prefab Builder for your own collections is on the LTS 2026 roadmap. ([GameMaker Manual, Local Asset Packages](https://manual.gamemaker.io/lts/en/IDE_Tools/Local_Asset_Packages.htm), [Prefab Library](https://manual.gamemaker.io/lts/en/IDE_Tools/Prefab_Library.htm), [GameMaker Update Spring 2026](https://gamemaker.io/en/blog/update-spring-2026))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [Feather naming rules](https://manual.gamemaker.io/lts/en/Setting_Up_And_Version_Information/IDE_Preferences/Feather_Settings.htm#s4): with the [`GM2017`](https://manual.gamemaker.io/lts/en/The_Asset_Editors/Code_Editor_Properties/Feather_Messages.htm#gm2017) message turned on, Feather flags asset, variable, function, macro and enum names that break the naming style, prefix or suffix you set, and new assets get names that follow the rules. Partly checks `GAMEMAKER-STRUCT-3`.
- `6` [gm-cli compile workflow](https://github.com/YoYoGames/gm-cli/blob/main/src/commands/init/compile.yml): the GitHub Actions workflow that `gm-cli init` generates test-compiles the game on every pull request and every push to `main`. Partly checks `GAMEMAKER-STRUCT-5`.
