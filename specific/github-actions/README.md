# GitHub Actions (CI/CD automation)

Scope: designing CI/CD and automation workflows on GitHub Actions, including reusable workflows, custom actions and deployments. Workflows run with access to your code, secrets and cloud accounts, so most rules here are about keeping them secure. For general supply-chain rules, see [Security](../../general/security.md).

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

- `9` [Secure use reference](https://docs.github.com/en/actions/reference/security/secure-use) (GitHub Docs): **the baseline for workflow security**: third-party actions, script injection, `GITHUB_TOKEN` permissions, OIDC, self-hosted runners and CODEOWNERS.
- `7` [Securely using `pull_request_target`](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target) (GitHub Docs): when to use the privileged pull request trigger, and how to harden it.
- `7` [OpenID Connect](https://docs.github.com/en/actions/concepts/security/openid-connect) (GitHub Docs): short-lived cloud credentials instead of stored secrets, with [setup guides per cloud provider](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-cloud-providers).
- `7` [Reusing workflow configurations](https://docs.github.com/en/actions/concepts/workflows-and-actions/reusing-workflow-configurations) (GitHub Docs): reusable workflows, composite actions and workflow templates, and when to use each.
- `7` [Deployment environments](https://docs.github.com/en/actions/concepts/workflows-and-actions/deployment-environments) (GitHub Docs): approvals, branch restrictions and environment secrets for deployment jobs.

## Key rules

### Security

- `9` `GHA-1` **Set the `GITHUB_TOKEN` to read-only at the top of each workflow, and grant write permissions only to the jobs that need them.** ([GitHub, Secure use reference](https://docs.github.com/en/actions/reference/security/secure-use), [GitHub, Use GITHUB_TOKEN for authentication](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token))
- `9` `GHA-2` **Pin third-party actions and reusable workflows to a full-length commit SHA, or lock them with a workflow dependency lockfile.** Tags and branches can be moved to malicious code. Lockfiles are in public preview and also cover transitive dependencies. ([GitHub, Using third-party actions](https://docs.github.com/en/actions/reference/security/secure-use#using-third-party-actions), [GitHub, Workflow dependency lockfiles](https://docs.github.com/en/actions/concepts/security/workflow-dependency-lockfiles))
- `9` `GHA-3` **Never expand untrusted input, such as `${{ github.event.pull_request.title }}`, directly in a `run:` script. Pass it through an intermediate environment variable.** ([GitHub, Script injections](https://docs.github.com/en/actions/concepts/security/script-injections), [GitHub, Secure use reference](https://docs.github.com/en/actions/reference/security/secure-use))
- `8` `GHA-4` **Use `pull_request` rather than `pull_request_target` unless fork pull requests need secrets or write access, and never execute pull request code in a `pull_request_target` or `workflow_run` workflow.** ([GitHub, Securely using pull_request_target](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target), [GitHub Security Lab, Preventing pwn requests](https://securitylab.github.com/resources/github-actions-preventing-pwn-requests/))
- `8` `GHA-5` **Authenticate to cloud providers with OpenID Connect instead of long-lived cloud secrets, and restrict the trust policy to specific repositories, branches or environments.** Define at least one condition so that untrusted repositories can't request access tokens. ([GitHub, OpenID Connect](https://docs.github.com/en/actions/concepts/security/openid-connect), [GitHub, OpenID Connect reference](https://docs.github.com/en/actions/reference/security/oidc))
- `7` `GHA-6` **Avoid self-hosted runners in public repositories. Where you use them, prefer ephemeral just-in-time runners.** A runner that keeps state between jobs can be persistently compromised by untrusted code. ([GitHub, Hardening for self-hosted runners](https://docs.github.com/en/actions/reference/security/secure-use#hardening-for-self-hosted-runners))
- `7` `GHA-7` **Enable Dependabot version updates for the `github-actions` ecosystem.** Dependabot also updates SHA-pinned actions and their version comments. ([GitHub, Keeping your actions up to date with Dependabot](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/secure-your-dependencies/auto-update-actions), [GitHub, Dependabot support for GitHub Actions](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories#github-actions))
- `6` `GHA-8` **Treat restored caches as untrusted input: never cache secrets, and write caches only from workflows with trusted triggers.** ([GitHub, Dependency caching: cache security](https://docs.github.com/en/actions/concepts/workflows-and-actions/dependency-caching), [GitHub, Dependency caching reference](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching))
- `6` `GHA-9` **Require approval from designated code owners for changes to `.github/workflows`.** ([GitHub, Using CODEOWNERS to monitor changes](https://docs.github.com/en/actions/reference/security/secure-use#using-codeowners-to-monitor-changes))
- `5` `GHA-10` **Pass secrets to reusable workflows by name instead of with `secrets: inherit`.** The called workflow then gets only the secrets it needs. ([zizmor, secrets-inherit](https://docs.zizmor.sh/audits/#secrets-inherit), [GitHub, Reuse workflows](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows))

### Reuse and deployment

- `7` `GHA-11` **Deploy through environments with protection rules: required reviewers, allowed deployment branches, and secrets scoped to the environment.** On GitHub Free, Pro and Team plans, required reviewers work only in public repositories. ([GitHub, Deployment environments](https://docs.github.com/en/actions/concepts/workflows-and-actions/deployment-environments), [GitHub, Deployments and environments reference](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments))
- `6` `GHA-12` **Share CI logic through reusable workflows (whole jobs) and composite actions (steps) instead of copying YAML between workflows and repositories.** ([GitHub, Reusing workflow configurations](https://docs.github.com/en/actions/concepts/workflows-and-actions/reusing-workflow-configurations))
- `6` `GHA-13` **Use concurrency groups to cancel superseded runs on the same branch and to stop deployments to the same environment from running at once.** ([GitHub, Concurrency](https://docs.github.com/en/actions/concepts/workflows-and-actions/concurrency), [GitHub, Control the concurrency of workflows and jobs](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [GitHub Actions repository settings](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository): the policy "Require actions to be pinned to a full-length commit SHA" blocks unpinned actions (reusable workflows can still use tags), and the restricted "Workflow permissions" setting makes the `GITHUB_TOKEN` read-only by default. Partly checks `GHA-1` and `GHA-2`.
- `6` [CodeQL queries for GitHub Actions](https://codeql.github.com/codeql-query-help/actions/): code scanning that finds [code injection](https://codeql.github.com/codeql-query-help/actions/actions-code-injection-critical/), [checkout of untrusted code in a privileged context](https://codeql.github.com/codeql-query-help/actions/actions-untrusted-checkout-critical/), cache poisoning, [workflows without `permissions`](https://codeql.github.com/codeql-query-help/actions/actions-missing-workflow-permissions/) and, in the extended suite, [unpinned tags](https://codeql.github.com/codeql-query-help/actions/actions-unpinned-tag/). Checks `GHA-3`, and partly `GHA-1`, `GHA-2`, `GHA-4` and `GHA-8`.
- `6` [zizmor audit rules](https://docs.zizmor.sh/audits/): a static analyser for workflows. Its default audits include `unpinned-uses` (since v1.20 it requires SHA pins for all actions), `excessive-permissions`, `template-injection`, `dangerous-triggers`, `cache-poisoning` and `secrets-inherit`. `self-hosted-runner` (auditor persona) and `concurrency-limits` (pedantic persona) are opt-in. Checks `GHA-1`, `GHA-2`, `GHA-3`, `GHA-4` and `GHA-10`, and partly `GHA-6`, `GHA-8` and `GHA-13`.
- `6` [OpenSSF Scorecard checks](https://github.com/ossf/scorecard/blob/main/docs/checks.md): [Token-Permissions](https://github.com/ossf/scorecard/blob/main/docs/checks.md#token-permissions) looks for read-only top-level permissions, [Pinned-Dependencies](https://github.com/ossf/scorecard/blob/main/docs/checks.md#pinned-dependencies) for actions pinned by hash, and [Dangerous-Workflow](https://github.com/ossf/scorecard/blob/main/docs/checks.md#dangerous-workflow) for untrusted checkouts and script injection. Dependency-Update-Tool only checks that Dependabot or Renovate is enabled. Checks `GHA-1` and `GHA-2`, and partly `GHA-3`, `GHA-4` and `GHA-7`.
- `6` [actionlint checks](https://github.com/rhysd/actionlint/blob/main/docs/checks.md#untrusted-inputs): a workflow linter for CI and editors that flags script injection through untrusted inputs, besides syntax, expression and `shellcheck` errors. Checks `GHA-3`.
- `5` [Dependabot alerts for actions](https://docs.github.com/en/actions/reference/security/secure-use#monitoring-the-actions-in-your-workflows): alert you when an action your workflows use has a reported vulnerability. Partly checks `GHA-7`.
