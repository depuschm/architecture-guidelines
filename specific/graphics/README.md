# Graphics and GPU rendering

Scope: engine-independent GPU rendering and shaders for games and other real-time 3D applications, on native platforms and on the web with WebGL and WebGPU. Engine-specific rendering rules are in [Unity: rendering and shaders](../unity/rendering.md), [Godot: rendering and shaders](../godot/rendering.md), [Unreal Engine: rendering and shaders](../unreal/rendering.md) and [GameMaker: rendering and shaders](../gamemaker/rendering.md). Frame-time budgets (`GAMEDEV-12`) and other engine-independent game rules are in [Game development](../gamedev/README.md), and store, thermal and download-size rules for phones are in [Mobile games](../mobile-games/README.md).

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

No single guide covers every GPU. Use the guide for each GPU family you target as its baseline; much of each vendor's advice applies to the others too.

- `8` [Arm GPU Best Practices Developer Guide](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695) (Arm, issue 10, January 2025, PDF): **the baseline for Arm Mali and Immortalis GPUs**: the optimisation process and budgets, draw calls, render passes on tile-based GPUs, shader precision, textures and compute.
- `8` [Adreno GPU on Mobile: Best Practices](https://docs.qualcomm.com/doc/80-78185-2/topic/mobile_best_practices.html) (Qualcomm): **the baseline for Qualcomm Adreno GPUs**: renderer architecture, render passes and tile memory, depth testing, textures and shaders.
- `8` [WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices) (MDN): **the baseline for WebGL**: errors and limits, blocking calls, video memory budgets, batching, parallel shader compilation, precision, mipmaps and compressed textures.
- `7` [Analyze and optimize game performance](https://developer.android.com/games/optimize/gameperformance) and [CPU and GPU optimization tips](https://developer.android.com/games/optimize/optimization-tips) (Android Developers): finding CPU and GPU bottlenecks on Android devices, and fixing common GPU problems with RenderDoc and Android GPU Inspector.
- `7` [Tailor your apps for Apple GPUs and tile-based deferred rendering](https://developer.apple.com/documentation/metal/tailor-your-apps-for-apple-gpus-and-tile-based-deferred-rendering) and [Optimizing GPU performance](https://developer.apple.com/documentation/xcode/optimizing-gpu-performance) (Apple): how Apple GPUs render, and how to find GPU bottlenecks with the Metal debugger.
- `7` [RDNA Performance Guide](https://gpuopen.com/learn/rdna-performance-guide/) (AMD GPUOpen, 2023): **the baseline for AMD Radeon GPUs** with Direct3D 12 and Vulkan: command buffers, pipeline state objects, barriers, memory and shaders.
- `7` [Advanced API Performance tips](https://developer.nvidia.com/blog/tag/advanced-api-performance/) (NVIDIA Technical Blog): short lists of what to do and avoid on NVIDIA GPUs with Direct3D 12 and Vulkan, one post per topic.
- `7` [WebGPU API](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API) (MDN) and the [WebGPU specification](https://www.w3.org/TR/webgpu/) (W3C): the WebGPU programming model, devices, pipelines, error handling and browser support.

## Key rules

### Choosing the renderer

- `8` `GFX-1` **Choose the graphics API or engine render pipeline, and the oldest hardware you will support, at the start of the project, and record the choice and the options you rejected in an ADR.** Switching later means reworking shaders, materials and lighting; the ADR rules are `ADR-1` and `ADR-3` in [Decisions](../../general/decisions.md). Prefer each platform's current API: Vulkan on Android, where OpenGL ES no longer gets new features, and Metal on Apple platforms, where OpenGL ES is deprecated. ([Unity, Choose a render pipeline](https://docs.unity3d.com/Manual/choose-a-render-pipeline.html), [Godot, Overview of renderers](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html), [Android, Use Vulkan for graphics](https://developer.android.com/games/develop/vulkan/overview), [Apple, OpenGL ES](https://developer.apple.com/documentation/opengles))

### Budgets and bottlenecks

- `7` `GFX-2` **Break each platform's frame-time budget (`GAMEDEV-12`) down into GPU budgets for each device tier: GPU time per frame, shader cycles, triangle counts, and memory for textures, meshes and render targets.** Keep the memory budget below the smallest supported device's limit: iOS terminates apps that exceed a per-device memory limit, and WebGL can't query video memory at all. ([Arm GPU Best Practices, 2.1 Optimization process](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [Apple, Reducing the memory footprint of Metal apps](https://developer.apple.com/documentation/metal/reducing-the-memory-footprint-of-metal-apps), [MDN, Estimate a per-pixel VRAM budget](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#estimate_a_per-pixel_vram_budget))
- `7` `GFX-3` **Before optimising, find out whether the frame is CPU-bound or GPU-bound, and which GPU stage limits it. Measure frame times in milliseconds with vsync off, not frames per second, and measure again after each change, because the bottleneck moves.** Setting the frame-time budget you measure against is `GAMEDEV-12`. ([Android, Identify CPU or GPU bottlenecks](https://developer.android.com/games/optimize/gameperformance#cpu-gpu-bottlenecks), [Arm GPU Best Practices, 2.1 Optimization process](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [Godot, General optimization tips](https://docs.godotengine.org/en/stable/tutorials/performance/general_optimization.html))
- `6` `GFX-4` **Inspect GPU frames with a frame debugger and GPU profiler for each target API: RenderDoc for Vulkan, Direct3D and OpenGL ES, PIX for Direct3D 12, the Metal debugger in Xcode for Apple GPUs, and Android GPU Inspector or the GPU vendor's profiler on Android.** RenderDoc doesn't support Metal or WebGL. ([RenderDoc, FAQ](https://renderdoc.org/docs/getting_started/faq.html), [Microsoft, Get started with PIX](https://learn.microsoft.com/en-us/windows/win32/direct3dtools/pix/articles/general/pix-overview), [Apple, Optimizing GPU performance](https://developer.apple.com/documentation/xcode/optimizing-gpu-performance), [Android GPU Inspector](https://developer.android.com/agi))

### Shaders and pipelines

- `8` `GFX-5` **Don't compile shaders or create pipeline state objects during gameplay. Create them while loading or on background threads, and keep them between runs in a pipeline cache (`VkPipelineCache`, a Direct3D 12 pipeline library) or as precompiled binaries where the platform allows, such as Metal binary archives.** Compiling during a frame causes hitches, and Arm, AMD and NVIDIA all advise against it. In WebGL, compile with `KHR_parallel_shader_compile`. ([Arm GPU Best Practices, 4.1 and 4.2](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [AMD, RDNA Performance Guide](https://gpuopen.com/learn/rdna-performance-guide/), [NVIDIA, Pipeline State Objects](https://developer.nvidia.com/blog/advanced-api-performance-pipeline-state-objects/), [Microsoft, CreatePipelineLibrary](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device1-createpipelinelibrary), [Apple, Metal binary archives](https://developer.apple.com/documentation/metal/metal-binary-archives), [MDN, Prefer KHR_parallel_shader_compile](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#prefer_khr_parallel_shader_compile))
- `7` `GFX-6` **Keep the number of shader variants small and known: count them in every build, strip those no material uses, and use dynamic branching, specialization constants or an ubershader for features that don't need a variant of their own.** Each independent feature switch doubles the variants, and every variant adds build time, memory and loading time. ([Unity, Introduction to shader variants](https://docs.unity3d.com/Manual/shader-variants.html), [AMD, RDNA Performance Guide](https://gpuopen.com/learn/rdna-performance-guide/), [NVIDIA, Pipeline State Objects](https://developer.nvidia.com/blog/advanced-api-performance-pipeline-state-objects/), [Godot, Reducing stutter from shader compilations](https://docs.godotengine.org/en/stable/tutorials/performance/pipeline_compilations.html))
- `7` `GFX-7` **Compile every shader for every target API offline, in CI, and validate the output, so that a shader that fails on one platform breaks the build rather than the game.** Khronos recommends that every tool that produces SPIR-V checks it with the validator, and DXC validates the DXIL it emits. ([Arm GPU Best Practices, 2.2 Basic optimization checklist](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [Khronos, SPIRV-Tools validator](https://github.com/KhronosGroup/SPIRV-Tools/blob/main/README.md), [Microsoft, DirectX Shader Compiler](https://github.com/microsoft/DirectXShaderCompiler/blob/main/README.md))
- `7` `GFX-8` **Run development and automated test builds with the graphics API's validation turned on, such as the Vulkan validation layers with Best Practices, the Direct3D 12 debug layer or Metal API Validation, and fix what they report.** Microsoft recommends running with the debug layer most of the time, and GPU-based validation on a few machines in a nightly test pass. ([Microsoft, GPU-based validation and the Direct3D 12 debug layer](https://learn.microsoft.com/en-us/windows/win32/direct3d12/using-d3d12-debug-layer-gpu-based-validation), [Khronos, Best Practices validation](https://github.com/KhronosGroup/Vulkan-ValidationLayers/blob/main/docs/best_practices.md), [Apple, Validating your app's Metal API usage](https://developer.apple.com/documentation/xcode/validating-your-apps-metal-api-usage), [MDN, Address and eliminate WebGL errors](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#address_and_eliminate_webgl_errors))
- `6` `GFX-9` **Use 16-bit precision (`mediump` or explicit 16-bit types) wherever it is accurate enough, especially in fragment shaders on mobile GPUs, and check the results on a mobile GPU, because desktop GPUs usually ignore `mediump`.** On Adreno, 16-bit fragment shaders can be twice as fast and twice as power-efficient. ([Arm GPU Best Practices, 10.1 Minimize precision](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [Qualcomm, Adreno best practices: half-precision](https://docs.qualcomm.com/doc/80-78185-2/topic/mobile_best_practices.html), [Android, Optimize shader precision](https://developer.android.com/games/optimize/optimization-tips#optimize-shader-precision))

### Draw calls and overdraw

- `7` `GFX-10` **Cut draw calls and state changes: cull objects outside the view on the CPU, batch or instance objects that share a material, and sort draws by pipeline state.** Arm suggests fewer than about 500 draw calls per frame with OpenGL ES and 1,000 with Vulkan on its current GPUs. ([Arm GPU Best Practices, 3.2 and 3.3](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [AMD, RDNA Performance Guide](https://gpuopen.com/learn/rdna-performance-guide/), [MDN, Batch draw calls](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#batch_draw_calls))
- `6` `GFX-11` **Draw opaque geometry front to back and transparent geometry back to front, and avoid `discard` and depth writes in fragment shaders where you can, so that early depth testing removes hidden fragments before they are shaded.** ([Arm GPU Best Practices, 3.4 Optimizing the draw call render order](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [Android, Avoid discard to enable Early-Z](https://developer.android.com/games/optimize/optimization-tips#avoid-discard-early-z))

### Tile-based GPUs

- `7` `GFX-12` **On tile-based GPUs, which include most mobile GPUs and Apple silicon, choose every attachment's load and store action deliberately: clear or don't-care on load unless you need the previous contents, and don't-care on store for attachments you don't read later, such as depth and multisampled color, which can then be transient or memoryless.** Each unneeded load or store copies the attachment between tile memory and main memory. Also merge consecutive passes that render to the same targets. ([Khronos, Vulkan Guide: Tile Based Rendering best practices](https://github.com/KhronosGroup/Vulkan-Guide/blob/main/chapters/tile_based_rendering_best_practices.adoc), [Arm GPU Best Practices, 7.3 Efficient render passes with Vulkan](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [Apple, Setting load and store actions](https://developer.apple.com/documentation/metal/setting-load-and-store-actions), [Qualcomm, Adreno best practices: render pass](https://docs.qualcomm.com/doc/80-78185-2/topic/mobile_best_practices.html), [Android, Minimize load or store operations](https://developer.android.com/games/optimize/optimization-tips#minimize-operations))

### Assets

- `7` `GFX-13` **Ship textures in GPU-compressed formats, with mipmaps for anything seen in 3D: ASTC, with ETC2 as the fallback, on mobile, BC formats on desktop, and on the web a format each device supports, for example by transcoding Basis Universal at load time.** Compressed textures use less memory and bandwidth, and mipmaps make distant textures both faster and less aliased. ([Arm GPU Best Practices, 8.4 Texture sampling performance](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695), [Android, Textures](https://developer.android.com/games/optimize/textures), [Android, Target texture compression formats in Android App Bundles](https://developer.android.com/guide/playcore/asset-delivery/texture-compression), [Microsoft, Texture block compression in Direct3D 11](https://learn.microsoft.com/en-us/windows/win32/direct3d11/texture-block-compression-in-direct3d-11), [MDN, Consider compressed texture formats](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#consider_compressed_texture_formats), [MDN, Use mipmaps](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#use_mipmaps_for_any_texture_youll_see_in_3d))
- `6` `GFX-14` **Give meshes that move towards and away from the camera levels of detail, with about half the triangles at each level, so that distant objects don't cost more than they show.** ([Android, Geometry: level of detail](https://developer.android.com/games/optimize/geometry#level-of-detail), [Android, Optimize geometry complexity](https://developer.android.com/games/optimize/optimization-tips#optimize-geometry))

### Web

- `6` `GFX-15` **Feature-detect WebGPU and keep a WebGL 2 fallback, or use an engine that has one.** WebGPU works in all major browsers, but not yet on every platform, such as Linux or Firefox on Android, and `requestAdapter()` can return no adapter. ([web.dev, WebGPU is now supported in major browsers](https://web.dev/blog/webgpu-supported-major-browsers#browser_and_os_availability), [MDN, WebGPU API: accessing a device](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API#accessing_a_device))
- `6` `GFX-16` **Handle a lost GPU context: listen for `webglcontextlost` and `webglcontextrestored` in WebGL, and watch `GPUDevice.lost` in WebGPU, and be able to recreate every GPU resource.** Browsers drop contexts when the GPU is reset, switched or overloaded, and MDN advises always handling lost devices. ([MDN, isContextLost(): usage notes](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/isContextLost#usage_notes), [MDN, GPUDevice: lost](https://developer.mozilla.org/en-US/docs/Web/API/GPUDevice/lost))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `6` [Vulkan Best Practices validation](https://github.com/KhronosGroup/Vulkan-ValidationLayers/blob/main/docs/best_practices.md) (Khronos): part of the Khronos validation layer. It checks the app at run time, so turn it on while automated tests render frames. It warns, for example, about pipelines created without a cache, attachments loaded with `LOAD_OP_LOAD` or stored needlessly, attachments that should be transient, many small draw calls, and the same pipeline bound twice in a command buffer. Some checks run only when the vendor-specific checks for Arm, AMD, NVIDIA or Imagination GPUs are turned on. Partly checks `GFX-5`, `GFX-10` and `GFX-12`.
- `6` [glslang](https://github.com/KhronosGroup/glslang/blob/main/README.md) and [`spirv-val`](https://github.com/KhronosGroup/SPIRV-Tools/blob/main/README.md) (Khronos): the reference GLSL and ESSL compiler and the SPIR-V validator. Run them on every shader in CI. Checks `GFX-7` for GLSL, ESSL and SPIR-V.
- `6` [DirectX Shader Compiler](https://github.com/microsoft/DirectXShaderCompiler/blob/main/README.md) (Microsoft): compiles HLSL to validated DXIL for Direct3D 12, or to SPIR-V for Vulkan. Run `dxc` on every shader and variant in CI. glslang's HLSL front end was deprecated in April 2026. Checks `GFX-7` for HLSL.
- `5` [naga](https://github.com/gfx-rs/wgpu/blob/trunk/naga/README.md) (wgpu): `naga shader.wgsl` validates a WGSL shader, and it can also translate shaders between WGSL, SPIR-V, GLSL, HLSL and MSL. Checks `GFX-7` for WGSL.
- `5` [Mali Offline Compiler](https://learn.arm.com/learning-paths/mobile-graphics-and-gaming/ams/malioc/) (Arm): estimates each shader's cycle cost on a chosen Mali GPU, and reports register use and the share of 16-bit arithmetic. With [`--format json`](https://documentation-service.arm.com/static/674866c827eda361ad4dc590), a CI script can fail shaders that exceed a cycle budget. Partly checks `GFX-2` and `GFX-9`.
