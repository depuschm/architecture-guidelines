# iOS (Swift and SwiftUI)

Scope: native iPhone and iPad apps written in Swift with SwiftUI, in the Swift 6 language mode. The App Store has required Xcode 26 and the iOS 26 SDK since 28 April 2026 (`MOBGAME-5`), and the current release is Xcode 27, with Swift 6.4 and the iOS 27 SDK. Most rules also apply to UIKit code and to Apple's other platforms. Store requirements, privacy declarations and purchases for games are in [Mobile games](../mobile-games/README.md). Keeping secrets out of app builds (`SEC-11`) and encrypting every connection (`SEC-13`) are in [Security](../../general/security.md), third-party SDKs and personal data in [Privacy and personal data](../../general/privacy.md), and sign-in in [Authentication and sessions](../../general/authentication.md). Cross-platform apps are covered in [React Native and Expo](../react-native/README.md) and [Flutter](../flutter/README.md).

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

Apple publishes no single architecture guide for iOS apps. Use the framework documentation and the Swift guides below as the baseline, and the key rules for the decisions they leave open.

- `9` [SwiftUI](https://developer.apple.com/documentation/swiftui) (Apple Developer Documentation), with [Model data](https://developer.apple.com/documentation/swiftui/model-data) and [Managing model data in your app](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app): **the baseline for app structure, views and data flow**: scenes, state, bindings, Observation and the environment.
- `9` [OWASP Mobile Application Security Verification Standard (MASVS)](https://mas.owasp.org/MASVS/): the security requirements for mobile apps: storage, cryptography, authentication, network communication, platform interaction, code quality, resilience and privacy. The [OWASP MASTG](https://mas.owasp.org/MASTG/) describes how to test each of them on iOS.
- `8` [Concurrency](https://docs.swift.org/latest/documentation/the-swift-programming-language/concurrency/) (The Swift Programming Language): asynchronous functions, tasks and task groups, isolation, the main actor, actors and `Sendable` types. The [Swift 6 concurrency migration guide](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/dataracesafety/) explains data-race safety and how to adopt it in existing code.
- `8` [Swift API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/) (Swift.org): naming and API conventions, led by clarity at the point of use, that make your code read like the standard library.
- `8` [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) (Apple): the design guidance for Apple platforms. For architecture decisions, read [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), which asks for larger text sizes, VoiceOver descriptions and support for other assistive technologies.
- `7` [Security](https://developer.apple.com/documentation/security) (Apple Developer Documentation) and the [Apple Platform Security](https://support.apple.com/guide/security/welcome/web) guide: the Keychain, certificate, trust and cryptography APIs, and how the platform protects data on the device, including Data Protection classes.
- `7` [SwiftData](https://developer.apple.com/documentation/swiftdata) (Apple Developer Documentation): persistence for Swift model classes, with schema versions and migrations, concurrency and syncing. The [Backyard Birds](https://developer.apple.com/documentation/swiftui/backyard-birds-sample) sample app combines it with SwiftUI and Observation.
- `7` [Testing](https://developer.apple.com/documentation/xcode/testing) (Xcode): Swift Testing for unit tests, XCTest with XCUIAutomation for UI tests, test plans, code coverage and the test pyramid.

## Key rules

### State and data flow

- `7` `IOS-1` **Make each shared model an `@Observable` class, create it with `@State private var` in the view or `App` that owns it, and pass it down as a plain property, with `@Bindable` where a subview needs bindings, or through `.environment(_:)`.** With Observation, available since iOS 17, a view updates only when a property that its `body` reads changes, and you use `@State` and `@Environment` instead of `ObservableObject`, `@StateObject` and `@EnvironmentObject`. ([Apple, Managing model data in your app](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app), [Migrating from the Observable Object protocol to the Observable macro](https://developer.apple.com/documentation/swiftui/migrating-from-the-observable-object-protocol-to-the-observable-macro))
- `7` `IOS-2` **Keep data and the logic that changes it in model types, not in views, and use `@State` only for state that a view owns: declare it `private` in the highest view that needs it, and pass the value or a binding to subviews.** Separating the data model from the views makes the app more modular and easier to test. Don't do expensive work in a `@State` default value, which SwiftUI creates every time it creates the view; defer it to `.task`. ([Apple, Managing model data in your app](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app), [State](https://developer.apple.com/documentation/swiftui/state))

### Concurrency

- `8` `IOS-3` **Build every target in the Swift 6 language mode, which prevents data races at compile time. Migrate older modules one at a time, for example by setting Strict Concurrency Checking to Complete in the Swift 5 mode first and fixing the warnings.** ([Swift.org, Data race safety](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/dataracesafety/), [Enable data-race safety checking](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/enabledataracesafety/), [Migration strategy](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/migrationstrategy/))
- `7` `IOS-4` **Keep UI code and UI state on the main actor, and add concurrency only where you need it: set Default Actor Isolation to `MainActor` for app targets, run heavy work off the main actor with `@concurrent` functions, and keep other mutable state that tasks share in actors.** The main actor protects the data that the UI shows, and isolating code to the main actor by default reduces false data-race errors in code that runs sequentially. ([The Swift Programming Language, Concurrency](https://docs.swift.org/latest/documentation/the-swift-programming-language/concurrency/), [Xcode, Build settings reference](https://developer.apple.com/documentation/xcode/build-settings-reference), [Swift.org, Swift 6.2 released](https://www.swift.org/blog/swift-6.2-released/), [Apple, Embracing Swift concurrency (WWDC25)](https://developer.apple.com/videos/play/wwdc2025/268/))
- `6` `IOS-5` **Prefer structured concurrency, `async let`, task groups and SwiftUI's `.task` modifier, to unstructured `Task { }`. When you do create a `Task`, keep its handle and cancel it when its work is no longer needed.** Child tasks are cancelled with their parent, and SwiftUI cancels a `.task` when its view goes away, but you are responsible for an unstructured task yourself. ([The Swift Programming Language, Concurrency](https://docs.swift.org/latest/documentation/the-swift-programming-language/concurrency/), [Apple, task(name:priority:file:line:_:)](https://developer.apple.com/documentation/swiftui/view/task%28name:priority:file:line:_:%29))

### Secrets and secure connections

- `9` `IOS-6` **Store tokens, passwords and keys in the Keychain, with the most restrictive accessibility that works for the app, such as `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, never in `UserDefaults`, property lists or plain files.** `UserDefaults` stores data on disk unencrypted. Give files that hold personal data the `complete` Data Protection class if the app reads them only in the foreground. ([Apple, UserDefaults](https://developer.apple.com/documentation/foundation/userdefaults), [Restricting keychain item accessibility](https://developer.apple.com/documentation/security/restricting-keychain-item-accessibility), [Encrypting your app's files](https://developer.apple.com/documentation/uikit/encrypting-your-app-s-files))
- `9` `IOS-7` **Sign users in through `ASWebAuthenticationSession`, with the authorization code flow and PKCE (`AUTH-2`), never in a `WKWebView`.** RFC 8252, the best current practice for OAuth in native apps, says that apps must not use embedded user agents for authorization requests. ([IETF, RFC 8252, 8.12 Embedded user agents](https://www.rfc-editor.org/rfc/rfc8252.html#section-8.12), [Apple, ASWebAuthenticationSession](https://developer.apple.com/documentation/authenticationservices/aswebauthenticationsession))
- `8` `IOS-8` **Keep App Transport Security on: don't set `NSAllowsArbitraryLoads`, fix a server that fails the ATS checks instead of adding an exception, and limit any exception you can't avoid to the domains that need it.** This applies `SEC-13`. Exceptions reduce the app's security, and some must be justified in App Review. ([Apple, Preventing insecure network connections](https://developer.apple.com/documentation/security/preventing-insecure-network-connections))

### Privacy

- `9` `IOS-9` **Add a privacy manifest (`PrivacyInfo.xcprivacy`) to the app that declares the data it collects and an approved reason for each required reason API it uses, use the SDKs on Apple's list only in versions that include their privacy manifest (and their signature, if you add them as binaries), and compare the privacy report that Xcode generates from all the manifests with the App Store privacy details before each release.** App Store Connect doesn't accept apps that use required reason APIs without a declared reason. This applies `MOBGAME-6` and `PRIV-11` to every app. ([Apple, Privacy manifest files](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files), [Describing use of required reason API](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api), [Describing data use in privacy manifests](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests), [Third-party SDK requirements](https://developer.apple.com/support/third-party-SDK-requirements/))

### App lifecycle

- `7` `IOS-10` **Save the user's work when the scene phase changes to `.background`, because the app may be terminated soon after, and restore lightweight UI state, such as the selected tab, with `@SceneStorage`. Keep model data and sensitive data out of `@SceneStorage`.** ([Apple, ScenePhase](https://developer.apple.com/documentation/swiftui/scenephase), [SceneStorage](https://developer.apple.com/documentation/swiftui/scenestorage))
- `6` `IOS-11` **Do background work only through the system's mechanisms: finish a task the user started with `beginBackgroundTask(withName:expirationHandler:)`, transfer large files with a background `URLSession`, and schedule refreshes and maintenance as `BGAppRefreshTask` and `BGProcessingTask` requests.** The system decides when scheduled tasks run, and terminates the app if a task overruns its time. ([Apple, Choosing background strategies for your app](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app))

### Persistence and networking

- `7` `IOS-12` **Persist structured app data with SwiftData, or Core Data, and version the schema from the first release: describe each released schema with a `VersionedSchema`, and the migrations between them with a `SchemaMigrationPlan`.** This applies `DATA-2` to the data on users' devices; Core Data migrations likewise depend on properly versioned models. ([Apple, SwiftData](https://developer.apple.com/documentation/swiftdata), [VersionedSchema](https://developer.apple.com/documentation/swiftdata/versionedschema), [SchemaMigrationPlan](https://developer.apple.com/documentation/swiftdata/schemamigrationplan), [Core Data, Staged migrations](https://developer.apple.com/documentation/coredata/staged-migrations))
- `6` `IOS-13` **Make HTTP requests with `URLSession` and its async methods, set `waitsForConnectivity` so that a request waits for a network instead of failing at once, and keep the data the user needs offline in local storage.** Put timeouts and retries with backoff on every call (`OPS-3`). ([Apple, TN3151: Choosing the right networking API](https://developer.apple.com/documentation/technotes/tn3151-choosing-the-right-networking-api), [waitsForConnectivity](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/waitsforconnectivity), [SwiftData](https://developer.apple.com/documentation/swiftdata))

### Accessibility

- `7` `IOS-14` **Use the built-in text styles, and make any custom font scale the same way, so that text follows Dynamic Type, give every meaningful image and custom control a VoiceOver label, and hide decorative images from VoiceOver.** Check each screen with Accessibility Inspector, and in UI tests with `performAccessibilityAudit(for:_:)`. This applies `A11Y-9` and `A11Y-12`. ([Apple, HIG: Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [HIG: VoiceOver](https://developer.apple.com/design/human-interface-guidelines/voiceover), [Performing accessibility audits for your app](https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app))

### Testing and delivery

- `7` `IOS-15` **Write unit tests with Swift Testing and UI tests with XCTest and XCUIAutomation, in a test pyramid (`TEST-1`), and run them on every pull request with `xcodebuild test` or Xcode Cloud.** ([Apple, Testing](https://developer.apple.com/documentation/xcode/testing), [Running tests and interpreting results](https://developer.apple.com/documentation/xcode/running-tests-and-interpreting-results), [Xcode Cloud](https://developer.apple.com/documentation/xcode/xcode-cloud))
- `7` `IOS-16` **Sign release builds with cloud-managed certificates, through automatic signing in Xcode or in Xcode Cloud, and never commit exported signing identities or their passwords.** If you must sign manually, protect an exported identity with a strong password, share the file and the password through different channels, and keep CI copies in the CI's secret store (`SEC-2`). ([Apple, Distributing your app for beta testing and releases](https://developer.apple.com/documentation/xcode/distributing-your-app-for-beta-testing-and-releases), [Cloud-managed certificates](https://developer.apple.com/help/account/certificates/cloud-managed-certificates), [Synchronizing code signing identities with your developer account](https://developer.apple.com/documentation/xcode/sharing-your-teams-signing-certificates))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [Swift 6 language mode](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/enabledataracesafety/): set the Swift Language Version build setting (`SWIFT_VERSION`) to 6, or `swift-tools-version: 6.0` in a package, and the compiler reports data-race safety violations as errors. In Swift 5 mode, Strict Concurrency Checking set to Complete reports them as warnings. Checks `IOS-3`.
- `7` [App Store Connect upload checks](https://developer.apple.com/documentation/bundleresources/adding-a-privacy-manifest-to-your-app-or-third-party-sdk): App Store Connect doesn't accept builds that use required reason APIs without a declared reason, and rejects invalid privacy manifest files and listed SDKs without one. Uploading every build to TestFlight from CI runs these checks. Partly checks `IOS-9`.
- `7` [Accessibility audits in UI tests](https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app): `performAccessibilityAudit(for:_:)` fails a UI test when the current screen has issues such as missing element descriptions, insufficient contrast, clipped text or text that doesn't support Dynamic Type. Call it on every screen the tests visit. Partly checks `IOS-14`.
- `6` [Verifying the origin of your XCFrameworks](https://developer.apple.com/documentation/xcode/verifying-the-origin-of-your-xcframeworks) (Xcode): the build fails if a binary SDK's code signature is removed, becomes invalid, or changes to a different developer. Partly checks `IOS-9`.
- `6` [Thread Sanitizer and Main Thread Checker](https://developer.apple.com/documentation/xcode/diagnosing-memory-thread-and-crash-issues-early) (Xcode): turn them on for the Test action or in a test plan configuration. They report data races between threads, and system APIs called off the main thread, while the tests run. Partly checks `IOS-3` and `IOS-4`.
- `5` [SwiftLint](https://realm.github.io/SwiftLint/rule-directory.html) opt-in rules: [`private_swiftui_state`](https://realm.github.io/SwiftLint/private_swiftui_state.html) flags `@State` properties that aren't private, and [`accessibility_label_for_image`](https://realm.github.io/SwiftLint/accessibility_label_for_image.html) and [`accessibility_trait_for_button`](https://realm.github.io/SwiftLint/accessibility_trait_for_button.html) flag images without a label that aren't hidden from accessibility, and tappable views without a button or link trait. Partly checks `IOS-2` and `IOS-14`.
