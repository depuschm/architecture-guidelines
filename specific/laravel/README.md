# PHP and Laravel

Scope: web applications and APIs built with Laravel and PHP, with Eloquent, Blade, queues and Horizon. On 2026-11-01, Laravel 13 is the current release: it needs PHP 8.3 or later, gets bug fixes until the third quarter of 2027 and security fixes until 17 March 2028. Laravel 12 gets security fixes only, until 24 February 2027. For configuration, health checks, telemetry and resilience, follow [general/operations-reliability.md](../../general/operations-reliability.md); for secrets, authorization and the supply chain, [general/security.md](../../general/security.md); for sign-in and sessions, [general/authentication.md](../../general/authentication.md); for migrations and idempotent message handling, [general/data.md](../../general/data.md). Browser-side rules for accessibility, performance and security are in [Web front end](../web/README.md); databases, caches and containers have their own folders, such as [PostgreSQL](../postgres/README.md), [Redis and caching](../redis/README.md) and [Docker](../docker/README.md). The rules here cover what is specific to Laravel.

## Key rules

### Configuration and deployment

- `9` `LARAVEL-1` **Never commit the `.env` file: commit `.env.example` with placeholder values, and supply the real values as environment variables on the server or in an encrypted environment file (`php artisan env:encrypt`).** Generate `APP_KEY` with `php artisan key:generate`; when you rotate it, list the old keys in `APP_PREVIOUS_KEYS`, so that existing sessions and encrypted data keep working. This is how Laravel applications follow `SEC-2` in [general/security.md](../../general/security.md). ([Laravel, Environment file security](https://laravel.com/framework/docs/configuration#environment-file-security), [Encrypting environment files](https://laravel.com/framework/docs/configuration#encrypting-environment-files), [Encryption: configuration](https://laravel.com/framework/docs/encryption#configuration), [Gracefully rotating encryption keys](https://laravel.com/framework/docs/encryption#gracefully-rotating-encryption-keys))
- `9` `LARAVEL-2` **In production, set `APP_DEBUG` to `false` and point the web server's document root at the `public` directory.** With debug mode on, error pages can expose sensitive configuration values to users, and serving the project root exposes sensitive configuration files to the internet. ([Laravel, Deployment: debug mode](https://laravel.com/framework/docs/deployment#debug-mode), [Deployment: Nginx](https://laravel.com/framework/docs/deployment#nginx))
- `7` `LARAVEL-3` **Run `php artisan optimize` in every deployment, to cache the configuration, events, routes and views; call `env()` only in the files in `config/`; and restart queue workers and other long-running processes after deploying, for example with `php artisan reload`.** Once the configuration is cached, Laravel no longer loads `.env`, so `env()` calls elsewhere return `null` for values that are defined only in `.env`. ([Laravel, Deployment: optimization](https://laravel.com/framework/docs/deployment#optimization), [Configuration caching](https://laravel.com/framework/docs/configuration#configuration-caching), [Deployment: reloading services](https://laravel.com/framework/docs/deployment#reloading-services))

### Security

- `9` `LARAVEL-4` **Authorize every action: write the rules for each model in a policy and the other rules in gates, and check them in each controller action, in the Form Request's `authorize()` method, or with the `can` middleware.** Gates and policies deny guests by default. This is how Laravel applications apply `SEC-1` in [general/security.md](../../general/security.md). ([Laravel, Authorization](https://laravel.com/framework/docs/authorization#introduction), [Authorizing actions via middleware](https://laravel.com/framework/docs/authorization#via-middleware), [Guest users](https://laravel.com/framework/docs/authorization#guest-users), [Authorizing form requests](https://laravel.com/framework/docs/validation#authorizing-form-requests))
- `9` `LARAVEL-5` **Output data with Blade's escaped `{{ }}` syntax, use `{!! !!}` only for HTML you trust, never for content that users supplied, and pass data to JavaScript with `Js::from()`.** `{{ }}` runs values through `htmlspecialchars` to prevent XSS. This is how Blade templates apply `WEB-8`; for sanitizing HTML and Content Security Policy, see [Web front end](../web/README.md). ([Laravel, Blade: displaying unescaped data](https://laravel.com/framework/docs/blade#displaying-unescaped-data), [Rendering JSON](https://laravel.com/framework/docs/blade#rendering-json))
- `9` `LARAVEL-6` **Pass values to raw SQL only as bindings, with `?` or named placeholders, in `DB::select()`, `whereRaw()`, `orderByRaw()` and the other raw methods, and never let user input choose column names, including `orderBy` columns.** The query builder binds values for you, but raw expressions are inserted into the query as strings, PDO can't bind column names, and `DB::unprepared()` binds nothing. This applies `SEC-18`. ([Laravel, Query builder](https://laravel.com/framework/docs/queries#introduction), [Raw methods](https://laravel.com/framework/docs/queries#raw-methods), [Database: running a select query](https://laravel.com/framework/docs/database#running-a-select-query), [Running an unprepared statement](https://laravel.com/framework/docs/database#running-an-unprepared-statement))
- `8` `LARAVEL-7` **Validate every request with a Form Request or the validator, pass only the validated data (`$request->validated()` or `safe()`) to `create()`, `fill()` and `update()`, and declare each model's mass-assignable attributes with the `Fillable` attribute (the `$fillable` property before Laravel 13) instead of unguarding the model.** Otherwise a user can send an extra field, such as `is_admin`, that changes a column you didn't expect. In development, `Model::preventSilentlyDiscardingAttributes()` throws when code fills an attribute that isn't fillable. This applies `SEC-10` in [general/security.md](../../general/security.md). ([Laravel, Form request validation](https://laravel.com/framework/docs/validation#form-request-validation), [Working with validated input](https://laravel.com/framework/docs/validation#working-with-validated-input), [Eloquent: mass assignment](https://laravel.com/framework/docs/eloquent#mass-assignment), [Allowing mass assignment](https://laravel.com/framework/docs/eloquent#allowing-mass-assignment), [Mass assignment exceptions](https://laravel.com/framework/docs/eloquent#mass-assignment-exceptions))
- `8` `LARAVEL-8` **Validate the type and size of every upload with the `File` rule, for example `File::types([...])->max('10mb')` or `File::image()`, and store it under a generated name with `store()` or `hashName()`, never a name built from `getClientOriginalName()`, `getClientOriginalExtension()` or other user input.** An attacker could upload a file named `shell.php` and run it if the storage is web-accessible. `File::types()` checks the file's content, not only its extension, and the image rule rejects SVG files unless you allow them. ([Laravel, Validating files](https://laravel.com/framework/docs/validation#validating-files), [Validating file types](https://laravel.com/framework/docs/validation#validating-files-file-types), [File storage: file uploads](https://laravel.com/framework/docs/filesystem#file-uploads), [Specifying a file name](https://laravel.com/framework/docs/filesystem#specifying-a-file-name), [Other uploaded file information](https://laravel.com/framework/docs/filesystem#other-uploaded-file-information))
- `7` `LARAVEL-9` **Keep browser routes in the `web` middleware group, where the `PreventRequestForgery` middleware checks them, add `@csrf` to every `POST`, `PUT`, `PATCH` and `DELETE` form, and exclude only routes that can't send a token, such as third-party webhooks, from CSRF protection.** For a single-page app that uses Laravel as its API, follow the Sanctum documentation. This applies `AUTH-17`. ([Laravel, Preventing CSRF requests](https://laravel.com/framework/docs/csrf#preventing-csrf-requests), [Excluding URIs from CSRF protection](https://laravel.com/framework/docs/csrf#csrf-excluding-uris))

### Database

- `8` `LARAVEL-10` **Change the schema only through migrations in `database/migrations`, run them in each deployment with `php artisan migrate --force`, and add `--isolated` when several servers deploy at once.** `--isolated` takes a lock, so that only one server runs the migrations. This is how Laravel applications follow `DATA-2` in [general/data.md](../../general/data.md). ([Laravel, Migrations](https://laravel.com/framework/docs/migrations#introduction), [Isolating migration execution](https://laravel.com/framework/docs/migrations#isolating-migration-execution), [Forcing migrations to run in production](https://laravel.com/framework/docs/migrations#forcing-migrations-to-run-in-production))
- `7` `LARAVEL-11` **Eager load the relationships that each query's results use, with `with()` or `load()`, and call `Model::preventLazyLoading(! $this->app->isProduction())` in `AppServiceProvider`, so that lazy loading, the cause of N+1 queries, throws an exception in development and tests.** Production keeps working if a lazy load slips through. ([Laravel, Eager loading](https://laravel.com/framework/docs/eloquent-relationships#eager-loading), [Preventing lazy loading](https://laravel.com/framework/docs/eloquent-relationships#preventing-lazy-loading))
- `7` `LARAVEL-12` **Wrap writes that must succeed or fail together in `DB::transaction()`, pass `attempts` to retry on deadlocks, and dispatch queued jobs from inside a transaction only after it commits, with the queue connection's `after_commit` option or `->afterCommit()`.** Otherwise a worker can pick up the job before the transaction commits, when the records it needs may not exist yet. ([Laravel, Database transactions](https://laravel.com/framework/docs/database#database-transactions), [Handling deadlocks](https://laravel.com/framework/docs/database#handling-deadlocks), [Queues: jobs and database transactions](https://laravel.com/framework/docs/queues#jobs-and-database-transactions))

### Queues

- `8` `LARAVEL-13` **Run slow work, such as processing uploaded files, in queued jobs; make each job safe to run more than once, keep each worker's `--timeout` several seconds shorter than the connection's `retry_after`, limit the attempts, and keep failed jobs in the `failed_jobs` table to inspect and retry them.** If `--timeout` is longer than `retry_after`, a job can be processed twice. Idempotent consumers are `DATA-9` in [general/data.md](../../general/data.md). ([Laravel, Queues](https://laravel.com/framework/docs/queues#introduction), [Job expirations and timeouts](https://laravel.com/framework/docs/queues#job-expirations-and-timeouts), [Dealing with failed jobs](https://laravel.com/framework/docs/queues#dealing-with-failed-jobs))

### Code quality and testing

- `6` `LARAVEL-14` **Write most tests as feature tests that send HTTP requests to the application and assert on the response and the database, reset the database for each test with `RefreshDatabase`, and create test data with model factories.** The Laravel docs say most tests should be feature tests. Their requests are simulated inside the test process, without a real network request; Laravel supports both Pest and PHPUnit. ([Laravel, Testing](https://laravel.com/framework/docs/testing#introduction), [HTTP tests: making requests](https://laravel.com/framework/docs/http-tests#making-requests), [Database testing: resetting the database](https://laravel.com/framework/docs/database-testing#resetting-the-database-after-each-test), [Model factories](https://laravel.com/framework/docs/database-testing#model-factories))
- `6` `LARAVEL-15` **Check the code style with Laravel Pint, and analyse the code with Larastan, the PHPStan extension for Laravel, in CI.** Pint uses its `laravel` preset by default; choose the `per` or `psr12` preset to follow the PHP-FIG style. ([Laravel, Pint](https://laravel.com/framework/docs/pint#running-pint), [Pint presets](https://laravel.com/framework/docs/pint#presets), [Larastan](https://github.com/larastan/larastan))

### Versions

- `8` `LARAVEL-16` **Run a Laravel release that still receives security fixes, on a PHP branch that is still supported, and plan each upgrade before the support ends.** Laravel releases get bug fixes for 18 months and security fixes for 2 years, and PHP branches get 2 years of active support and 2 more of security fixes; for example, PHP 8.2 reaches end of life on 31 December 2026. Commit `composer.lock`, and run `composer audit` in CI. This is how Laravel applications follow `SEC-17` in [general/security.md](../../general/security.md). ([Laravel, Support policy](https://laravel.com/framework/docs/releases#support-policy), [Upgrade guide](https://laravel.com/framework/docs/upgrade), [PHP, Supported Versions](https://www.php.net/supported-versions.php), [Composer, Commit your composer.lock file](https://getcomposer.org/doc/01-basic-usage.md#commit-your-composerlock-file-to-version-control), [Composer, audit](https://getcomposer.org/doc/03-cli.md#audit))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [GitHub secret scanning push protection](https://docs.github.com/en/code-security/concepts/secret-security/push-protection): blocks pushes that contain credentials, for example a committed `.env` file. See [general/security.md](../../general/security.md) for more secret scanners. Partly checks `LARAVEL-1`.
- `6` [Larastan rules](https://github.com/larastan/larastan/blob/3.x/docs/rules.md): [`NoEnvCallsOutsideOfConfig`](https://github.com/larastan/larastan/blob/3.x/docs/rules.md#noenvcallsoutsideofconfig), on by default, reports `env()` calls outside the config directory, and [`JobDispatchedInTransactionUsesAfterCommitRule`](https://github.com/larastan/larastan/blob/3.x/docs/rules.md#jobdispatchedintransactionusesaftercommitrule), turned on with `checkDispatchInTransactionAfterCommit`, reports jobs dispatched inside `DB::transaction()` without `afterCommit()`. Partly checks `LARAVEL-3`, `LARAVEL-12` and `LARAVEL-15`.
- `6` [Psalm Laravel plugin, security analysis](https://github.com/psalm/psalm-plugin-laravel/blob/4.x/docs/security.md): taint analysis that follows request input to sinks such as `orderBy()` columns, `orderByRaw()`, `DB::select()` and `DB::unprepared()`, to file storage paths, and, when turned on, to `{!! !!}` in Blade templates. Partly checks `LARAVEL-5`, `LARAVEL-6` and `LARAVEL-8`.
- `6` [Laravel Pint `--test`](https://laravel.com/framework/docs/pint#running-pint): fails with a non-zero exit code when files don't match the configured style. Partly checks `LARAVEL-15`.
- `6` [`composer audit`](https://getcomposer.org/doc/03-cli.md#audit): exits with an error when an installed package, such as `laravel/framework`, has a security advisory, or is abandoned or flagged as malware. Partly checks `LARAVEL-16`.
- `5` [Semgrep Laravel rules](https://github.com/semgrep/semgrep-rules/tree/develop/php/laravel/security): [`laravel-blade-form-missing-csrf`](https://github.com/semgrep/semgrep-rules/blob/develop/php/laravel/security/laravel-blade-form-missing-csrf.yaml) flags state-changing forms without `@csrf`, [`laravel-dangerous-model-construction`](https://github.com/semgrep/semgrep-rules/blob/develop/php/laravel/security/laravel-dangerous-model-construction.yaml) flags `$guarded = []`, and [`laravel-active-debug-code`](https://github.com/semgrep/semgrep-rules/blob/develop/php/laravel/security/laravel-active-debug-code.yaml) flags code that sets `APP_DEBUG` to true. Partly checks `LARAVEL-2`, `LARAVEL-7` and `LARAVEL-9`.
