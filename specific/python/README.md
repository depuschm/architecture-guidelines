# Python

Scope: applications and back-end services written in Python 3, such as web APIs built with FastAPI or Django, background workers and command-line tools, on Python versions that still receive fixes. For configuration, health checks, telemetry and resilience, follow [general/operations-reliability.md](../../general/operations-reliability.md); for secrets, authorization and the supply chain, [general/security.md](../../general/security.md); for test strategy and architecture tests, [general/testing-delivery.md](../../general/testing-delivery.md); for container images, [Docker](../docker/README.md). The rules here cover what is specific to Python.

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

- `9` [Python Packaging User Guide](https://packaging.python.org/en/latest/) (PyPA): **the baseline for project metadata, `pyproject.toml`, virtual environments and installing packages.** Its [tool recommendations](https://packaging.python.org/en/latest/guides/tool-recommendations/) name the recognised tools for each task, and the deprecated ones to avoid.
- `8` [Deployment checklist](https://docs.djangoproject.com/en/stable/howto/deployment/checklist/) (Django): the settings to review before deploying a Django project, for security, performance, operations and error reporting.
- `8` [Security in Django](https://docs.djangoproject.com/en/stable/topics/security/) (Django): the built-in protections against cross-site scripting, CSRF, SQL injection, clickjacking and host header attacks, plus HTTPS, sessions and user-uploaded content, and their limits.
- `7` [Developing with asyncio](https://docs.python.org/3/library/asyncio-dev.html) (Python docs): debug mode, threads, blocking code, and finding never-awaited coroutines and never-retrieved exceptions.
- `7` [Security Considerations](https://docs.python.org/3/library/security_warnings.html) (Python docs): the standard-library modules with security caveats, such as `pickle`, `random`, `subprocess`, `tempfile`, `xml` and `zipfile`.
- `7` [Static Typing with Python](https://typing.python.org/en/latest/) (Python typing docs): tutorials, guides, reference and the typing specification that type checkers share.
- `7` [Architecture Patterns with Python](https://www.cosmicpython.com/book/preface) (Harry Percival and Bob Gregory, free online): dependency inversion, the repository, service layer and unit of work patterns, and event-driven architecture, with [an appendix for Django](https://www.cosmicpython.com/book/appendix_django). Use it when the domain is complex enough to justify the layers.
- `6` [Deployments Concepts](https://fastapi.tiangolo.com/deployment/concepts/) (FastAPI): HTTPS, running on startup, restarts, worker processes, memory and pre-start steps, whichever way you deploy a FastAPI app.
- `6` [Django Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Django_Security_Cheat_Sheet.html) (OWASP): authentication, key management, security headers, cookies, CSRF, XSS and HTTPS settings for Django.
- `6` [PEP 8, Style Guide for Python Code](https://peps.python.org/pep-0008/): the standard conventions for naming, code layout and imports.

## Key rules

### Project setup and dependencies

- `8` `PY-1` **Run a Python version that still receives fixes, and upgrade before its end-of-life date.** Each feature release gets bug fixes for about two years, then only security fixes until five years after its release. Declare the oldest version the project supports with `requires-python`. ([Python Developer's Guide, Status of Python versions](https://devguide.python.org/versions/), [Packaging User Guide, requires-python](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/#python-requires))
- `8` `PY-2` **Commit a lock file that pins every direct and transitive dependency, install exactly what it lists in CI and deployments, and audit it for known vulnerabilities in CI.** With uv, commit `uv.lock` and install with `uv sync --locked`; with pip-tools, compile requirements with `--generate-hashes` and install them with `pip install --require-hashes`. See [general/security.md](../../general/security.md) for dependency updates and provenance. ([uv, The lockfile](https://docs.astral.sh/uv/concepts/projects/layout/#the-lockfile), [pip, Secure installs](https://pip.pypa.io/en/stable/topics/secure-installs/), [pip-tools, pip-compile](https://pip-tools.pypa.io/en/stable/reference/pip-compile/), [pip-audit](https://github.com/pypa/pip-audit))
- `6` `PY-3` **Install each application's dependencies into its own virtual environment, not into the Python that the operating system manages, and treat the environment as disposable.** Don't commit or copy it; recreate it from the lock file. ([Python, venv](https://docs.python.org/3/library/venv.html), [PEP 668, Marking Python base environments as externally managed](https://peps.python.org/pep-0668/))
- `6` `PY-4` **Describe the project in `pyproject.toml`, use the src layout, and keep tests in a separate `tests/` directory.** Put metadata, `requires-python` and dependencies in the `[project]` table rather than in `setup.py`, and settings for tools such as Ruff, mypy and pytest under `[tool]`. The src layout helps prevent tests and tools from importing the in-development copy of the code by accident instead of the installed package. ([Packaging User Guide, Writing your pyproject.toml](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/), [src layout vs flat layout](https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/), [pytest, Good Integration Practices](https://docs.pytest.org/en/stable/explanation/goodpractices.html#choosing-a-test-layout))

### Application structure

- `6` `PY-5` **When the domain has real business logic, keep it in plain Python modules that import neither the web framework nor the ORM, and let views, routers, tasks and commands call it through a service layer.** A simple CRUD app doesn't need these layers. ([Architecture Patterns with Python, Repository pattern](https://www.cosmicpython.com/book/chapter_02_repository), [Service layer](https://www.cosmicpython.com/book/chapter_04_service_layer))
- `6` `PY-6` **In FastAPI, split path operations into `APIRouter` modules by area, and provide shared resources such as database sessions, settings and the current user through dependencies (`Depends`).** Tests can then replace them with `app.dependency_overrides`. ([FastAPI, Bigger Applications](https://fastapi.tiangolo.com/tutorial/bigger-applications/), [Dependencies](https://fastapi.tiangolo.com/tutorial/dependencies/), [Testing Dependencies with Overrides](https://fastapi.tiangolo.com/advanced/testing-dependencies/))

### Types and validation

- `8` `PY-7` **Validate all external input at runtime where it enters the application, with Pydantic models (as FastAPI does for request bodies) or with Django forms or Django REST framework serializers, and use only the validated data.** Type hints aren't enforced at runtime, so they don't check incoming data. ([Python, typing](https://docs.python.org/3/library/typing.html), [FastAPI, Request Body](https://fastapi.tiangolo.com/tutorial/body/), [Django, Working with forms](https://docs.djangoproject.com/en/stable/topics/forms/), [Django REST framework, Serializer validation](https://www.django-rest-framework.org/api-guide/serializers/#validation), [Security in Django: Always sanitize user input](https://docs.djangoproject.com/en/stable/topics/security/#s-always-sanitize-user-input))
- `7` `PY-8` **Annotate the code with type hints and run a type checker, such as mypy or Pyright, in CI, pinned with the other development dependencies.** Aim for strict mode: turn it on for new code, and module by module in existing code. ([mypy, Using mypy with an existing codebase](https://mypy.readthedocs.io/en/stable/existing_code.html), [mypy, --strict](https://mypy.readthedocs.io/en/stable/command_line.html#cmdoption-mypy-strict), [Pyright, Configuration](https://github.com/microsoft/pyright/blob/main/docs/configuration.md))

### Async code

- `8` `PY-9` **In `async` code, don't call blocking I/O or CPU-heavy functions directly: use async libraries, run blocking calls in a thread with `asyncio.to_thread()` (in Django, `sync_to_async()`), and run CPU-heavy work in an executor such as a process pool.** A blocking call stalls every other task on the event loop. In FastAPI, declare endpoints and dependencies that use blocking libraries with plain `def`, which FastAPI runs in a thread pool. ([Python, Running blocking code](https://docs.python.org/3/library/asyncio-dev.html#running-blocking-code), [asyncio.to_thread](https://docs.python.org/3/library/asyncio-task.html#asyncio.to_thread), [FastAPI, Concurrency and async / await](https://fastapi.tiangolo.com/async/#path-operation-functions), [Django, Async adapter functions](https://docs.djangoproject.com/en/stable/topics/async/#s-async-adapter-functions))
- `6` `PY-10` **Run concurrent tasks in an `asyncio.TaskGroup`, or keep a reference to every task you start with `asyncio.create_task()` until it finishes.** The event loop keeps only weak references to tasks, so an unreferenced task can be garbage-collected before it's done. ([Python, Task groups](https://docs.python.org/3/library/asyncio-task.html#task-groups), [asyncio.create_task](https://docs.python.org/3/library/asyncio-task.html#asyncio.create_task))
- `5` `PY-11` **Write async code only where a service waits on many I/O operations at once, such as long-lived connections or calls fanned out to other services. Otherwise keep it synchronous.** Django advises enabling ASGI only if the project has asynchronous code, and FastAPI advises plain `def` when in doubt. ([Python, asyncio](https://docs.python.org/3/library/asyncio.html), [Django, Asynchronous support: Performance](https://docs.djangoproject.com/en/stable/topics/async/#s-performance), [FastAPI, In a hurry?](https://fastapi.tiangolo.com/async/#in-a-hurry))

### Configuration

- `9` `PY-12` **In Django, never enable `DEBUG` in production, load `SECRET_KEY` and other secrets from the environment or a file, and run `manage.py check --deploy` against the production settings.** Keep the production settings in their own settings module, and serve the app with a production WSGI or ASGI server instead of `runserver`. ([Django, Deployment checklist](https://docs.djangoproject.com/en/stable/howto/deployment/checklist/), [check --deploy](https://docs.djangoproject.com/en/stable/ref/django-admin/#cmdoption-check-deploy))
- `6` `PY-13` **Load configuration into one typed settings object, such as a `pydantic-settings` `BaseSettings` class, so that missing or malformed values raise a validation error when the settings load.** Environment variables are always strings; the settings class converts and validates them, and can also read secrets files. In FastAPI, provide it through a dependency so that tests can override it. ([FastAPI, Settings and Environment Variables](https://fastapi.tiangolo.com/advanced/settings/), [Pydantic, Settings Management](https://pydantic.dev/docs/validation/latest/concepts/pydantic_settings/))

### Code quality and security

- `9` `PY-14` **Never pass untrusted data to `pickle`, `eval()`, `exec()` or `yaml.load()`, or into a shell command with `shell=True`.** Each of them can run arbitrary code: use JSON or `yaml.safe_load()` for data, and pass subprocess arguments as a list. ([Python, pickle](https://docs.python.org/3/library/pickle.html), [Built-in functions: eval](https://docs.python.org/3/builtins/functions.html#eval), [subprocess: Security considerations](https://docs.python.org/3/library/subprocess.html#security-considerations), [PyYAML documentation](https://pyyaml.org/wiki/PyYAMLDocumentation))
- `6` `PY-15` **Lint and format with Ruff, and run `ruff check` and `ruff format --check` in CI and in a pre-commit hook.** Ruff replaces Flake8 and its plugins, isort and Black with one fast tool. Extend its rule selection with the rule sets you need, such as `S` (security) and `ASYNC`. ([Ruff](https://docs.astral.sh/ruff/), [Ruff linter: Rule selection](https://docs.astral.sh/ruff/linter/#rule-selection), [Ruff formatter](https://docs.astral.sh/ruff/formatter/), [Ruff integrations: pre-commit](https://docs.astral.sh/ruff/integrations/#pre-commit))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [mypy `--strict`](https://mypy.readthedocs.io/en/stable/command_line.html#cmdoption-mypy-strict) and [Pyright strict mode](https://github.com/microsoft/pyright/blob/main/docs/configuration.md): fail CI on type errors. Both can apply strict checking to selected modules first, through mypy's per-module options or Pyright's `strict` paths. Checks `PY-8`.
- `7` [`manage.py check --deploy`](https://docs.djangoproject.com/en/stable/ref/django-admin/#cmdoption-check-deploy): run it with the production settings and `--fail-level WARNING`, so that the [deployment checks](https://docs.djangoproject.com/en/stable/ref/checks/#s-security) fail CI when `DEBUG` is on, `SECRET_KEY` is short or was generated automatically by Django, `ALLOWED_HOSTS` is empty, or HTTPS settings are missing. Partly checks `PY-12`.
- `7` [pip hash-checking mode](https://pip.pypa.io/en/stable/topics/secure-installs/#hash-checking-mode) and [uv `--locked`](https://docs.astral.sh/uv/concepts/projects/sync/#checking-the-lockfile): `pip install --require-hashes` fails when a requirement isn't pinned and hashed, and `uv sync --locked` or `uv lock --check` fails when `uv.lock` doesn't match `pyproject.toml`. Partly checks `PY-2`.
- `6` [Ruff flake8-bandit (`S`) rules](https://docs.astral.sh/ruff/rules/#flake8-bandit-s): [S301](https://docs.astral.sh/ruff/rules/suspicious-pickle-usage/), [S307](https://docs.astral.sh/ruff/rules/suspicious-eval-usage/), [S102](https://docs.astral.sh/ruff/rules/exec-builtin/), [S506](https://docs.astral.sh/ruff/rules/unsafe-yaml-load/) and [S602](https://docs.astral.sh/ruff/rules/subprocess-popen-with-shell-equals-true/) flag `pickle`, `eval()`, `exec()`, `yaml.load()` and `shell=True`. [Bandit](https://bandit.readthedocs.io/en/latest/), the standalone security linter, has equivalent checks. Checks `PY-14`.
- `6` [Ruff flake8-async (`ASYNC`) rules](https://docs.astral.sh/ruff/rules/#flake8-async-async) and [RUF006](https://docs.astral.sh/ruff/rules/asyncio-dangling-task/): [ASYNC210](https://docs.astral.sh/ruff/rules/blocking-http-call-in-async-function/), [ASYNC230](https://docs.astral.sh/ruff/rules/blocking-open-call-in-async-function/) and [ASYNC251](https://docs.astral.sh/ruff/rules/blocking-sleep-in-async-function/) flag blocking HTTP calls, `open()` and `time.sleep()` in async functions, and RUF006 flags `create_task()` results that aren't stored. Checks `PY-10`, and partly `PY-9`.
- `6` [Ruff linter exit codes](https://docs.astral.sh/ruff/linter/#exit-codes): `ruff check` exits with status 1 on lint violations, and [`ruff format --check`](https://docs.astral.sh/ruff/formatter/) with a non-zero status on unformatted files, in CI or the [pre-commit hook](https://docs.astral.sh/ruff/integrations/#pre-commit). Checks `PY-15`.
- `6` [pip-audit](https://github.com/pypa/pip-audit): audits an environment, requirements files, or a project's `pyproject.toml` and `pylock.*.toml` files against the PyPI and OSV vulnerability databases, and exits with code 1 when it finds a known vulnerability. It has an official GitHub Action and a pre-commit hook. In uv projects, [`uv audit`](https://docs.astral.sh/uv/reference/cli/#uv-audit) audits the project's dependencies. Partly checks `PY-2`.
- `6` [Import Linter forbidden contracts](https://import-linter.readthedocs.io/en/stable/contract_types/forbidden/): `lint-imports`, in CI or as a pre-commit hook, reports domain modules that import forbidden modules, including external packages such as `django`, `fastapi` or `sqlalchemy`. [Layers contracts](https://import-linter.readthedocs.io/en/stable/contract_types/layers/) check the direction of dependencies between layers. Checks `PY-5`.

## Tutorials and further reading

- `7` [Writing your first Django app](https://docs.djangoproject.com/en/stable/intro/tutorial01/) (Django): the official eight-part tutorial, covering models, views, templates, forms, testing, static files and the admin.
- `7` [Tutorial - User Guide](https://fastapi.tiangolo.com/tutorial/) (FastAPI): builds up FastAPI's features step by step, from path operations and request bodies to dependencies, security, databases and testing.
- `6` [The Python Tutorial](https://docs.python.org/3/tutorial/index.html) (Python docs): the official introduction to the language and its standard library.
- `6` [Working on projects](https://docs.astral.sh/uv/guides/projects/) (uv): creating a project, managing dependencies, the lock file and running commands with uv.
- `6` [Packaging Python Projects](https://packaging.python.org/en/latest/tutorials/packaging-projects/) (PyPA): a small project with `pyproject.toml` and the src layout, built and uploaded to a package index.
- `5` [Type hints cheat sheet](https://mypy.readthedocs.io/en/stable/cheat_sheet_py3.html) (mypy): annotation syntax for variables, functions, classes, generics and async code at a glance.
