# Redis and caching

Scope: using Redis, and compatible servers such as Valkey, as a cache, session store, rate limiter or message queue, plus the caching patterns that apply to any shared cache. The rules cite the Redis documentation; the Valkey documentation covers the same topics and says the same about security, eviction, persistence and Cluster. Who owns data and how consistent it must be are in [general/data.md](../../general/data.md) (`DATA-1`, `DATA-5`). Timeouts, retries and circuit breakers for calls to Redis are in [general/operations-reliability.md](../../general/operations-reliability.md) (`OPS-3`, `OPS-5`). For a relational system of record, see [PostgreSQL](../postgres/README.md); for HTTP and CDN caching, see [Web front end](../web/README.md) and [Serverless and edge hosting](../web-hosting/README.md).

## Key rules

### Caching patterns

- `8` `REDIS-1` **Keep the authoritative copy of cached data in a durable data store, and keep data only in Redis when you have configured persistence and replication for it on purpose.** A cache is a transient store whose entries can be evicted or lost at any time. ([Azure, Caching guidance: high availability and scalability](https://learn.microsoft.com/en-us/azure/architecture/best-practices/caching#implement-high-availability-and-scalability-and-improve-performance), [Redis, Key eviction](https://redis.io/docs/latest/develop/reference/eviction/), [Redis anti-patterns, Running ephemeral Redis as a primary database](https://redis.io/tutorials/redis-anti-patterns-every-developer-should-avoid/#9-running-ephemeral-redis-as-a-primary-database))
- `8` `REDIS-2` **Give cache entries a TTL, even a long one, unless write-through keeps them current, and set `maxmemory` with an eviction policy that fits the workload, such as `allkeys-lru` for a pure cache.** On 64-bit systems Redis has no memory limit by default, and the `volatile-*` policies evict nothing when no key has a TTL. ([AWS, Caching best practices](https://aws.amazon.com/caching/best-practices/), [Redis, Key eviction: maxmemory](https://redis.io/docs/latest/develop/reference/eviction/#maxmem), [Eviction policies](https://redis.io/docs/latest/develop/reference/eviction/#eviction-policies))
- `7` `REDIS-3` **Choose the write strategy per data set: cache-aside (load on a miss, invalidate on write) as the default, and write-through where readers must see a change right after the write.** With cache-aside, a reader can miss or briefly see stale data between a write and the next read. ([Azure, Cache-Aside pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/cache-aside), [Azure, Caching guidance: keep the cache consistent on writes](https://learn.microsoft.com/en-us/azure/architecture/best-practices/caching#keep-the-cache-consistent-on-writes), [AWS, Caching best practices](https://aws.amazon.com/caching/best-practices/))
- `7` `REDIS-4` **Plan for a cold or unavailable cache: put a timeout on cache calls (`OPS-3`), make sure the data store can take the load of all misses or cap and shed that load, and load-test with the cache disabled.** Falling back to the data store during a long cache outage can overload it. ([AWS Builders' Library, Caching challenges and strategies](https://builder.aws.com/content/3K9TeXp6strMiJ4vhakpRD7BQWO/caching-challenges-and-strategies), [Azure, Caching guidance: high availability and scalability](https://learn.microsoft.com/en-us/azure/architecture/best-practices/caching#implement-high-availability-and-scalability-and-improve-performance))
- `6` `REDIS-5` **Protect expensive entries from cache stampedes: add random jitter to TTLs, let only one caller recompute a missing entry (request coalescing), or refresh hot entries before they expire.** Many keys expiring in the same second can also block Redis while it removes them. ([AWS, Caching best practices](https://aws.amazon.com/caching/best-practices/), [AWS Builders' Library, Caching challenges and strategies](https://builder.aws.com/content/3K9TeXp6strMiJ4vhakpRD7BQWO/caching-challenges-and-strategies), [Redis, Diagnosing latency: latency generated by expires](https://redis.io/docs/latest/operate/oss_and_stack/management/optimization/latency/#latency-generated-by-expires), [Vattani et al., Optimal Probabilistic Cache Stampede Prevention](https://www.vldb.org/pvldb/vol8/p886-vattani.pdf))

### Keys, commands and data types

- `8` `REDIS-6` **Never call `KEYS` from application code, and avoid other O(N) commands on big keys: iterate with `SCAN`, `SSCAN`, `HSCAN` or `ZSCAN`, keep collections and values small, and watch the slow log.** Redis runs commands one at a time, so one slow command delays every client. Find big keys with `redis-cli --bigkeys` and `--memkeys`. ([Redis, Keys and values: KEYS](https://redis.io/docs/latest/develop/using-commands/keyspace/#keys), [Diagnosing latency: latency generated by slow commands](https://redis.io/docs/latest/operate/oss_and_stack/management/optimization/latency/#latency-generated-by-slow-commands), [Redis CLI: scan for big keys and memory usage](https://redis.io/docs/latest/develop/tools/cli/#scan-for-big-keys-and-memory-usage), [SLOWLOG](https://redis.io/docs/latest/commands/slowlog/))
- `6` `REDIS-7` **Name keys with one schema, such as `app:object-type:id[:field]`, with a prefix per application or tenant, and hash long natural keys instead of using them as key names.** Redis has no namespaces, so prefixes prevent collisions and let ACLs restrict users to their own keys. ([Redis, Keys and values: content of keys](https://redis.io/docs/latest/develop/using-commands/keyspace/#content-of-keys), [Redis, ACL: key permissions](https://redis.io/docs/latest/operate/oss_and_stack/management/security/acl/#key-permissions))
- `5` `REDIS-8` **On Redis Cluster, put keys that one multi-key command, transaction or script uses into the same hash slot with a hash tag, such as `{user:1000}:cart`, and use hash tags only where you need them.** Multi-key operations work only when all keys hash to the same slot, but too many keys in one slot eventually hurts performance. ([Redis, Keys and values: hashtags](https://redis.io/docs/latest/develop/using-commands/keyspace/#hashtags), [Redis cluster specification: hash tags](https://redis.io/docs/latest/operate/oss_and_stack/reference/cluster-spec/#hash-tags))
- `5` `REDIS-9` **Use Streams with consumer groups, not Pub/Sub, for messages that must not be lost.** Pub/Sub delivers at most once: a message is gone if the subscriber is disconnected or fails to handle it. Streams persist messages and support at-least-once delivery with acknowledgements. ([Redis, Pub/sub: delivery semantics](https://redis.io/docs/latest/develop/pubsub/#delivery-semantics), [Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/))

### Security

- `9` `REDIS-10` **Never expose Redis to the internet or other untrusted networks: bind it to private interfaces, firewall the port so that only the application hosts can reach it, and leave protected mode on.** Redis is designed for trusted clients in trusted environments, and anyone who reaches the port can, for example, delete the whole data set. ([Redis, Security: network security](https://redis.io/docs/latest/operate/oss_and_stack/management/security/#network-security), [Protected mode](https://redis.io/docs/latest/operate/oss_and_stack/management/security/#protected-mode), [Valkey, Security](https://valkey.io/topics/security/))
- `8` `REDIS-11` **Authenticate every client as a named ACL user with only the commands and key patterns it needs, turn off the passwordless `default` user, and use TLS when traffic crosses a network you don't fully control.** By default, every connection is authenticated as `default`, which may run every command on every key, and `AUTH` is sent unencrypted without TLS. ([Redis, ACL](https://redis.io/docs/latest/operate/oss_and_stack/management/security/acl/), [Redis, Security: authentication](https://redis.io/docs/latest/operate/oss_and_stack/management/security/#authentication), [Redis, TLS](https://redis.io/docs/latest/operate/oss_and_stack/management/security/encryption/))

### Persistence and availability

- `7` `REDIS-12` **Choose persistence by what losing the data would cost: none for a cache you can rebuild, RDB snapshots when losing the last minutes of writes is acceptable, and AOF plus RDB for safety close to PostgreSQL's. Copy RDB snapshots off the machine at least daily.** ([Redis, Persistence: what should I use](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/#ok-so-what-should-i-use), [Backing up Redis data](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/#backing-up-redis-data))
- `6` `REDIS-13` **With replication, turn on persistence on the primary and the replicas, or stop a primary without persistence from restarting automatically.** A primary that restarts empty replicates the empty data set and wipes its replicas. ([Redis, Replication: safety when the master has persistence turned off](https://redis.io/docs/latest/operate/oss_and_stack/management/replication/#safety-of-replication-when-master-has-persistence-turned-off))
- `6` `REDIS-14` **For automatic failover, run Sentinel, with at least three instances on machines that fail independently, or Redis Cluster, and design for lost writes.** Replication is asynchronous, so a failover can lose acknowledged writes, even with `WAIT`. ([Redis, Sentinel: fundamental things to know](https://redis.io/docs/latest/operate/oss_and_stack/management/sentinel/#fundamental-things-to-know-about-sentinel-before-deploying), [Redis, Replication](https://redis.io/docs/latest/operate/oss_and_stack/management/replication/), [Redis cluster specification: write safety](https://redis.io/docs/latest/operate/oss_and_stack/reference/cluster-spec/#write-safety))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [Redis ACL command categories](https://redis.io/docs/latest/operate/oss_and_stack/management/security/acl/#command-categories): built into Redis and Valkey. Give application users rules such as `+@all -@dangerous ~myapp:*`, in test environments too, so that Redis rejects `KEYS`, `FLUSHALL`, `CONFIG` and the other [dangerous commands](https://redis.io/docs/latest/operate/oss_and_stack/management/security/acl/#dangerous), and keys outside the application's prefix, with an error. Partly checks `REDIS-6` and `REDIS-7`.
- `6` [Checkov Terraform policies](https://www.checkov.io/5.Policy%20Index/terraform.html): misconfiguration checks for managed Redis in Terraform, such as `CKV_AWS_31` (ElastiCache in-transit encryption with an auth token), `CKV_AZURE_89` (Azure Cache for Redis without public network access), `CKV_AZURE_91` (only the TLS port), `CKV_GCP_95` and `CKV_GCP_97` (Memorystore AUTH and in-transit encryption), `CKV_AWS_134` (ElastiCache automatic backups) and `CKV2_AWS_50` (ElastiCache Multi-AZ automatic failover). Partly checks `REDIS-10`, `REDIS-11`, `REDIS-12` and `REDIS-14`.
