# Java and Spring Boot

Scope: back-end services and web applications built with Spring Boot 4 on a Java LTS release, with Spring Security, and Spring Data JPA and Hibernate for relational data. On 2026-11-01, Spring Boot 4.1 and 4.0 have open-source support; they run on Spring Framework 7 and need Java 17 or later. For configuration, health checks, telemetry and resilience, follow [general/operations-reliability.md](../../general/operations-reliability.md); for secrets, authorization and the supply chain, [general/security.md](../../general/security.md); for sign-in and sessions, [general/authentication.md](../../general/authentication.md); for data ownership, migrations and messaging, [general/data.md](../../general/data.md); for architecture tests, [general/testing-delivery.md](../../general/testing-delivery.md). Container images, Kubernetes, telemetry pipelines and PostgreSQL have their own folders: [Docker](../docker/README.md), [Kubernetes](../kubernetes/README.md), [OpenTelemetry](../opentelemetry/README.md) and [PostgreSQL](../postgres/README.md). The rules here cover what is specific to Spring Boot.

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

- `10` [Spring Boot reference documentation](https://docs.spring.io/spring-boot/reference/index.html) (Spring): **the baseline.** Code structure, dependency injection, externalized configuration, profiles, data access, web and security, Actuator, observability, testing, packaging and deployment, with [how-to guides](https://docs.spring.io/spring-boot/how-to/index.html) for common tasks.
- `9` [Spring Security reference](https://docs.spring.io/spring-security/reference/index.html) (Spring): **the baseline for security**: the filter chain architecture, authentication, request and method authorization, and protection against exploits such as CSRF.
- `8` [Spring Modulith reference](https://docs.spring.io/spring-modulith/reference/) (Spring): application modules in a Spring Boot application, verifying their structure, events between modules, module integration tests and documentation. Use it for modular monoliths.
- `8` [A Short Guide to Hibernate 7](https://docs.hibernate.org/orm/7.4/introduction/html_single/) (Hibernate): mapping entities and associations, sessions and transactions, queries, and tuning performance, including association fetching and the N+1 selects problem. Spring Boot 4.1 uses Hibernate 7.4.
- `7` [Spring Framework reference](https://docs.spring.io/spring-framework/reference/) (Spring): the core container and dependency injection, transaction management, and the web frameworks that Spring Boot configures.
- `7` [Spring Data JPA reference](https://docs.spring.io/spring-data/jpa/reference/) (Spring): repositories, query methods, projections, entity graphs and transactionality.
- `7` [Spring Boot support timeline](https://spring.io/projects/spring-boot#support) and [support policy](https://spring.io/support-policy/) (Spring): the open-source and commercial support end date of each Spring Boot generation, and how long major and minor releases are supported.

## Key rules

### Structure and dependency injection

- `7` `SPRING-1` **Inject dependencies through constructors, not into fields.** The Spring Boot and Spring Framework docs recommend constructor injection: dependencies can be `final`, required ones can't be `null`, and the object is complete when it's created. A class with a single constructor needs no `@Autowired`. ([Spring Boot, Spring Beans and Dependency Injection](https://docs.spring.io/spring-boot/reference/using/spring-beans-and-dependency-injection.html), [Spring Framework, Constructor-based or setter-based DI?](https://docs.spring.io/spring-framework/reference/core/beans/dependencies/factory-collaborators.html#beans-constructor-vs-setter-injection))
- `6` `SPRING-2` **Package by feature: put the main application class in a root package, give each business capability its own subpackage, and once there are several, enforce the boundaries with Spring Modulith.** Spring Modulith treats each direct subpackage of the main package as an application module, rejects references to another module's internal subpackages and cycles between modules, and checks this in a test with `ApplicationModules.of(Application.class).verify()`. This is how Spring applications apply `STYLE-5` and `STYLE-7` in [general/architecture-styles.md](../../general/architecture-styles.md). ([Spring Boot, Structuring Your Code](https://docs.spring.io/spring-boot/reference/using/structuring-your-code.html), [Spring Modulith, Application Modules](https://docs.spring.io/spring-modulith/reference/fundamentals.html#modules.advanced), [Verifying Application Module Structure](https://docs.spring.io/spring-modulith/reference/verification.html))

### Configuration

- `9` `SPRING-3` **Keep secrets out of `application.properties`, `application.yaml` and every other file in the repository: mount them as files and import them with `spring.config.import=configtree:`, or load them from a secrets manager, for example with Spring Cloud Vault.** Spring Boot has no built-in encryption for property values. This is how Spring Boot applications follow `SEC-2` in [general/security.md](../../general/security.md). ([Spring Boot, Using Configuration Trees](https://docs.spring.io/spring-boot/reference/features/external-config.html#features.external-config.files.configtree), [Encrypting Properties](https://docs.spring.io/spring-boot/reference/features/external-config.html#features.external-config.encrypting))
- `6` `SPRING-4` **Bind your own settings to `@ConfigurationProperties` classes instead of scattering `@Value` annotations, and annotate them with `@Validated` and Jakarta Bean Validation constraints, so that Spring Boot validates the values when it binds them.** `@ConfigurationProperties` adds full relaxed binding and configuration metadata, and gives the code one structured, type-safe object to inject. ([Spring Boot, @ConfigurationProperties vs. @Value](https://docs.spring.io/spring-boot/reference/features/external-config.html#features.external-config.typesafe-configuration-properties.vs-value-annotation), [@ConfigurationProperties Validation](https://docs.spring.io/spring-boot/reference/features/external-config.html#features.external-config.typesafe-configuration-properties.validation))

### Security

- `9` `SPRING-5` **Declare the authorization of every request in each `SecurityFilterChain`: permit the public paths explicitly, require roles or authorities for the rest, and end with `anyRequest().authenticated()` or `anyRequest().denyAll()`.** Spring Security calls denying by default a healthy practice, because it turns the rules into an allow list. A custom `SecurityFilterChain` replaces Spring Boot's default web security, including the protection of Actuator endpoints, so it has to cover every request. Permit static resources with `permitAll()` rather than ignoring them, so that they still get security headers. This applies `SEC-1` in [general/security.md](../../general/security.md). ([Spring Security, Authorize HttpServletRequests: matching by HTTP method](https://docs.spring.io/spring-security/reference/servlet/authorization/authorize-http-requests.html#match-by-httpmethod), [Favor permitAll over ignoring](https://docs.spring.io/spring-security/reference/servlet/authorization/authorize-http-requests.html#favor-permitall), [Spring Boot, MVC Security](https://docs.spring.io/spring-boot/reference/web/spring-security.html#web.security.spring-mvc))
- `9` `SPRING-6` **Expose only the Actuator endpoints you need over HTTP, and secure every exposed endpoint other than `health`, with Spring Security rules built on `EndpointRequest` or by keeping the endpoints behind a firewall.** Only `health` is exposed by default, because endpoints can contain sensitive information, and the Spring Boot docs strongly recommend securing the endpoints of a publicly exposed application. ([Spring Boot, Exposing Endpoints](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#actuator.endpoints.exposing), [Actuator Security](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#actuator.endpoints.security))
- `8` `SPRING-7` **Keep Spring Security's CSRF protection, which is on by default, for every endpoint that browsers call with cookies or HTTP Basic credentials, and exempt only paths that only non-browser clients call, such as APIs authenticated with bearer tokens, with `csrf.ignoringRequestMatchers()` instead of turning the protection off with `csrf.disable()`.** This applies `AUTH-17`, which also asks for `GET`, `HEAD` and `OPTIONS` requests without side effects. ([Spring Security, When to use CSRF protection](https://docs.spring.io/spring-security/reference/features/exploits/csrf.html#csrf-when), [CSRF and stateless browser applications](https://docs.spring.io/spring-security/reference/features/exploits/csrf.html#csrf-when-stateless), [Safe methods must be read-only](https://docs.spring.io/spring-security/reference/features/exploits/csrf.html#csrf-protection-read-only), [Disable CSRF protection](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html#disable-csrf))
- `7` `SPRING-8` **Use method security (`@EnableMethodSecurity` with `@PreAuthorize` and `@PostAuthorize`) for checks that depend on a method's arguments or return value, such as ownership of a record, and keep a catch-all rule in the `SecurityFilterChain`.** Methods without an annotation aren't secured, and Spring Boot doesn't enable method security for you. ([Spring Security, Method Security](https://docs.spring.io/spring-security/reference/servlet/authorization/method-security.html), [Comparing request-level and method-level authorization](https://docs.spring.io/spring-security/reference/servlet/authorization/method-security.html#request-vs-method))

### Data

- `8` `SPRING-9` **Manage the schema with Flyway or Liquibase migrations, which Spring Boot runs at startup, and leave `spring.jpa.hibernate.ddl-auto` at `none` or set it to `validate`.** `none` is the default when a migration tool is present or the database isn't embedded; `validate` makes Hibernate check the mappings against the migrated schema. This is how Spring Boot applications follow `DATA-2` in [general/data.md](../../general/data.md). ([Spring Boot, Use a Higher-level Database Migration Tool](https://docs.spring.io/spring-boot/how-to/data-initialization.html#howto.data-initialization.migration-tool), [Initialize a Database Using Hibernate](https://docs.spring.io/spring-boot/how-to/data-initialization.html#howto.data-initialization.using-hibernate), [Hibernate, Testing persistence logic](https://docs.hibernate.org/orm/7.4/introduction/html_single/#testing))
- `7` `SPRING-10` **Map every association with `fetch = LAZY`, fetch the data each use case needs up front with `join fetch` or an entity graph (`@EntityGraph` in Spring Data JPA), and set `spring.jpa.open-in-view=false`.** JPA fetches `@ManyToOne` eagerly by default, and lazy loading while code walks the results causes N+1 selects. Spring Boot turns on Open EntityManager in View by default in web applications, which lets views and serializers run such queries after the service's transaction has ended, while holding a database connection. ([Hibernate, Many-to-one](https://docs.hibernate.org/orm/7.4/introduction/html_single/#many-to-one), [Association fetching](https://docs.hibernate.org/orm/7.4/introduction/html_single/#association-fetching), [Join fetching](https://docs.hibernate.org/orm/7.4/introduction/html_single/#join-fetch), [Spring Data JPA, Configuring Fetch- and LoadGraphs](https://docs.spring.io/spring-data/jpa/reference/jpa/query-methods.html#jpa.entity-graph), [Spring Boot, Open EntityManager in View](https://docs.spring.io/spring-boot/reference/data/sql.html#data.sql.jpa-and-spring-data.open-entity-manager-in-view), [Vlad Mihalcea, The Open Session In View Anti-Pattern](https://vladmihalcea.com/the-open-session-in-view-anti-pattern/))
- `7` `SPRING-11` **Define transaction boundaries with `@Transactional` on the methods of service classes that carry out one use case across several repository calls, and call those methods from other beans.** With Spring's default proxy mode, a call from one method of a class to another of the same class bypasses the proxy and runs without the transaction. Put the annotation on concrete classes, not on interfaces. ([Spring Data JPA, Transactionality](https://docs.spring.io/spring-data/jpa/reference/jpa/transactions.html), [Spring Framework, Using @Transactional](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html))

### Operations

- `7` `SPRING-12` **On Kubernetes, point the liveness and readiness probes at `/actuator/health/liveness` and `/actuator/health/readiness`, keep checks of external systems out of the liveness group, and give the pod a `preStop` sleep and a termination grace period long enough for the sleep and `spring.lifecycle.timeout-per-shutdown-phase`.** Graceful shutdown is on by default, but traffic can still reach a pod that has begun shutting down. If Actuator runs on a separate management port, also expose the probes on the main port with `management.endpoint.health.probes.add-additional-paths=true`. This applies `K8S-2` and `K8S-3` in [Kubernetes](../kubernetes/README.md). ([Spring Boot, Kubernetes Probes](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#actuator.endpoints.kubernetes-probes), [Checking External State With Kubernetes Probes](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#actuator.endpoints.kubernetes-probes.external-state), [Graceful Shutdown](https://docs.spring.io/spring-boot/reference/web/graceful-shutdown.html), [Kubernetes Container Lifecycle](https://docs.spring.io/spring-boot/how-to/deployment/cloud.html#howto.deployment.cloud.kubernetes.container-lifecycle))
- `7` `SPRING-13` **Instrument through Micrometer Observation, which Spring Boot uses for metrics and traces, export both over OTLP to an OpenTelemetry Collector, and set the service name with `OTEL_SERVICE_NAME` or `management.opentelemetry.resource-attributes`.** Add `spring-boot-starter-opentelemetry` for traces, and Micrometer's OTLP registry for metrics. Spring Boot samples only 10% of traces by default, so set `management.tracing.sampling.probability` deliberately (`OTEL-8`). The OpenTelemetry Java agent and Spring Boot starter, maintained by the OpenTelemetry community, are the alternatives. This applies `OPS-11` in [general/operations-reliability.md](../../general/operations-reliability.md), and `OTEL-1` and `OTEL-11` in [OpenTelemetry](../opentelemetry/README.md). ([Spring Boot, Observability: OpenTelemetry Support](https://docs.spring.io/spring-boot/reference/actuator/observability.html#actuator.observability.opentelemetry), [Tracing: OpenTelemetry With OTLP](https://docs.spring.io/spring-boot/reference/actuator/tracing.html#actuator.micrometer-tracing.tracer-implementations.otel-otlp), [Tracing: Sampling](https://docs.spring.io/spring-boot/reference/actuator/tracing.html#actuator.micrometer-tracing.sampling), [Metrics: OTLP](https://docs.spring.io/spring-boot/reference/actuator/metrics.html#actuator.metrics.export.otlp))

### Versions and runtime

- `8` `SPRING-14` **Run a Spring Boot generation that still has open-source support, and upgrade to the next minor release before its support ends; run it on a Java LTS release that your JDK distribution still updates.** Each Spring Boot minor release gets at least 13 months of open-source support; for example, open-source support for Spring Boot 3.5 ended on 30 June 2026, and for 4.0 it ends on 31 December 2026. Java 17, 21 and 25 are LTS releases, and Spring Boot 4.1 runs on Java 17 to 27. This is how Spring Boot applications follow `SEC-17` in [general/security.md](../../general/security.md). ([Spring, Spring Boot support timeline](https://spring.io/projects/spring-boot#support), [Spring support policy](https://spring.io/support-policy/), [Spring Boot, System Requirements](https://docs.spring.io/spring-boot/system-requirements.html), [Oracle Java SE Support Roadmap](https://www.oracle.com/java/technologies/java-se-support-roadmap.html))
- `5` `SPRING-15` **Enable virtual threads with `spring.threads.virtual.enabled=true` only on Java 21 or later, preferably Java 24 or later, and when you do, set `spring.main.keep-alive=true` and limit concurrency with semaphores or connection pools rather than pools of threads.** Virtual threads are daemon threads, so scheduled tasks alone no longer keep the JVM running, and thread pool settings stop having an effect. Watch for pinned virtual threads, which lower throughput. ([Spring Boot, Virtual threads](https://docs.spring.io/spring-boot/reference/features/spring-application.html#features.spring-application.virtual-threads), [Oracle, Java 25 Virtual Threads](https://docs.oracle.com/en/java/javase/25/core/virtual-threads.html))

### Testing

- `7` `SPRING-16` **Test controllers with `@WebMvcTest` and repositories with `@DataJpaTest`, and run at least the repository and integration tests against the database engine you use in production, started by Testcontainers and connected with `@ServiceConnection`.** Each test slice loads only the configuration for one layer, so the tests stay fast. In-memory databases are fast, but the Hibernate guide advises testing against the database system you use in production. ([Spring Boot, Auto-configured Tests](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html#testing.spring-boot-applications.autoconfigured-tests), [Testcontainers: Service Connections](https://docs.spring.io/spring-boot/reference/testing/testcontainers.html#testing.testcontainers.service-connections), [Hibernate, Testing persistence logic](https://docs.hibernate.org/orm/7.4/introduction/html_single/#testing))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [Spring Modulith verification](https://docs.spring.io/spring-modulith/reference/verification.html): `ApplicationModules.of(Application.class).verify()` in a unit test fails on cycles between modules and on references to another module's internal packages. Checks `SPRING-2`.
- `7` [GitHub secret scanning push protection](https://docs.github.com/en/code-security/concepts/secret-security/push-protection): blocks pushes that contain credentials, for example in `application.yaml`. See [general/security.md](../../general/security.md) for more secret scanners. Partly checks `SPRING-3`.
- `6` [CodeQL, Disabled Spring CSRF protection](https://codeql.github.com/codeql-query-help/java/java-spring-disabled-csrf-protection/), [Exposed Spring Boot actuators](https://codeql.github.com/codeql-query-help/java/java-spring-boot-exposed-actuators/) and [Exposed Spring Boot actuators in configuration file](https://codeql.github.com/codeql-query-help/java/java-spring-boot-exposed-actuators-config/): queries in the default code-scanning suite that flag `csrf().disable()`, security configurations that open Actuator endpoints to everyone, and `management.endpoints.web.exposure.include=*`. Partly checks `SPRING-6` and `SPRING-7`.
- `6` [ArchUnit GeneralCodingRules](https://www.archunit.org/userguide/html/000_Index.html#_generalcodingrules) and [ProxyRules](https://www.archunit.org/userguide/html/000_Index.html#_proxyrules): `NO_CLASSES_SHOULD_USE_FIELD_INJECTION` fails a test when a class uses field injection, and `no_classes_should_directly_call_other_methods_declared_in_the_same_class_that_are_annotated_with(Transactional.class)` when a class calls its own `@Transactional` methods. Checks `SPRING-1`, and partly `SPRING-11`.
- `6` [OWASP Dependency-Check](https://dependency-check.github.io/DependencyCheck/dependency-check-maven/configuration.html) (also for [Gradle](https://dependency-check.github.io/DependencyCheck/dependency-check-gradle/configuration.html)): scans the dependencies, including Spring Boot and the libraries it manages, for known vulnerabilities, and fails the build above the CVSS score set in `failBuildOnCVSS`. Partly checks `SPRING-14`.
