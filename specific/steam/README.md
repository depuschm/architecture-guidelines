# Steam and PC games

Scope: architecture concerns specific to shipping and running a game on Steam and on Windows and Linux PCs, whatever the engine: SteamPipe builds and branches, Steamworks account and key security, player authentication and in-game purchases, stats, achievements and leaderboards, Steam Cloud, controllers and Steam Input, Steam Deck, Steam Machine and Proton compatibility, PC settings, crash reporting and code signing. It follows the Steamworks documentation as of November 2026, including the compatibility review for Steam Deck, Steam Machine and other SteamOS devices; VR is out of scope. Engine-independent rules, such as save-data versioning, server authority and accessibility, are in [Game development](../gamedev/README.md), the counterpart for phones is [Mobile games](../mobile-games/README.md), and engine-specific guidance is in [Unity](../unity/README.md), [Godot](../godot/README.md), [Unreal Engine](../unreal/README.md) and [GameMaker](../gamemaker/README.md). Build pipelines also follow [GitHub Actions](../github-actions/README.md) or [GitLab CI/CD](../gitlab-ci/README.md), and keys, purchases and crash data follow [Security](../../general/security.md) and [Privacy](../../general/privacy.md).

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Key rules

### Builds and releases

- `7` `STEAM-1` **Upload builds from CI with `steamcmd` under a dedicated Steam build account that has only the *Edit App Metadata* and *Publish App Changes To Steam* permissions, and keep its login token in the CI secret store.** Log in once with the password and Steam Guard code, then keep the resulting `config.vdf`, which holds the login token, as a CI secret: restore it for every run, keep the updates `steamcmd` makes to it, and never commit it (`SEC-2`). Logging in with the password again issues a new Steam Guard token. For itch.io, push with `butler push` and keep the API key in the `BUTLER_API_KEY` secret. ([Steamworks, Steam build account](https://partner.steamgames.com/doc/sdk/uploading#Build_Account), [Using SteamPipe in a CI/CD environment](https://partner.steamgames.com/doc/sdk/uploading#automating_steampipe), [itch.io, Running butler from CI builds](https://itch.io/docs/butler/login.html#running-butler-from-ci-builds-github-actions-gitlab-ci-etc))
- `7` `STEAM-2` **Let CI set builds live only on a beta branch with a password, test each build there, and set it live on the default branch by hand in Steamworks. To roll back, set the previous build live again.** Build scripts can't set the default branch live, and for a released game Steam asks the account that does it to confirm through the Steam Mobile Authenticator or by SMS, so give that account one of them. After a security change to the account, such as a new email address or phone number, it can't set builds live for a released game for three days. Set the branch password before the first build goes live on it, so that the branch stays private. ([Steamworks, Updating your game: uploading your update](https://partner.steamgames.com/doc/store/updates#7), [Advanced build scripts](https://partner.steamgames.com/doc/sdk/uploading#5), [Authorizing default build updates](https://partner.steamgames.com/doc/store/application/builds#Authorizing_Default_Build_Updates), [Beta branches](https://partner.steamgames.com/doc/store/application/builds#Beta_Branches), [Steam build account](https://partner.steamgames.com/doc/sdk/uploading#Build_Account), [Introduction to SteamPipe](https://partner.steamgames.com/doc/sdk/uploading#Introduction))
- `7` `STEAM-3` **Ship updates and extra content through SteamPipe depots or DLC, not as downloads inside the game, and lay out pack files so that patches stay small: no more than about one or two GB each, grouped by level or feature, with new content in new pack files, no reordered assets or build timestamps, and compression only per asset.** SteamPipe compares files in 1 MB chunks, so a change that shifts data through a pack file makes players download most of it again; in Unreal Engine, Valve suggests a pak padding alignment of 1 MB. Leave `steam_appid.txt` out of depots, because it's for development only. ([Steamworks, Updating your game: best practices](https://partner.steamgames.com/doc/store/updates), [Game content structure: best practices](https://partner.steamgames.com/doc/sdk/uploading#AppStructureBestPractices), [SteamAPI_Init](https://partner.steamgames.com/doc/sdk/api#SteamAPI_Init))

### Accounts, keys and purchases

- `9` `STEAM-4` **Keep the publisher Web API key and the Encrypted App Ticket key on your servers only, never in the game or its repository, and limit each publisher key to the permissions and calling IP addresses it needs.** Publisher keys give access to sensitive user data and protected methods such as microtransactions and sales data, Valve says they must not be distributed with a game client, and requests that contain them should use HTTPS. Create them in a dedicated Steamworks group. This applies `SEC-11` and `SEC-2`. ([Steamworks, Publisher keys](https://partner.steamgames.com/doc/webapi_overview/auth#publisher-keys), [Creating a publisher Web API key](https://partner.steamgames.com/doc/webapi_overview/auth#create_publisher_key), [Encrypted Application Tickets](https://partner.steamgames.com/doc/features/auth#2))
- `7` `STEAM-5` **Identify players on your game servers and backends by verifying a Steam session ticket, not by a Steam ID that the client reports: a game server or peer passes the ticket to `BeginAuthSession`, and a backend sends a ticket from `GetAuthTicketForWebApi` to the `ISteamUserAuth/AuthenticateUserTicket` Web API.** Use each ticket only once, refuse players whose ticket is invalid, and check ownership of the game and its DLC for the verified identity, for example with `UserHasLicenseForApp` or `ISteamUser/CheckAppOwnership`. This applies `SEC-1`. ([Steamworks, Authentication between clients and game servers](https://partner.steamgames.com/doc/features/auth#client_to_client), [Authentication with a backend server](https://partner.steamgames.com/doc/features/auth#client_to_backend_webapi))
- `7` `STEAM-6` **Run in-game purchases from your server: start each one with `ISteamMicroTxn/InitTxn`, grant the items only after your server's `FinalizeTxn` call succeeds, and call `GetReport` at least once a day to take back the items of refunded and charged-back orders.** The game's `MicroTxnAuthorizationResponse_t` callback only reports that the player approved the purchase, for the game to pass on to your server. This is the Steam counterpart of `MOBGAME-1` and `MOBGAME-3`. ([Steamworks, Microtransactions: in-game purchasing](https://partner.steamgames.com/doc/features/microtransactions/implementation#6), [Status values](https://partner.steamgames.com/doc/features/microtransactions/implementation#status_values))
- `7` `STEAM-7` **Grant Steamworks permissions through groups that contain only the apps each person works on, give each person only the permissions they need, keep *Administrator*, *Manage Users*, *Manage Signing* and *Actual Authority* to a few people, and review who has them regularly.** *Manage Signing* controls the anti-cheat and SDK Auth settings, and Valve recommends reviewing *Actual Authority* periodically; the User History page shows who added or removed whom, and with which permissions. This applies `SEC-1`. ([Steamworks, Managing groups](https://partner.steamgames.com/doc/gettingstarted/managing_users#5), [Actual Authority](https://partner.steamgames.com/doc/gettingstarted/managing_users#7), [Group permissions](https://partner.steamgames.com/doc/gettingstarted/managing_users#9), [User history](https://partner.steamgames.com/doc/gettingstarted/managing_users#4))

### Stats, achievements and saves

- `7` `STEAM-8` **Let only servers you host set the stats, achievements and leaderboard scores that competition or rewards depend on: set the stat's *Set By* to *Official GS* and register your servers' IP ranges, and set competitive leaderboards' *Writes* to *Trusted*, so that only your server can submit scores, with the `SetLeaderboardScore` Web API.** Players can modify their own game servers or pretend to be one, so *GS* is weaker than *Official GS*. For stats that clients set, use minimum and maximum values, *Increment Only* and *Max Change*, especially for aggregated stats. This applies `GAMEDEV-5`. ([Steamworks, Define your game's stats](https://partner.steamgames.com/doc/features/achievements#4), [Game server stats](https://partner.steamgames.com/doc/features/achievements#game_server_stats), [Global stats](https://partner.steamgames.com/doc/features/achievements#global_stats), [Leaderboards: creating via the web](https://partner.steamgames.com/doc/features/leaderboards#4))
- `7` `STEAM-9` **Write Steam Cloud saves to a folder for each Steam user, such as `{64BitSteamID}` in an Auto-Cloud path, keep Auto-Cloud root paths *Cross-Platform*, split saves into small files by how often they change, and never sync machine-specific settings such as resolution or graphics quality.** Use the Cloud API (`ISteamRemoteStorage`) instead of Auto-Cloud when the game needs to choose which files to sync, and set a demo's *Shared cloud APP ID* to the full game, so that demo saves carry over. Versioning saves and keeping the last good one are `GAMEDEV-10` and `GAMEDEV-11`. ([Steamworks, Steam Cloud: notes and best practices](https://partner.steamgames.com/doc/features/cloud#notes-and-best-practices), [Save file paths](https://partner.steamgames.com/doc/features/cloud#3), [Cross-platform saves](https://partner.steamgames.com/doc/features/cloud#4), [Cloud API and Auto-Cloud](https://partner.steamgames.com/doc/features/cloud#5), [Initial setup](https://partner.steamgames.com/doc/features/cloud#initial-setup), [Getting your game ready for Steam Deck: game features](https://partner.steamgames.com/doc/steamhardware/recommendations#3))
- `6` `STEAM-10` **Let Steam keep stats and achievements: call `SetStat` whenever a stat changes and `StoreStats` at checkpoints and right after unlocking achievements, and don't keep a copy of them in your own files.** Steam caches them for offline play and merges progress from several computers, and a separate cache can conflict with it and make players' progress look reverted. Store independent stats and compute the ones derived from them, such as games played from games won and lost. ([Steamworks, How to use stats and achievements](https://partner.steamgames.com/doc/features/achievements#6), [Offline mode](https://partner.steamgames.com/doc/features/achievements#8), [Stat consistency](https://partner.steamgames.com/doc/features/achievements#10))

### Controllers, Steam Deck and PC settings

- `7` `STEAM-11` **Make the whole game playable with a controller in its default configuration: read input as actions grouped into action sets, through the Steam Input API or your engine's action-based input (`UNREAL-29`, `GODOT-22`), show glyphs for the device in use, accept mouse and controller input at the same time, and open the on-screen keyboard with `ShowGamepadTextInput` or `ShowFloatingGamepadTextInput` when the game needs text.** The Verified rating on Steam Deck and Steam Machine requires full access with the default controller configuration, matching glyphs, and text entry with a controller alone. Publish an official Steam Input configuration for every controller type, don't restrict how players customize their controls (remapping is `GAMEDEV-18`), and look up glyphs every frame, because players can change their bindings at any time. ([Steamworks, Compatibility checklist](https://partner.steamgames.com/doc/steamhardware/compat#2), [Steam Input: overview](https://partner.steamgames.com/doc/features/steam_controller/getting_started_for_devs#1), [Playing nicely with Steam Input](https://partner.steamgames.com/doc/features/steam_controller/getting_started_for_devs#5), [In-game actions file](https://partner.steamgames.com/doc/features/steam_controller/getting_started_for_devs#iga), [On-screen glyphs](https://partner.steamgames.com/doc/features/steam_controller/getting_started_for_devs#18), [Getting your game ready for Steam Deck: input](https://partner.steamgames.com/doc/steamhardware/recommendations#1))
- `7` `STEAM-12` **Save graphics settings for each device and keep them out of Steam Cloud, choose defaults for the detected hardware without hiding any setting, support aspect ratios other than 16:9 and 16:10, and match the display's resolution on first launch.** For the Verified rating, the default configuration must reach 30 fps at 800p on Steam Deck and at 1080p on Steam Machine, and the smallest text must be at least 9 pixels high at 1280×800; Valve recommends 12 pixels and a text size setting, which is part of `GAMEDEV-18`. ([Steamworks, Getting your game ready for Steam Deck: game features](https://partner.steamgames.com/doc/steamhardware/recommendations#3), [Compatibility checklist](https://partner.steamgames.com/doc/steamhardware/compat#2), [Steam Deck requirements](https://partner.steamgames.com/doc/steamhardware/compat#3), [Steam Input: overview](https://partner.steamgames.com/doc/features/steam_controller/getting_started_for_devs#1))
- `7` `STEAM-13` **Make all single-player content playable without an Internet connection, and test it offline, including the first launch on a new Steam account.** Valve strongly recommends this, especially for Steam Deck players, whose network access may be more sporadic. ([Steamworks, Getting your game ready for Steam Deck: game features](https://partner.steamgames.com/doc/steamhardware/recommendations#3))
- `6` `STEAM-14` **Build everything the player needs into the game instead of a separate launcher, choose middleware that runs under Proton, and test the Windows build under Proton, on Linux or a Steam Deck.** Valve recommends user-space anti-cheat with its Proton support turned on, such as Easy Anti-Cheat or BattlEye, standalone video codecs such as VP9 or AV1 instead of Media Foundation, and no anti-tamper. Kernel-level anti-cheat isn't supported, and middleware that doesn't run makes a game Unsupported on Steam Deck and Steam Machine. Launchers built on .NET or WPF are a known Proton problem and hard to use with a controller. ([Steamworks, Proton anti-cheat support](https://partner.steamgames.com/doc/steamhardware/proton#1), [Easy Anti-Cheat](https://partner.steamgames.com/doc/steamhardware/proton#2), [Known Proton issues](https://partner.steamgames.com/doc/steamhardware/proton#4), [Compatibility review FAQ](https://partner.steamgames.com/doc/steamhardware/compat#7), [Getting your game ready for Steam Deck: game features](https://partner.steamgames.com/doc/steamhardware/recommendations#3))

### Crashes and code signing

- `7` `STEAM-15` **Collect crash reports from players' release builds through your engine's crash reporter or a crash-reporting service, and archive the debug symbols of every build you upload, outside the depots.** Steam Error Reporting is near the end of its life and supports only 32-bit Windows games. Unreal's Crash Report Client isn't packaged by default and needs a crash report server, and projects on Unity 6.2 and later can use Unity Diagnostics. Exclude `*.pdb` files from depots with `FileExclusion`, and keep them, for example, in a symbol store built with SymStore. A crash-reporting service receives personal data, so vet it as `PRIV-11` asks. ([Steamworks, Steam Error Reporting](https://partner.steamgames.com/doc/features/error_reporting), [Unreal Engine, Crash Reporting](https://dev.epicgames.com/documentation/en-us/unreal-engine/crash-reporting-in-unreal-engine), [Unity, Diagnostics](https://docs.unity.com/en-us/cloud/developer-data/diagnostics), [Steamworks, Advanced build scripts](https://partner.steamgames.com/doc/sdk/uploading#5), [Microsoft, SymStore](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/symstore))
- `5` `STEAM-16` **Sign the Windows executables, libraries and installers you ship, in the release pipeline, with one consistent signing identity, such as Azure Artifact Signing or an OV certificate, and sign after every step that changes the files, such as the Steam DRM wrapper.** Unsigned files must build SmartScreen reputation again with every update, and on Windows 11, Smart App Control blocks unsigned executables without a positive reputation, however they were installed. ([Microsoft, Code signing options for Windows app developers](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options#azure-artifact-signing-formerly-trusted-signing--recommended-for-non-store-distribution), [SmartScreen reputation: minimizing warnings](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation#minimizing-smartscreen-warnings-in-practice), [Steamworks, Automated Steam DRM wrapper](https://partner.steamgames.com/doc/features/drm#2))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `6` [SignTool `verify`](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool#verify-command-options) (Windows SDK): `signtool verify /pa` checks that a file has a valid signature that chains to a trusted authority, and exits with code 1 if it doesn't, so a release job can fail on unsigned executables before uploading them. It doesn't check which identity signed the files. Partly checks `STEAM-16`.

- `5` [The 5 Golden Rules of Input](https://www.gamedeveloper.com/design/the-5-golden-rules-of-input) (Zach Burke, Game Developer, 2015): matching icons and cursor to the input device, letting every device work at any time, and pausing when a gamepad disconnects, which Valve recommends for games that don't use the Steam Input API.
