# Web games

Scope: games that run in a web browser, whether they're written for the web with a JavaScript framework such as Phaser 4, three.js, Babylon.js or PixiJS 8, or exported from an engine: Unity 6 Web builds (Unity 6.3 LTS to 6.6), Godot 4 web exports (4.7 is current), and GameMaker's HTML5 and GX.games targets. The rules cover engine exports and hosting, download size, the game loop in a browser tab, audio and input, saves in browser storage, publishing on itch.io and web game portals, and performance. WebGL and WebGPU rendering, including the WebGL 2 fallback (`GFX-15`) and lost contexts (`GFX-16`), are in [Graphics and GPU rendering](../graphics/README.md); the fixed time step (`GAMEDEV-1`), save versioning (`GAMEDEV-10` and `GAMEDEV-11`) and frame budgets (`GAMEDEV-12`) are in [Game development](../gamedev/README.md); and accessibility, security headers and HTTP caching for any web page are in [Web front end](../web/README.md). Engine rules are in [Unity](../unity/README.md), [Godot](../godot/README.md) and [GameMaker](../gamemaker/README.md), store rules for phones in [Mobile games](../mobile-games/README.md), multiplayer servers and backends in [Game servers and online services](../game-servers/README.md), and hosting on Vercel, Netlify and Cloudflare in [Serverless and edge hosting](../web-hosting/README.md).

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

## Adopted references

No single guide covers web games. Use the guide for your engine or framework, and the requirements of each site you publish on, as the baselines.

- `8` [Web](https://docs.unity3d.com/Manual/webgl.html) (Unity Manual): **the baseline for Unity Web builds**: browser support, WebGL 2 and WebGPU, [memory](https://docs.unity3d.com/Manual/webgl-memory.html), multithreading, compression and [server configuration](https://docs.unity3d.com/Manual/webgl-deploying.html), caching, and optimising for size and for mobile browsers.
- `8` [Exporting for the Web](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html) (Godot docs): **the baseline for Godot web exports**: WebGL 2 and the Compatibility renderer, thread support, progressive web apps, the platform's limits, and serving the files.
- `7` [Game development](https://developer.mozilla.org/en-US/docs/Games) (MDN): browser game techniques, from the anatomy of a main loop to the web APIs games use, control mechanisms and publishing.
- `7` [Phaser concepts: Scenes](https://docs.phaser.io/phaser/concepts/scenes), [Loader](https://docs.phaser.io/phaser/concepts/loader) and [Textures](https://docs.phaser.io/phaser/concepts/textures) (Phaser docs): the scene life cycle, where to load assets, and sprite sheets and texture atlases.
- `7` [three.js manual](https://threejs.org/manual/) (three.js): fundamentals, responsive canvases, disposing of objects, and optimising scenes with many objects.
- `7` [Optimizing Your Scene](https://doc.babylonjs.com/features/featuresDeepDive/scene/optimize_your_scene) (Babylon.js docs): instances, frozen materials and meshes, culling and the scene optimiser.
- `7` [Uploading HTML5 games](https://itch.io/docs/creators/html5) and the [butler manual](https://itch.io/docs/butler/pushing.html) (itch.io): ZIP requirements, embed options and precompressed files, and pushing builds with `butler push`, [from CI](https://itch.io/docs/butler/login.html#running-butler-from-ci-builds-github-actions-gitlab-ci-etc) with a `BUTLER_API_KEY` secret.
- `7` [Requirements](https://developers.poki.com/guide/requirements-quality) (Poki) and [Technical requirements](https://docs.crazygames.com/requirements/technical/) (CrazyGames): what each portal checks before it publishes a game: file size, devices and browsers, input, SDK integration and ads.
- `7` [Storage for the web](https://web.dev/articles/storage-for-the-web) (web.dev): which browser storage API to use, how much you can store, and how eviction works.
- `6` [Setting Up For GX Games](https://gamemaker.io/en/help/articles/setting-up-for-gx-games) and [HTML5: Common Issues and Differences To VM/YYC](https://gamemaker.io/en/help/articles/html5-common-issues-and-differences-to-vm-yyc) (GameMaker Help Centre): GameMaker's two web targets and how they differ from the desktop targets.
- `6` [Performance Tips](https://pixijs.com/8.x/guides/concepts/performance-tips) (PixiJS): sprite sheets and batching, culling, textures, text, filters and blend modes.

## Key rules

### Engine exports and hosting

- `8` `WEBGAME-1` **Before you choose a scripting language, renderer or plugins, check what the engine's web export supports.** Godot 4 can't export C# projects to the web and runs there only with the Compatibility renderer on WebGL 2 (`GODOT-16` and `GODOT-21`). Unity uses WebGL 2 by default, and WebGPU has limited browser and device support, so if you add WebGPU, keep WebGL 2 after it in the Graphics API list as the fallback (`GFX-15`). In GameMaker, the GX.games target behaves more like the desktop targets than the HTML5 target does, and if you use HTML5, keep WebGL on. ([Godot, Exporting for the Web](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#exporting-for-the-web), [Godot, WebGL version](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#webgl-version), [Unity, Compare WebGPU and WebGL2](https://docs.unity3d.com/Manual/web-graphics-apis-intro.html), [Unity, Enable the WebGPU graphics API](https://docs.unity3d.com/Manual/webgpu-enable.html), [GameMaker, Setting Up For GX Games](https://gamemaker.io/en/help/articles/setting-up-for-gx-games), [GameMaker, HTML5: Common Issues and Differences To VM/YYC](https://gamemaker.io/en/help/articles/html5-common-issues-and-differences-to-vm-yyc))
- `7` `WEBGAME-2` **Serve the engine's precompressed build files over HTTPS with the matching `Content-Encoding` header, `gzip` for `.gz` and `br` for `.br` files, and serve `.wasm` files as `application/wasm`.** Unity's decompression fallback works without the header, but makes the loader larger and loading less efficient, and Chrome and Firefox decompress Brotli natively only over HTTPS. Godot recommends compressing the large `.pck` and `.wasm` files on the server, and itch.io sets the header from the `.gz` or `.br` extension. With another MIME type, `WebAssembly.instantiateStreaming()` fails and the browser can't compile the module while it downloads. ([Unity, Deploy a Web application](https://docs.unity3d.com/Manual/webgl-deploying.html), [Godot, Serving the files](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#serving-the-files), [itch.io, Compression](https://itch.io/docs/creators/html5#compression), [MDN, WebAssembly.instantiateStreaming()](https://developer.mozilla.org/en-US/docs/WebAssembly/Reference/JavaScript_interface/instantiateStreaming_static))
- `7` `WEBGAME-3` **Export without threads unless you control the headers of every page that hosts the game.** Threads in WebAssembly builds need `SharedArrayBuffer`, which needs a secure context and cross-origin isolation: `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` on the page, `allow="cross-origin-isolated"` on every iframe in the chain, and an opt-in from every cross-origin resource, which rules out most ads and third-party scripts. Godot exports single-threaded by default since 4.3, and its docs call that more compatible with itch.io, Poki and CrazyGames; Unity's *Enable Native C/C++ Multithreading* needs the same headers. ([Godot, Exporting for the Web](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#exporting-for-the-web), [Godot, Thread and extension support](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#thread-and-extension-support), [Unity, Introduction to Web multithreading](https://docs.unity3d.com/Manual/web-multithreading-intro.html), [MDN, SharedArrayBuffer: security requirements](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/SharedArrayBuffer#security_requirements), [web.dev, Isolation in iframes](https://web.dev/articles/coop-coep#isolation_in_iframes))
- `6` `WEBGAME-4` **Ship GPU texture formats for both desktop and mobile browsers: in Unity, make two builds, one with DXT for desktop and one with ASTC for mobile browsers, and in Godot, turn on VRAM texture compression for both desktop and mobile in the web export preset.** In Unity, a device that doesn't support the build's format decompresses the textures in software, which uses more memory and can run slower; in Godot, enabling both makes the export bigger but more compatible. This applies `GFX-13`. ([Unity, Texture compression in Web](https://docs.unity3d.com/Manual/webgl-texture-compression.html), [Godot, Export options](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#export-options))

### Loading

- `8` `WEBGAME-5` **Set a download budget for the first load and for the whole game, from the portals and devices you target, and check every build against it.** Poki says the initial download of a good web game shouldn't exceed 5 MB, or 8 MB in total, and that players move to another game when loading takes more than 10 seconds. CrazyGames allows at most 50 MB before gameplay starts, 20 MB for its mobile homepage, and 250 MB and 1,500 files in total; itch.io accepts at most 500 MB, 1,000 files and 200 MB per file. ([Poki, Choosing your web game engine](https://developers.poki.com/guide/web-engine), [Poki, Requirements](https://developers.poki.com/guide/requirements-quality), [CrazyGames, File size and count limits](https://docs.crazygames.com/requirements/technical/#file-size-count-limits), [itch.io, ZIP file requirements](https://itch.io/docs/creators/html5#zip-file-requirements))
- `7` `WEBGAME-6` **Download only what the first scene needs before play starts, load the rest per scene in the background, and let the engine cache downloaded files on the player's device.** Unity 6.6 adds progressive asset loading; in earlier versions, use Addressables or AssetBundles, and Data Caching keeps the `.data` file and AssetBundles in IndexedDB. In Phaser, load shared assets in a boot scene and the others in the scene that uses them. If you write your own service worker, cache each build under a new cache name and delete the old caches when it activates. For mobile store builds, the same rule is `MOBGAME-10`. ([Unity, Reduce Web startup time with progressive asset loading](https://docs.unity3d.com/Manual/web-optimization-progressive-asset-loading.html), [Unity, Optimize Web platform for mobile](https://docs.unity3d.com/Manual/web-optimization-mobile.html), [Unity, Cache behavior in Web](https://docs.unity3d.com/Manual/webgl-caching.html), [Phaser, Loader: where to load assets](https://docs.phaser.io/phaser/concepts/loader#where-to-load-assets), [MDN, Using Service Workers: deleting old caches](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers#deleting_old_caches))

### Game loop and page lifecycle

- `7` `WEBGAME-7` **When the page becomes hidden, pause the game, suspend the `AudioContext` and save progress.** Listen for `visibilitychange`: the hidden state is often the last change a page can observe, especially on mobile, where closing the tab or the browser fires no `pagehide` or `unload`. Browsers stop `requestAnimationFrame` in hidden tabs, which stops engine loops such as Godot's `_process()` and can disconnect networked games, but they don't throttle tabs that play audio. Phaser pauses its game when the page is hidden and emits `hidden` and `visible` events. ([MDN, Page Visibility API: policies for background pages](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API#policies_in_place_to_aid_background_page_performance), [Chrome for Developers, Page Lifecycle API: hidden](https://developer.chrome.com/docs/web-platform/page-lifecycle-api#state-hidden), [MDN, AudioContext.suspend()](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/suspend), [Godot, Background processing](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#background-processing), [Phaser, Game: events](https://docs.phaser.io/phaser/concepts/game#events))
- `6` `WEBGAME-8` **If you write your own game loop, drive it with `requestAnimationFrame`, request the next frame before doing the frame's work, and advance the fixed time step of `GAMEDEV-1` from the callback's timestamp.** Don't update on `setInterval` or `setTimeout`, which keep using the CPU when the game is minimized and compete with rendering for the main thread. `requestAnimationFrame` follows the display's refresh rate, commonly 60 Hz but also 120 or 144 Hz, and pauses in background tabs, so keep `GAMEDEV-1`'s cap on steps per frame. ([MDN, Anatomy of a video game](https://developer.mozilla.org/en-US/docs/Games/Anatomy#building_a_main_loop_in_javascript), [MDN, requestAnimationFrame()](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame))

### Audio and input

- `8` `WEBGAME-9` **Start audio from the player's first click, tap or key press, for example on a "tap to play" screen, and resume the `AudioContext` from a later tap whenever it is suspended or interrupted.** Browsers block audio until the player has interacted with the page, and an `AudioContext` created before that starts suspended. On iOS, the context is interrupted when the game goes to the background or a call comes in, and only a new user gesture can resume it, not a `visibilitychange` handler. Unity and Godot both suggest a loading or splash screen that asks for this first interaction. ([MDN, Web Audio API best practices: autoplay policy](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices#autoplay_policy), [MDN, Autoplay guide: availability](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay#autoplay_availability), [MDN, BaseAudioContext.state](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/state), [CrazyGames, Resuming audio after iOS interrupts it](https://docs.crazygames.com/requirements/technical/#resuming-audio-after-ios-interrupts-it), [Unity, Audio in Web](https://docs.unity3d.com/Manual/webgl-audio.html), [Godot, Audio](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#audio))
- `7` `WEBGAME-10` **Handle mouse, touch and pen with Pointer Events on the game canvas, set `touch-action: none` on the canvas only, and if the game runs in mobile browsers, give it touch controls and a layout for each orientation it supports.** `touch-action: none` stops the browser from panning and zooming the game surface, and on the whole page it would also stop players with low vision from zooming. CrazyGames requires mouse, keyboard and touch for games that support mobile, and Poki requires mobile games to fill the screen in portrait, landscape or both. Don't rely on locking the orientation: `screen.orientation.lock()` isn't available in every major browser, and usually works only on mobile in fullscreen. ([MDN, Pointer events: touch-action](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events#touch-action_css_property), [MDN, touch-action: accessibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action#accessibility), [CrazyGames, Device and browser compatibility](https://docs.crazygames.com/requirements/technical/#device-browser-compatibility), [Poki, Requirements](https://developers.poki.com/guide/requirements-quality), [MDN, ScreenOrientation.lock()](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock))
- `6` `WEBGAME-11` **Read gamepads by polling `navigator.getGamepads()` once per frame, ask the player to press a button before expecting a controller to appear, and let players remap buttons when a gamepad's `mapping` isn't `"standard"`.** Browsers expose a connected gamepad only after the player presses a button or moves a stick, the API needs HTTPS, and Godot warns that mappings can be wrong for some combinations of browser, operating system and controller. This applies `GAMEDEV-18`. ([MDN, Using the Gamepad API](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API#connecting_to_a_gamepad), [Godot, Gamepads](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#gamepads))
- `6` `WEBGAME-12` **Request fullscreen and pointer lock only from a click or key-press handler, handle a refusal, and check that the page embedding the game allows them.** Both need a recent user interaction: Unity defers the request to the next input event, so trigger it on mouse-down or key-down rather than on release, and Godot needs it inside an input event callback. A cross-origin iframe needs `allow="fullscreen"`, and a sandboxed iframe needs `allow-pointer-lock`. For aiming, request pointer lock with `unadjustedMovement: true` to get raw mouse input where the browser supports it. ([MDN, requestFullscreen(): security considerations](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen#security_considerations), [MDN, Pointer Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API#iframe_limitations), [Unity, Input in Web](https://docs.unity3d.com/Manual/webgl-input.html), [Godot, Full screen and mouse capture](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#full-screen-and-mouse-capture))

### Saving

- `8` `WEBGAME-13` **Store saves in IndexedDB rather than `localStorage`, request persistent storage when the player first saves, and keep a copy of progress that matters on a server, such as a portal's cloud save or your own backend.** `localStorage` blocks the main thread, holds only about 5 MB of strings, and may be restricted in private browsing, so wrap storage calls in `try`/`catch` and keep the game playable without them. Browser storage is best-effort by default: browsers may evict it, Safari deletes script-written data of sites the player hasn't interacted with in seven days of use, and a game in another site's iframe gets storage separate from the same game on your own site. In Godot, `OS.is_userfs_persistent()` tells you whether `user://` will last. This applies `GAMEDEV-10` and `GAMEDEV-11`. ([web.dev, Storage for the web](https://web.dev/articles/storage-for-the-web#recommendation), [web.dev, Persistent storage: when to ask](https://web.dev/articles/persistent-storage#when_should_i_ask_for_persistent_storage), [MDN, Storage quotas and eviction criteria](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria#does_browser-stored_data_persist), [Privacy Sandbox, Storage partitioning](https://privacysandbox.google.com/cookies/storage-partitioning), [Poki, Requirements](https://developers.poki.com/guide/requirements-quality), [Godot, Using cookies for data persistence](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html#using-cookies-for-data-persistence), [CrazyGames, Data module](https://docs.crazygames.com/sdk/data/))

### Publishing

- `6` `WEBGAME-14` **If you publish on web game portals, integrate each portal's SDK and meet its technical requirements from the start: report loading and gameplay events, show ads only through the portal's SDK, and bundle every asset into the build.** Poki blocks external requests, allows no other ad system, requires the game to mute its audio during ads and to stay playable with an ad blocker, and checks that `gameplayStart()` and `gameplayStop()` fire at the right moments. CrazyGames measures the initial download up to its gameplay-start event, and its data module syncs saves to the player's account. ([Poki, Requirements](https://developers.poki.com/guide/requirements-quality), [CrazyGames, SDK integration](https://docs.crazygames.com/requirements/technical/#sdk-integration), [CrazyGames, Data module](https://docs.crazygames.com/sdk/data/))

### Performance

- `7` `WEBGAME-15` **Free GPU resources explicitly when a level or scene ends: in three.js, call `dispose()` on geometries, materials, textures and render targets, and in Phaser, remove assets that only the finished scene used.** three.js doesn't release WebGL buffers, textures and shader programs automatically, and MDN advises deleting WebGL objects eagerly rather than waiting for the garbage collector. In three.js, watch `renderer.info.memory` for leaks. ([three.js manual, How to dispose of objects](https://threejs.org/manual/#how-to-dispose-of-objects), [MDN, WebGL best practices: delete objects eagerly](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#delete_objects_eagerly), [Phaser, Loader: where to load assets](https://docs.phaser.io/phaser/concepts/loader#where-to-load-assets))
- `6` `WEBGAME-16` **Profile web builds in the browser on the slowest device you support, and move heavy work that doesn't draw, such as pathfinding or procedural generation, to Web Workers.** Use the DevTools Performance panel for main-thread time, with CPU throttling when you profile on a desktop; Spector.js to capture WebGL frames, which RenderDoc can't (`GFX-4`); and the engine's profiler on a development build, because Unity's Frame Debugger doesn't work on the web. Transfer `ArrayBuffer`s to workers instead of copying them, and render from a worker with `OffscreenCanvas` where the engine supports it. This applies `GAMEDEV-12`. ([Chrome DevTools, Analyze runtime performance](https://developer.chrome.com/docs/devtools/performance#simulate_a_mobile_cpu), [Spector.js](https://github.com/BabylonJS/Spector.js/blob/master/readme.md), [Unity, Profile a Web build](https://docs.unity3d.com/Manual/web-profile.html), [MDN, Transferable objects](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Transferable_objects), [web.dev, OffscreenCanvas](https://web.dev/articles/offscreen-canvas))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `6` [Lighthouse CI](https://github.com/GoogleChrome/lighthouse-ci/blob/main/docs/configuration.md): `resource-summary:total:size` and `resource-summary:total:count` assertions fail CI when the transfer size or number of requests of a page load exceed your budget. Point it at the game's page to check what the loader downloads before play starts. Partly checks `WEBGAME-5`.
- `4` [ESLint `no-restricted-globals`](https://eslint.org/docs/latest/rules/no-restricted-globals): list `localStorage` with [`checkGlobalObject: true`](https://eslint.org/docs/latest/rules/no-restricted-globals#checkglobalobject) to flag every use, including `window.localStorage`, in your own code. Partly checks `WEBGAME-13`.
