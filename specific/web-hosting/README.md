# Serverless and edge hosting (Vercel, Netlify, Cloudflare)

Scope: deploying web apps and APIs to Vercel, Netlify and Cloudflare Workers (including Cloudflare Pages). The rules are platform-neutral where the three platforms agree, and cite each platform's documentation. Framework rules are in [Next.js](../nextjs/README.md) and [Web front end](../web/README.md), which also covers caching static assets and HTML (`WEB-7`). Config in the environment and stateless processes (`OPS-9`) are in [general/operations-reliability.md](../../general/operations-reliability.md), keeping secrets out of code (`SEC-2`) is in [general/security.md](../../general/security.md), and database rules are in [PostgreSQL](../postgres/README.md).

> Entries are sorted by score from 1 to 10 ([criteria](../../RANKING.md)): 9–10 start here or strongly recommended, 6–8 recommended, 1–5 further reading or conditional.

- `8` [Workers Best Practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/) (Cloudflare Docs): configuration, secrets, background work, database connections, observability and code patterns for Workers.
- `7` [Caching overview](https://docs.netlify.com/build/caching/caching-overview/) (Netlify Docs): cache control headers, cache key variations, the durable cache, `stale-while-revalidate` and purging by site or cache tag on Netlify.

## Key rules

### Runtimes, regions and limits

- `7` `HOST-1` **Run code that queries a regional database or API in the same region as that backend, and keep edge execution for work that doesn't need it, such as redirects, rewrites, headers and geolocation.** Set the function region on Vercel and Netlify; on Cloudflare, which runs Workers close to the user by default, use Placement. ([Vercel, Configuring regions for Vercel Functions](https://vercel.com/docs/functions/configuring-functions/region), [Netlify, When to set a region](https://docs.netlify.com/build/functions/configuration/#when-to-set-a-region), [Netlify, Edge Functions use cases](https://docs.netlify.com/build/edge-functions/overview/#use-cases), [Cloudflare, Placement](https://developers.cloudflare.com/workers/configuration/placement/))
- `6` `HOST-2` **Start new projects on each platform's recommended compute: the Node.js runtime on Vercel, and Workers with static assets on Cloudflare.** Vercel recommends migrating from its Edge runtime to Node.js, and Cloudflare recommends Workers instead of Pages for new projects. ([Vercel, Edge Runtime](https://vercel.com/docs/functions/runtimes/edge), [Cloudflare, Use Workers Static Assets for new projects](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/#use-workers-static-assets-for-new-projects))
- `6` `HOST-3` **Keep each request well within the platform's duration, CPU, memory and payload limits, and move long or retryable work to background functions, queues or workflows.** For example, Netlify stops synchronous functions after 60 seconds, Vercel limits request and response bodies to 4.5 MB, and Workers on the Free plan get 10 ms of CPU time per request. ([Vercel, Functions limits](https://vercel.com/docs/functions/limitations), [Netlify, Functions default values](https://docs.netlify.com/build/functions/configuration/#default-values), [Netlify, Background Functions](https://docs.netlify.com/build/functions/background-functions/), [Cloudflare, Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [Cloudflare, Use Queues and Workflows for background work](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/#use-queues-and-workflows-for-async-and-background-work))

### State and data

- `8` `HOST-4` **Keep request and user data out of module-level variables and the local file system, and keep durable state in managed storage, such as a database, key-value store or blob store.** One instance serves many requests, sometimes at the same time, and can be stopped at any moment, so global state leaks between requests or disappears. ([Cloudflare, Do not store request-scoped state in global scope](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/#do-not-store-request-scoped-state-in-global-scope), [Vercel, Fluid compute: isolation boundaries and global state](https://vercel.com/docs/fluid-compute#isolation-boundaries-and-global-state), [Netlify, How functions work](https://docs.netlify.com/build/functions/overview/#how-functions-work), [Cloudflare, Choose a data or storage product](https://developers.cloudflare.com/workers/platform/storage-options/))
- `7` `HOST-5` **Connect to relational databases through connection pooling built for the platform: Hyperdrive on Cloudflare Workers, and on Vercel a pool created once per instance and registered with `attachDatabasePool`.** Opening a new connection on every invocation adds round trips and can exhaust the database's connection limit. For pooling in front of PostgreSQL itself, see `PG-9`. ([Cloudflare, Use Hyperdrive for external database connections](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/#use-hyperdrive-for-external-database-connections), [How Hyperdrive works](https://developers.cloudflare.com/hyperdrive/concepts/how-hyperdrive-works/), [Vercel, attachDatabasePool](https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package#attachdatabasepool))

### Caching

- `7` `HOST-6` **Set CDN caching deliberately on function responses: a shared-cache lifetime with `s-maxage` or `CDN-Cache-Control`, `stale-while-revalidate` where slightly stale content is acceptable, and `private` or `no-store` on per-user responses.** On Cloudflare, enable Workers Cache to cache a Worker's own responses, and note that `s-maxage` there turns off `stale-while-revalidate`. ([Vercel, Cache-Control headers](https://vercel.com/docs/caching/cache-control-headers), [Netlify, Supported cache control headers](https://docs.netlify.com/build/caching/caching-overview/#supported-cache-control-headers), [Cloudflare, Origin Cache Control](https://developers.cloudflare.com/cache/concepts/cache-control/), [Cloudflare, Workers Cache](https://developers.cloudflare.com/workers/cache/))
- `6` `HOST-7` **Tag cached responses with cache tags, and purge or invalidate them by tag when the underlying content changes.** Vercel and Cloudflare can also mark tagged entries stale instead of deleting them, which avoids a burst of requests to the origin. ([Vercel, Cache tags](https://vercel.com/docs/caching/cdn-cache/purge#cache-tags), [Netlify, Purge by cache tag](https://docs.netlify.com/build/caching/caching-overview/#purge-by-cache-tag), [Cloudflare, Workers Cache: purging the cache](https://developers.cloudflare.com/workers/cache/#purging-the-cache))

### Configuration and secrets

- `8` `HOST-8` **Store credentials only as the platform's secret variables: Vercel Secret environment variables, Netlify variables marked as containing secret values, and Cloudflare secrets. Never put them in plain variables or in `vercel.json`, `netlify.toml` or Wrangler files.** Secret values can't be read back once saved. ([Vercel, Config and Secret environment variables](https://vercel.com/docs/environment-variables/sensitive-environment-variables), [Netlify, Environment variable secrets policy](https://docs.netlify.com/build/environment-variables/secrets-controller/#environment-variable-secrets-policy), [Cloudflare, Store secrets with wrangler secret, not in source](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/#store-secrets-with-wrangler-secret-not-in-source), [Cloudflare, Secrets](https://developers.cloudflare.com/workers/configuration/secrets/))
- `8` `HOST-9` **Give production its own secrets and data stores, and don't let preview or development deployments use them.** Netlify gives a variable the same value in every deploy context unless you set values per context, and a Cloudflare Preview is isolated from production data only when you bind it to separate KV, D1, R2 or Hyperdrive resources. ([Vercel, Environment variables: environments](https://vercel.com/docs/environment-variables#environments), [Vercel, Environment variables policy](https://vercel.com/docs/environment-variables/sensitive-environment-variables#environment-variables-policy), [Netlify, Value per deploy context](https://docs.netlify.com/build/environment-variables/overview/#value-per-deploy-context), [Cloudflare, Previews: resources and isolation](https://developers.cloudflare.com/workers/previews/resources/#binding-reference))
- `6` `HOST-10` **Keep platform configuration in files in the repository, such as `vercel.json`, `netlify.toml` or the Wrangler configuration, and treat them as the source of truth instead of changing settings in the dashboard.** File settings are versioned with the code, and on Netlify and Cloudflare they override dashboard changes. ([Vercel, Project configuration](https://vercel.com/docs/project-configuration), [Netlify, File-based configuration](https://docs.netlify.com/build/configure-builds/file-based-configuration/), [Cloudflare, Wrangler configuration: source of truth](https://developers.cloudflare.com/workers/wrangler/configuration/#source-of-truth))

### Deployments

- `7` `HOST-11` **Keep preview deployments private: check that Vercel Deployment Protection or Netlify's private previews cover them, and put Cloudflare Access in front of Workers previews and Pages preview deployments, which are public by default.** ([Vercel, Deployment Protection](https://vercel.com/docs/deployment-protection#standard-protection), [Netlify, Private previews](https://docs.netlify.com/manage/security/secure-access-to-sites/project-visibility/#private-previews), [Cloudflare, Previews: access control](https://developers.cloudflare.com/workers/previews/#access-control), [Cloudflare Pages, Preview deployments](https://developers.cloudflare.com/pages/configuration/preview-deployments/))
- `7` `HOST-12` **Recover from a bad release by rolling back to the previous production deployment, and keep data and schema changes backward compatible so that the previous version still works.** A rollback switches the code, not the data: databases and bound resources keep their current state. ([Vercel, Instant Rollback](https://vercel.com/docs/instant-rollback), [Netlify, Rollbacks](https://docs.netlify.com/deploy/manage-deploys/manage-deploys-overview/#rollbacks), [Cloudflare, Rollbacks](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/))

### Observability

- `7` `HOST-13` **Send logs and traces to an external observability service with a log drain or OpenTelemetry export, because the platforms keep runtime logs only for hours or days.** For example, Vercel keeps one day of runtime logs on Pro, Netlify keeps function logs for at least 24 hours, and Workers Logs keeps them for 3 or 7 days, depending on the plan. Log drains need a Vercel Pro or Netlify Enterprise plan. ([Vercel, Runtime Logs: limits](https://vercel.com/docs/logs/runtime#limits), [Vercel, Drains](https://vercel.com/docs/drains), [Netlify, Function log retention](https://docs.netlify.com/build/functions/logs/#log-retention-and-limits), [Netlify, Log Drains](https://docs.netlify.com/manage/monitoring/log-drains/), [Cloudflare, Workers Logs: limits](https://developers.cloudflare.com/workers/observability/logs/workers-logs/#limits), [Cloudflare, OpenTelemetry export](https://developers.cloudflare.com/workers/observability/opentelemetry-export/))

## How to enforce

Tools that check the key rules above automatically, in CI, the IDE or a commit hook. "Partly" means the tool covers only some of what the rule asks.

- `7` [Vercel Separate Production Secret Values](https://vercel.com/docs/environment-variables/sensitive-environment-variables#environment-variables-policy): an optional team policy. When an owner turns on Require Separate Values, every Secret must have a different value in Production than in Preview, Development and custom environments. Partly checks `HOST-9`.
- `6` [Netlify secret scanning](https://docs.netlify.com/build/environment-variables/secrets-controller/#secret-scanning-overview): built into Netlify builds. It fails the build, before the deploy is published, when the value of a variable marked as secret appears in the repository code or the build output. Partly checks `HOST-8`.
